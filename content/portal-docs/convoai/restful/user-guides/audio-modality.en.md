# Use Audio Modality Output

Agora Conversational AI Engine supports audio modality output. This article explains how to configure an agent for audio-modality output and adapt your interfaces accordingly to enable context management, subtitle alignment, and agent audio playback.

## Prerequisites

Before you start, make sure that you have:

- Followed [Build Voice Interaction with an Agent](../get-started/quick-start.md) to implement the basic logic for interactive conversations with an AI agent.
- Read [Real-Time Subtitles](./realtime-sub.md) and completed the related configuration if you want to implement subtitles for output audio.

## Implementation

### Select the Output Modality

To use audio-modality output, set `llm.output_modalities` to one of the following values when calling [POST Create a Conversational AI Agent](../operations/start-agent.md):

- `["audio"]`: Output in pure audio modality. In this case, you do not need to configure a text-to-speech (TTS) module, and the audio returned by the custom large model is played directly by the agent. This article mainly explains how to use audio modality in this configuration.
- `["text", "audio"]`: Output in both text and audio modalities. In this case, two types of audio coexist: one generated by the TTS module and the other sent to the agent by the custom large model.

### Adapt the Interface to the Standard

Agora Conversational AI Engine interacts with large language models through an [OpenAI Chat Completions API](https://platform.openai.com/docs/api-reference/chat)-compatible interface, but aggregates different types of responses such as text, audio, subtitles, and word-level subtitle timestamps, and extends a `words` field for real-time subtitle alignment. You can refer to [Custom LLM](./custom-llm.md#implementation) to adapt your large-model service so that it is compatible with the following request and response formats.

#### Request Format

Compared with a text request, an audio request contains an additional `modalities` field that specifies the output modality and an `audio` field that specifies the output voice and format.

These two parameters are optional. If needed, you can pass them in the `llm.params` field when calling [POST Create a Conversational AI Agent](../operations/start-agent.md).

The following request format is used to generate audio:

```json
{
  "model": "gpt-4o-audio-preview",
  "modalities": ["audio"],
  "audio": { "voice": "alloy", "format": "wav" },
  "messages": [
    {
      "role": "user",
      "content": "Is a golden retriever a good family dog?"
    }
  ]
}
```

#### Response Format

Audio response content (`audio`) includes three types, all of which can be sent independently to the agent for processing:

| `audio` Type | Description | Source | Agent Processing |
| --- | --- | --- | --- |
| Audio data (`data`) | Base64-encoded PCM byte stream array | - Generated by an LLM with audio processing capability<br>- Generated by a custom audio-processing service | Play the audio directly |
| Transcript (`transcript`) | Full text corresponding to the audio | Generated by the LLM | Store in short-term memory (context) |
| Word-level subtitles (`words`) | Subtitle content with word-level timestamps | Generated by an LLM that supports word-level output | Process into real-time word-level subtitles |

The specific data structure is as follows for streaming responses:

```json
{"choices":[{"index":0,"delta":{"role":"assistant","audio":{"data": ""}},"logprobs":null,"finish_reason":null}]}

/// Audio data
{"choices":[{"index":0,"delta":{"audio":{"data": "base64 encoded pcm data"}},"logprobs":null,"finish_reason":null}]}

/// Transcript
{"choices":[{"index":0,"delta":{"audio":{"transcript": "Hello world!", "words":[{"text":"Hello", "start_ts":100, "end_ts":140, "duration":40}]}},"logprobs":null,"finish_reason":null}]}

/// Word-level subtitles
{"choices":[{"index":0,"delta":{"audio":{"words":[{"text":"world", "start_ts":150, "end_ts":190, "duration":40}, {"text":"!", "start_ts":190, "end_ts":200, "duration":10}]}},"logprobs":null,"finish_reason":null}]}

....

{"choices":[{"index":0,"delta":{},"logprobs":null,"finish_reason":"stop"}]}
```

Agora Conversational AI Engine aggregates different response types in the following format:

```json
{
    "choices": [
        {
            "delta": {
                "audio": {
                    "data": "base64 encoded pcm data",
                    "transcript": "Hello world!",
                    "words": [
                        {
                            "text": "Hello",
                            "start_ts": 100,
                            "end_ts": 140,
                            "duration": 40
                        },
                        {
                            "text": "world",
                            "start_ts": 150,
                            "end_ts": 190,
                            "duration": 40
                        },
                        {
                            "text": "!",
                            "start_ts": 190,
                            "end_ts": 200,
                            "duration": 10
                        }
                    ]
                }
            }
        }
    ]
}
```

The fields in `audio` have the following meanings:

- `data`: Audio data, a Base64-encoded PCM byte stream.
- `transcript`: Subtitle content corresponding to the audio.
- `words`: Word-level subtitle timestamps corresponding to the subtitles. Requires a model that supports word-level output.
  - `text`: The specific word or token.
  - `start_ts`: Milliseconds relative to the start time of the PCM audio data in the current request.
  - `end_ts`: Milliseconds relative to the end time of the PCM audio data in the current request.
  - `duration`: Actual playback duration of the corresponding word or token.

Depending on your scenario, your custom large model can selectively process and send these fields. For example:

- Audio-only output: only the `data` field is required.
- Subtitle-only output: only the `transcript` field is required. In this case, only subtitle content is sent, and it is not spoken through the TTS module.
- Audio + word-level subtitle output: both the `data` and `words` fields are required. In the `words` field, `text` and `start_ts` are required, while `end_ts` and `duration` are optional alternatives and you can send either one.

## Advanced Features

### Context Management

If the response contains the `audio.transcript` field, the subtitle content in that field is automatically stored in the agent's context manager and used for later context management. If the `audio.transcript` field is not received, nothing is stored in the context manager.

If you want the agent's short-term memory to contain audio-modality output content, make sure the response includes the `audio.transcript` field.

### Subtitle Alignment

After completing subtitle rendering by following the [Real-Time Subtitles](./realtime-sub.md) documentation, if the model response contains the `audio.words` field, Agora Conversational AI Engine segments the audio according to the `start_ts` and `end_ts` or `duration` fields in `audio.words`, and aligns subtitles based on the segmentation result.

Therefore, if you want the agent to segment sentences during audio playback based on subtitle content, make sure the model sends both the `audio.data` and `audio.words` fields.

### Make the Agent Speak Messages

If the agent you created does not configure a TTS module but does configure audio-modality output (`output_modalities` is `["audio"]`), you can adapt your custom large model according to the following rules so that the agent can speak custom messages:

In the `messages` list received by the agent and then sent to the custom large model, the large model is expected to handle the last message according to its `role`:

- If `role` is `assistant`: The model should treat the message as not requiring reasoning. You can convert it to audio and send it to the agent directly, and the agent plays the audio immediately.
- If `role` is `user`: The model should treat the message as requiring reasoning. The agent decides whether to speak the message based on whether the response after reasoning contains audio. This corresponds to the normal question-and-answer scenario between the user and the agent.

> Info
> The following agent playback behaviors also follow this protocol:
> - When the agent speaks a greeting message (`greeting_message`), failure message (`failure_message`), or silence message (`silence_message`)
> - When calling [POST Speak a Custom Message](../operations/agent-speak.md)
