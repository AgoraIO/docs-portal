# Agent Short-Term Memory

Short-term memory is the temporary information space in which an agent stores and processes information during the current session. During interaction between the user and a conversational AI agent, the agent caches the context of the current conversation in short-term memory to ensure that it can continuously understand and respond to the user's ongoing input.

An agent created by Agora Conversational AI Engine maintains the short-term memory generated during the conversation. It not only supports selecting information from short-term memory and passing it to the large model, but can also persist it into long-term memory through the message notification service.

This article covers the following:

- What is stored in short-term memory
- How to obtain short-term memory
- How to use short-term memory

> Info
> This article applies to Agora Conversational AI Engine v1.4 and later.

## Data Structure of Short-Term Memory

The overall short-term memory of Conversational AI Engine is stored in JSON format. It follows the rules of [OpenAI Chat Completions](https://platform.openai.com/docs/api-reference/chat) with some extensions. The data structure is as follows:

```json
{
    "contents": [
        {
            "role": "assistant",
            "content": "How can I help you today?",
            "turn_id": 1,
            "timestamp": 1678901234,
            "metadata": {
                "source": "greeting"
            }
        },
        {
            "role": "user",
            "content": "Can you tell me a joke?",
            "turn_id": 2,
            "timestamp": 1678901235,
            "metadata": {
                "source": "asr",
                "user": "user123"
            }
        },
        {
            "role": "assistant",
            "content": "Why did the scarecrow ",
            "turn_id": 2,
            "timestamp": 1678901236,
            "metadata": {
                "interrupted": true,
                "interrupt_timestamp": 1678905225,
                "original": "Why did the scarecrow win an award? Because he was outstanding in his field!",
                "source": "llm"
            }
        },
        {
            "role": "user",
            "content": "You know what? Tell me a story instead.",
            "turn_id": 3,
            "timestamp": 1678905235,
            "metadata": {
                "source": "asr",
                "user": "user123"
            }
        },
        {
            "role": "assistant",
            "content": "Once upon a time in a land far away, there lived a brave knight who fought dragons and saved princesses.",
            "turn_id": 3,
            "timestamp": 1678905236,
            "metadata": {
                "source": "llm"
            }
        },
        {
            "role": "assistant",
            "content": "Are you still there?",
            "turn_id": 4,
            "timestamp": 1678905236,
            "metadata": {
                "source": "command"
            }
        }
    ]
}
```

**OpenAI standard fields**

- `role`: The role that sends the message. In short-term memory, only the user (`user`) and the agent (`assistant`) are supported. System messages (`system`) are not included.
- `content`: The actual text content. Currently, short-term memory does not consider multimodal input.

**Agora Conversational AI Engine extension fields**

- `turn_id`: The identifier of a conversation turn. `turn_id` starts from `0` and increases sequentially. One round of conversation between the user and the agent corresponds to one `turn_id`.
- `timestamp`: The timestamp of the corresponding message, in milliseconds.
- `metadata`: Metadata of the message. The fields are as follows:
  - `source`: The input source of the message:
    - Possible sources for a `user` message include:
      - Speech recognition result (`asr`)
      - Text message (`message`)
      - Message generated by a RESTful API call (`command`)
    - Possible sources for an `assistant` message include:
      - Large model (`llm`)
      - Greeting (`greeting`)
      - Large-model invocation failure (`llm failure`)
      - Message generated by a RESTful API call (`command`)
      - Silence prompt (`silence`)
  - `interrupted`: Whether this agent message (`role` is `assistant`) was interrupted by human speech:
    - `true`: The message was interrupted.
    - `false`: The message was not interrupted. `false` is the default case, and the field is hidden in that case.
  - `interrupt_timestamp`: The timestamp at which the agent message was interrupted, in milliseconds. This field exists only when the agent message is interrupted by human speech (`interrupted` is `true`).
  - `original`: The full content actually generated by the large model. This field exists only when the agent message is interrupted by human speech (`interrupted` is `true`).

## How to Obtain Short-Term Memory

Agora Conversational AI Engine supports two ways to obtain short-term memory:

- While the agent is running, you can call [GET Get Agent Short-Term Memory](../operations/get-history.md) to obtain the short-term memory JSON. This API returns the complete short-term memory stored during the entire lifecycle of the agent.
- After the agent stops, Agora sends the short-term memory back to your business server through the message notification service. For details, see [Message Notification Event Types](../webhook/ncs-events.md#103-agent-history).

## How to Use Short-Term Memory

### Pass Memory Content to the Large Model

Depending on the `llm.vendor` field passed in when the agent is created, Agora Conversational AI Engine uses different strategies to pass memory content to the large model:

- When `llm.vendor` is not `"custom"`, to ensure compatibility, Agora Conversational AI Engine passes only the OpenAI standard fields, namely `role` and `content`, from short-term memory.
- When `llm.vendor` is `"custom"`, Agora Conversational AI Engine passes all fields in short-term memory. You can refer to the sample code in [Custom LLM](./custom-llm.md) to implement a wrapper that filters or merges certain extension fields in short-term memory and selectively processes and passes this information to the large model.

![image](https://doc.shengwang.cn/img/convoai/use-memory.svg)

#### Non-custom Scenario

In a non-`custom` scenario, only the OpenAI standard `role` and `content` fields are passed from short-term memory as the input to the large model.

```json
{
    "messages": [
        {
            "role": "assistant",
            "content": "How can I help you today?"
        },
        {
            "role": "user",
            "content": "Can you tell me a joke?"
        },
        {
            "role": "assistant",
            "content": "Why did the scarecrow "
        },
        {
            "role": "user",
            "content": "You know what? Tell me a story instead."
        },
        {
            "role": "assistant",
            "content": "Once upon a time in a land far away, there lived a brave knight who fought dragons and saved princesses."
        },
        {
            "role": "assistant",
            "content": "Are you still there?"
        }
    ]
}
```

#### Custom Scenario

In a `custom` scenario, the agent passes the complete set of extension fields to the large model. You can refer to the sample code in [Custom LLM](./custom-llm.md) to implement a wrapper that filters and merges fields, for example:

- Add timestamps before `content`
- Add user information before `content`
- In interruption scenarios, also provide `original` to the large model

These operations can be combined with `system_messages` to achieve a smarter experience, such as helping the model understand the user or understand interruption context.

### Persist and Inject Long-Term Memory

The agent's short-term memory disappears when the agent stops. After the agent stops, you can store the short-term memory on your server and persist it as long-term memory. Later, when creating the agent, you can inject the original memory content or summarized memory content directly through `llm.system_messages`, so that the agent can still access and use those data after exiting or restarting.

The following example shows how to inject summarized memory content through `system_messages`:

```json
[
    {
        "role": "system",
        "content": "You are a helpful assistant. xxx"
    },
    {
        "role": "system",
        "content": "Previously, user has talked about their favorite hobbies with some key topics: xxx"
    }
]
```

In addition, since v1.4, you can call [POST Update Agent Configuration](../operations/agent-update.md) while the agent is running to update the `system_messages` field, thereby updating memory content.
