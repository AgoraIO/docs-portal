# Event Types

After Agora Message Notification Service is enabled, Agora notification servers send channel event callbacks to your server by HTTPS POST. The data format is JSON, the character encoding is UTF-8, and the signature algorithm is HMAC/SHA1 or HMAC/SHA256.

This page describes the event types returned in channel event callbacks and what they mean.

## Request Headers

The `header` of a message notification callback contains the following fields:

| Field Name | Value |
| :------------------- | :----------------------------------------------------------- |
| `Content-Type`       | Application/json |
| `Agora-Signature`    | The signature value generated by Agora with the customer secret and the HMAC/SHA1 algorithm. You need to verify this signature value by using the customer secret and the HMAC/SHA1 algorithm. For details, see [Verify the Signature](./enable-ncs.md#verify-the-signature). |
| `Agora-Signature-V2` | The signature value generated by Agora with the customer secret and the HMAC/SHA256 algorithm. You need to verify this signature value by using the customer secret and the HMAC/SHA256 algorithm. For details, see [Verify the Signature](./enable-ncs.md#verify-the-signature). |

## Request Body

The request body of a message notification callback contains the following fields:

| Field | Type | Description |
| :---------- | :---------- | :----------------------------------------------------------- |
| `noticeId`  | String | Notification ID that identifies one event notification from an Agora business server. |
| `productId` | Number | Business ID. A value of `17` indicates the Conversational AI Engine business. |
| `eventType` | Number | Type of notified event. For details, see [Event Types](#eventtype). |
| `notifyMs`  | Number | The Unix timestamp (ms) when the Agora message server sends the event notification to your server. This value is updated when the notification is **retried**. |
| `payload`   | JSON Object | The specific content of the notification event. `payload` varies depending on `eventType`. For details, see [Event Types](#eventtype). |

Example request body of a message notification callback:

```json
{
    "noticeId": "2000001428:4330:107",
    "productId": 17,
    "eventType": 101,
    "notifyMs": 1611566412672,
    "payload": {...}
}
```

<a id="eventtype"></a>
## Event Types

Agora Message Notification Service can notify the following events from the Conversational AI Engine service:

| eventType | event_name | Event Description |
| --- | --- | --- |
| 101 | `agent joined` | Agent joined the channel. |
| 102 | `agent left` | Agent left the channel. |
| 103 | `agent history` | After the agent stops, the stored short-term memory is sent back (the maximum number of items is determined by the `llm.max_history` parameter passed when [creating the agent](../operations/start-agent.md#llm-max_history), and the default is 32), including the following information:<br>- Conversation messages between the user and the agent<br>- Agent creation and stop timestamps |
| 110 | `agent error` | Agent error. |
| 111 | `agent metrics` | Agent performance metrics. |
| 112 | `turn finished` | Conversation turn finished. |
| 201 | `inbound call state` | Inbound call state change. |
| 202 | `outbound call state` | Outbound call state change. |

<a id="101"></a>
### 101 agent joined

When `eventType` is `101`, it indicates that the agent has joined the channel. The `payload` contains the following fields:

| Field | Type | Meaning |
| :------------ | :------- | :-------------------------------------------------- |
| `agent_id` | String | Agent ID. |
| `name` | String | Agent name. |
| `start_ts` | Number | Timestamp when the agent is created and joins the channel. |
| `channel` | String | Channel name where the agent is located. |
| `labels` | Object | Custom labels. Returned only if the `labels` field was passed when the agent was created. |

Example `payload`:

```json
{
    "agent_id": "1NT29X10YHxxxxxWJOXLYHNYB",
    "name": "support_agent_001",
    "start_ts": 1737111452,
    "channel": "xxxxx",
    "labels": {
        "campaign_id": "test_campaign",
        "customer_group": "vip"
    }
}
```

<a id="102"></a>
### 102 agent left

When `eventType` is `102`, it indicates that the agent has left the channel. The `payload` contains the following fields:

| Field | Type | Meaning |
| :------------ | :------- | :-------------------------------------------------- |
| `agent_id` | String | Agent ID. |
| `name` | String | Agent name. |
| `start_ts` | Number | Timestamp when the agent is created and joins the channel. |
| `stop_ts` | Number | Timestamp when the agent stops and leaves the channel. |
| `channel` | String | Channel name where the agent is located. |
| `status` | String | Agent status. |
| `message` | String | Reason why the agent left the channel. |
| `labels` | Object | Custom labels. Returned only if the `labels` field was passed when the agent was created. |

Examples of `payload` for different reasons why the agent leaves the channel:

#### Agent stopped manually

```json
    {
        "agent_id": "1NT29X10YHxxxxxWJOXLYHNYB",
        "name": "support_agent_001",
        "start_ts": 1737111452,
        "stop_ts": 1737111455,
        "channel": "xxxxx",
        "status": "STOPPED",
        "message": "OK"
    }
    ```

#### Agent idle timeout

```json
    {
        "agent_id": "1NT29X10YHxxxxxWJOXLYHNYB",
        "name": "support_agent_001",
        "start_ts": 1737111452,
        "stop_ts": 1737111455,
        "channel": "xxxxx",
        "status": "STOPPED",
        "message": "Idle for too long"
    }
    ```

#### Agent error

```json
    {
        "agent_id": "1NT29X10YHxxxxxWJOXLYHNYB",
        "name": "support_agent_001",
        "start_ts": 1737111452,
        "stop_ts": 1737111455,
        "channel": "xxxxx",
        "status": "FAILED",
        "message": "Connecting for too long"
    }
    ```

#### RTC connection error

```json
    {
        "agent_id": "1NT29X10YHxxxxxWJOXLYHNYB",
        "name": "support_agent_001",
        "start_ts": 1737111452,
        "stop_ts": 1737111455,
        "channel": "xxxxx",
        "status": "FAILED",
        "message": "RTC connection error"
    }
    ```

<a id="103"></a>
### 103 agent history

When `eventType` is `103`, it indicates the short-term memory of the conversation between the user and the agent. The `payload` contains the following fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `agent_id` | String | Agent ID. |
| `name` | String | Agent name. |
| `channel` | String | Channel name where the agent is located. |
| `start_ts` | Number | Timestamp when the agent is created and joins the channel. |
| `stop_ts` | Number | Timestamp when the agent stops and leaves the channel. |
| `contents` | Array[Object] | Short-term memory of the conversation between the user and the agent. It contains the following fields:<br>- `role`: Message sender role, including the following values:<br>- `user`: user.<br>- `assistant`: agent.<br>- `content`: message content. |
| `labels` | Object | Custom labels. Returned only if the `labels` field was passed when the agent was created. |

Example `payload`:

```json
{
    "agent_id": "xxxx",
    "name": "support_agent_001",
    "channel": "xxxx",
    "start_ts": 123,
    "stop_ts": 123,
    "contents": [
        {
            "role": "user",
            "content": "hello."
        },
        {
            "role": "assistant",
            "content": "hi, how can I help you?",
        }
    ],
    "labels": {
        "campaign_id": "test_campaign",
        "customer_group": "vip"
    }
}
```

<a id="110"></a>
### 110 agent error

When `eventType` is `110`, it indicates that the agent encountered an error. The `payload` contains the following fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `agent_id` | String | Agent ID. |
| `name` | String | Agent name. |
| `start_ts` | Number | Timestamp when the agent is created and joins the channel. |
| `channel` | String | Channel name where the agent is located. |
| `turn_id` | String | Subtitle conversation turn. For details, see [Real-Time Subtitles API Reference](../user-guides/realtime-sub.md#api-reference). |
| `errors` | Array | Error information. It contains the following fields:<br>- `module`: Module where the error occurred.<br>- `turn_id`: Subtitle conversation turn.<br>- `code`: Error code. You can refer to the error-code documentation of the corresponding vendor for that module.<br>- `message`: Error message. |
| `labels` | Object | Custom labels. Returned only if the `labels` field was passed when the agent was created. |

Example `payload` returned when the agent encounters an error:

```json
{
    "agent_id": "1NT29X10YHxxxxxWJOXLYHNYB",
    "name": "support_agent_001",
    "start_ts": 1737111452,
    "channel": "xxxxx",
    "turn_id": 2,
    "errors": [{"module": "llm", "turn_id":2, "code":503, "message": "Insufficient balance."}],
}
```

<a id="111"></a>
### 111 agent metrics

When `eventType` is `111`, it indicates agent performance metrics. The `payload` contains the following fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `agent_id` | String | Agent ID. |
| `name` | String | Agent name. |
| `start_ts` | Number | Timestamp when the agent is created and joins the channel. |
| `stop_ts` | Number | Timestamp when the agent stops and leaves the channel. |
| `channel` | String | Channel name where the agent is located. |
| `metrics` | Array[Object] | Performance metrics array. Each object contains the following fields:<br>- `turn_id`: Conversation turn ID.<br>- `asr_ttlw`: TTLW (Time To Last Word) metric of the ASR module, indicating the delay in milliseconds from the end of the user's speech to the ASR output of the last word.<br>- `llm_ttfb`: TTFB (Time To First Byte) metric of the LLM module, indicating the delay in milliseconds from the start of the LLM request to the first byte of the response.<br>- `llm_ttfs`: TTFS (Time To First Sentence) metric of the LLM module, indicating the elapsed time in milliseconds from the start of the LLM request to the first complete sentence in the response.<br>- `tts_ttfb`: TTFB (Time To First Byte) metric of the TTS module, indicating the delay in milliseconds from the start of the TTS request to the first byte of the response. |
| `labels` | Object | Custom labels. Returned only if the `labels` field was passed when the agent was created. |

Example `payload`:

```json
{
    "agent_id": "A42AC47Hxxxxxxxx4PK27ND25E",
    "name": "support_agent_001",
    "start_ts": 1000,
    "stop_ts": 1672531200,
    "channel": "test-channel",
    "metrics": [
        {
            "turn_id": 1,
            "tts_ttfb": 61
        },
        {
            "turn_id": 2,
            "asr_ttlw": 141,
            "llm_ttfb": 270,
            "llm_ttfs": 482,
            "tts_ttfb": 90,
        },
        {
            "turn_id": 3,
            "asr_ttlw": 103,
            "llm_ttfb": 306,
            "llm_ttfs": 948,
            "tts_ttfb": 106,
        }
    ],
    "labels": {
        "campaign_id": "test_campaign",
        "customer_group": "vip"
    }
}
```
