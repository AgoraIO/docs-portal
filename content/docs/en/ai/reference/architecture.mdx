Use this page when you want to build a voice agent yourself instead of relying on Agent Studio. It explains the minimum application shape, why each layer exists, and what order to implement the pieces in.

## What you are building

A code-first voice agent app usually has two parts:

- **Backend**: Owns secrets, generates tokens, and starts or stops the agent session.
- **Client**: Captures microphone audio, joins the Agora channel, and renders conversation state to the user.

The backend should never embed your UI logic, and the client should never embed your App Certificate or other long-lived credentials.

## Why you need a backend

If you are building your own app, the backend is responsible for:

- generating RTC and RTM tokens
- holding your App Certificate and server-side credentials
- starting the agent session
- stopping the agent session
- adding business rules, logging, and operational controls

Without a backend, the browser or mobile client would need to hold sensitive credentials directly, which is not acceptable for production.

## Recommended application shape

The smallest useful code-first app usually includes:

- **Token endpoint**
  Returns the RTC and RTM tokens the client needs to join a session.
- **Start-agent endpoint**
  Creates the agent session and joins it to the same channel as the user.
- **Stop-agent endpoint**
  Ends the session cleanly when the conversation is over.
- **Client app**
  Requests microphone permission, joins the channel, starts the agent, and displays live state such as transcripts.

## Runtime flow

The typical request flow looks like this:

1. The client opens a conversation screen.
2. The client requests tokens from your backend.
3. The client joins the Agora channel with RTC and RTM.
4. The client asks the backend to start the agent session.
5. The backend creates the agent with your chosen configuration.
6. The user and agent interact in the same channel.
7. The client displays transcripts, state changes, or multimodal content.
8. The client or backend stops the agent session when the conversation ends.

## What belongs in each layer

**Backend responsibilities**

- credential storage
- token generation
- agent lifecycle management
- provider configuration
- business rules
- logging and error handling

**Client responsibilities**

- microphone capture
- channel join and leave
- session UI
- transcript rendering
- user controls such as start, stop, mute, or interrupt

## Recommended implementation order

If you are building from scratch, implement in this order:

1. [Start and stop an agent](../build/start-stop-agent.md)
   Learn the minimum agent lifecycle and the core API calls.
2. [Use presets](../build/presets.md)
   Get a working configuration without bringing your own provider credentials.
3. Implement a token endpoint and a start-agent endpoint.
4. Build a client that can join the channel and start a session.
5. Add transcripts, events, memory, and multimodal features only after the basic path works.
