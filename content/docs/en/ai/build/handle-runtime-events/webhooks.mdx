A webhook is a user-defined HTTPS callback that lets your backend receive notifications when Conversational AI events occur. Agora sends POST requests to your webhook endpoint so your system can react to agent lifecycle changes, history delivery, errors, and performance metrics in real time.

For the combined entry point that compares client toolkit and webhook delivery, see [Get runtime events](get-runtime-events).

Use this page when you need durable backend records for monitoring, alerting, or analytics. If you need live UI state inside the app, use [Client-side events](event-notifications).

## Understand the tech

Using Agora Console, you subscribe to specific events for your project and configure the URL of the webhook endpoint that receives them. Agora sends event notifications to that endpoint whenever the subscribed events occur. Your server verifies the request signature, processes the JSON payload, and returns `200 OK` to confirm receipt.

## Common uses

Webhooks are typically used to:

- Track when an agent joins or leaves a channel
- Receive short-term memory history after an agent session ends
- Capture module-level errors for monitoring and debugging
- Collect performance metrics such as LLM and TTS latency

## Prerequisites

Before you begin, make sure you have:

- An Agora account
- An active Agora project with Conversational AI enabled
- A public HTTPS endpoint that can receive webhook callbacks
- Server-side access to store and validate the secret used for signature verification

For local testing, you also need:

- A local HTTP server that can receive POST requests.
- A tunnel such as ngrok to expose the local server over HTTPS.

## Enable notifications

To enable Agora notifications for Conversational AI:

1. Sign in to the [Agora Console](https://console.agora.io).
2. Open **Projects** and locate the target project.
3. From the product navigation, open **Conversational AI Engine** and select the **Webhook** tab.
4. Add an event and configure the delivery settings:
   - **Receiving region**: Select the region where your webhook server is deployed. Agora uses this region to route notifications to a nearby notification server.
   - **Receiving URL**: Enter the public HTTPS URL of your webhook endpoint.
   - **Subscribed events**: Select the event types you want to receive. If you need several events, select them in one configuration to avoid repeating the health check.
   - **IP allowlist**: Enable this option only if your webhook server is protected by a firewall, then add Agora notification server IP addresses to your firewall allowlist.
5. Save the generated **Secret**. You need it for signature verification.
6. Run the console-side health check and confirm your server responds with `200 OK`.
7. Save the configuration. After the health check succeeds, confirm that the webhook status is **Enabled**.

### Recommended webhook endpoint settings

- Use HTTPS only.
- Enable HTTP keep-alive if possible.
- Make sure your server responds within 10 seconds.
- For keep-alive, use at least `MaxKeepAliveRequests >= 100` and `KeepAliveTimeout >= 10` seconds when your server stack exposes these settings.

## Test a local webhook

During development, you can run a small local server, expose it with ngrok, and use the generated HTTPS URL in Agora Console.

### Run a Go receiver

The following Go example listens on `/ncsNotify`, reads the raw request body, logs the notification, and returns a JSON `200 OK` response. Add signature verification before using the endpoint in production.

```go
package main

import (
    "encoding/json"
    "io"
    "log"
    "net/http"
)

func ncsNotify(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Error(w, "method not allowed", http.StatusMethodNotAllowed)
        return
    }

    body, err := io.ReadAll(r.Body)
    if err != nil {
        http.Error(w, "failed to read body", http.StatusBadRequest)
        return
    }

    log.Printf("Agora-Signature: %s", r.Header.Get("Agora-Signature"))
    log.Printf("Agora-Signature-V2: %s", r.Header.Get("Agora-Signature-V2"))
    log.Printf("Notification body: %s", string(body))

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusOK)
    _ = json.NewEncoder(w).Encode(map[string]string{"status": "ok"})
}

func main() {
    http.HandleFunc("/ncsNotify", ncsNotify)
    log.Println("Listening on :8080")
    log.Fatal(http.ListenAndServe(":8080", nil))
}
```

Run the server:

```bash
go run main.go
```

### Expose the local endpoint

Start an HTTPS tunnel to your local server:

```bash
ngrok http 8080
```

Use the HTTPS forwarding URL as your receiving URL in Agora Console:

```text
https://example.ngrok-free.app/ncsNotify
```

When the Console health check runs, your server receives test callbacks where `channelName` is `test_webhook` and `uid` is `12121212`.

## Configure firewall allowlists

If your webhook server is behind a firewall, query Agora notification server IP addresses and add all returned addresses to your firewall allowlist.

Call the IP query API with your Agora customer ID and customer secret:

```bash
curl -u "$AGORA_CUSTOMER_KEY:$AGORA_CUSTOMER_SECRET" \
  https://api.agora.io/v2/ncs/ip
```

Agora may update notification server IP addresses. Query this API and refresh your firewall allowlist at least every 24 hours.

## Health check

Before enabling the webhook, Agora sends test callbacks for the events you subscribed to. Your server must respond within 10 seconds, return HTTP status code `200`, and use a JSON response body.

If the health check fails, Agora Console shows one of the following errors:

| Code | Error | How to fix |
| --- | --- | --- |
| `590` | Request timeout | Your server did not return `200 OK` within 10 seconds. Check response timing and network connectivity from Agora notification servers to your endpoint. |
| `591` | Domain name unreachable | The domain name is invalid or cannot resolve to the target IP address. Check DNS and server deployment. |
| `592` | Certificate error | Agora could not verify your server's SSL certificate. Check the certificate chain and, if your server uses a firewall, confirm that all Agora notification server IP addresses are allowlisted. |

## Request header

The header of notification callbacks contains the following fields:

| Field name | Value |
| --- | --- |
| `Content-Type` | `application/json` |
| `Agora-Signature` | Signature generated with the secret using HMAC/SHA1 |
| `Agora-Signature-V2` | Signature generated with the secret using HMAC/SHA256 |

## Request body

The request body of notification callbacks contains the following fields:

| Field name | Type | Description |
| --- | --- | --- |
| `noticeId` | String | Notification ID that uniquely identifies this callback |
| `productId` | Number | Product ID of the notification source |
| `eventType` | Number | Type of event being notified |
| `notifyMs` | Number | Unix timestamp in milliseconds when Agora sends the callback |
| `payload` | JSON object | Event-specific data |

The following example shows a sample request body:

```json
{
  "noticeId": "2000001428:4330:107",
  "productId": 1,
  "eventType": 101,
  "notifyMs": 1611566412672,
  "payload": {}
}
```

Agora can notify your server of the following Conversational AI events:

| eventType | Description |
| --- | --- |
| `101` | Agent joined a channel |
| `102` | Agent left a channel |
| `103` | Dialogue history notification |

| `111` | Agent performance metrics |
| `201` | Incoming call status change |
| `202` | Outgoing call status change |

## Signature verification

To communicate securely between Agora and your webhook, Agora uses signatures for identity verification:

1. When you configure notifications in Agora Console, Agora generates a secret for your project.
2. When sending a notification, Agora generates `Agora-Signature` and `Agora-Signature-V2` values using HMAC/SHA1 and HMAC/SHA256.
3. When your server receives the callback, verify one of those signatures against the raw request body.

The following Go example calculates a signature and compares it with the received value:

```go
import (
    "crypto/hmac"
    "crypto/sha1"
    "encoding/hex"
    "net/http"
)

const secret = "<replace-with-your-secret>"

func calcSignatureV1(secret, payload string) string {
    mac := hmac.New(sha1.New, []byte(secret))
    mac.Write([]byte(payload))
    return hex.EncodeToString(mac.Sum(nil))
}

func verify(requestBody, signature string) bool {
    calculatedSignature := calcSignatureV1(secret, requestBody)
    return calculatedSignature == signature
}
```

After reading the request body in your handler, verify the signature:

```go
if !verify(string(body), agoraSignature) {
    http.Error(w, "Invalid signature", http.StatusUnauthorized)
    return
}
```

## Best practices

- Keep the webhook secret on the server side only.
- Store raw payloads for troubleshooting when useful.
- Use `noticeId` as the deduplication key when storing or processing notifications, because retries can deliver the same event more than once.
- Use `notifyMs` to detect stale or out-of-order notifications. Agora does not guarantee that webhook callbacks arrive in event order.
- Return `200 OK` quickly and move heavier processing to async workers if needed.
- If Agora does not receive a `200 OK` response within 10 seconds, it retries delivery. Retry intervals increase with each attempt and delivery stops after three retries.
