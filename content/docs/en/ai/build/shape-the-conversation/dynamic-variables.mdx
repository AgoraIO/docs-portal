title: Use dynamic variables
description: Insert business information and the current date or time into the agent's system messages, greeting, and other text.
---

Dynamic variables let you reference business information, such as the user's name or your company name, in the agent's system messages and scripted messages. You can also insert the current date or time. This way, the same prompts and messages work for different users and business scenarios.

## Understand the tech

There are two types of dynamic variables. They differ in where their values come from:

| Type | Value source | Example |
| --- | --- | --- |
| Custom variable | You provide the value in `llm.template_variables` when you start the agent. | `{{user_name}}` |
| System variable | The Conversational AI Engine provides the value. You don't declare it in `template_variables`. The `now()` system variable returns the current date or time. | `{{now(timezone='America/New_York')}}` |

## Prerequisites

Before you begin, implement the basic logic for interacting with a conversational AI agent by following the [quickstart](../../get-started/quickstart).

## Implementation

You configure dynamic variables when you start the agent, using either an Agora Agents SDK or the [Start a conversational AI agent](/en/api-reference/api-ref/conversational-ai/join) REST API.

Define variables in `llm.template_variables`, then reference them as `{{variable_name}}` in the target text. Variable values must be strings.

### Use system variables

System variables are values that the Conversational AI Engine provides at the moment it renders the text. You don't declare them in `template_variables`. `now()` is the only system variable. It returns the current date or time, which lets the agent answer time-sensitive questions or greet users according to the time of day.

To insert the current time, use `{{now(...)}}` directly in a system message or scripted message. Set the time zone your business needs explicitly, and choose a format that fits your use case:

| Use case | Recommended syntax |
| --- | --- |
| Current date in New York | `{{now(format='yyyy-MM-dd', timezone='America/New_York')}}` |
| Current hour and minute in New York | `{{now(format='HH:mm', timezone='America/New_York')}}` |
| Current date and time in New York | `{{now(timezone='America/New_York')}}` |

:::info
When you reference the current time in a system message, choose a time precision that fits your use case. A value precise to the second changes often, which can reduce how much of the prompt the LLM can reuse from its cache from that point on.

If your use case only needs the current date, use `{{now(format='yyyy-MM-dd', timezone='America/New_York')}}`. Use hour, minute, or second precision only when the agent needs the exact time. Always set the time zone for where your business operates.
:::

### Understand when the time updates

The engine gets the system time each time it evaluates the expression:

- **System messages**: evaluated again before each request to the LLM, including later turns in the same session.
- **Greeting, failure, and silence messages**: evaluated each time the message is rendered. When the silence or failure message is triggered again, the engine gets the time again.
- **Updates, restarts, and reconnections**: after an update takes effect, or after the agent restarts or reconnects, the next evaluation uses the latest time.

All time expressions in one system message list, or in one rendered message, share the same moment. The engine then converts that moment to each time zone and format. For example, a New York time and a Tokyo time in the same rendered message represent the same moment.

An expression that outputs only the date also updates at the next evaluation after the date changes in the target time zone.

## Supported text fields

You can reference the same variable in several text fields. Both custom variables and system variables work in the following fields:

| Field | Description |
| --- | --- |
| `llm.system_messages[].content` (string) | System message. Gives the LLM a role, prompt, or sample answers. |
| `llm.greeting_message` | Greeting. The text the agent says when a user joins. |
| `llm.failure_message` | Failure message. The text the agent says when the LLM call fails. |
| `parameters.silence_config.content` | Silence message. After the silence timeout, the agent says this text if `action` is `speak`, or passes it to the LLM if `action` is `think`. |

Rendering replaces only text. Message roles, the order of text segments, and non-text content stay the same. For the full definition of each field, see [Start a conversational AI agent](/en/api-reference/api-ref/conversational-ai/join).

## Reference

This section describes the time function syntax, supported time formats, and replacement rules.

### Time function parameters

The time function accepts two parameters: `format` and `timezone`. Name both parameters explicitly:

| Parameter | Type | Description | Default |
| --- | --- | --- | --- |
| `format` | String | The output format of the time. | `yyyy-MM-dd HH:mm:ss` |
| `timezone` | String | An IANA time zone name or alias, such as `America/New_York`, `Asia/Tokyo`, or `UTC`. | The local time zone of the engine's runtime environment |

Parameter names are case-sensitive, and you can pass the two named parameters in any order. The following table shows common syntax:

| Syntax | Format and time zone |
| --- | --- |
| `{{now()}}` | Default format, in the local time zone of the engine's runtime environment. |
| `{{now('yyyy-MM-dd')}}` | Date only, in the local time zone of the engine's runtime environment. |
| `{{now('yyyy-MM-dd', 'America/New_York')}}` | The first argument sets the format, and the second sets the time zone. |
| `{{now(timezone='America/New_York')}}` | Sets only the time zone and uses the default format. |
| `{{now(format='yyyy-MM-dd', timezone='America/New_York')}}` | Sets the format and the time zone by parameter name. |
| `{{now('HH:mm', timezone='America/New_York')}}` | The first argument sets the format, and `timezone` sets the time zone. |

Strings can use single or double quotes. To use double quotes inside a JSON string, escape them as `\"`. For example:

```json
{
  "properties": {
    "llm": {
      "greeting_message": "It's {{now(timezone=\"America/New_York\")}} in New York."
    }
  }
}
```

Default values apply only when you omit a parameter. If the format, the time zone, or the syntax is invalid, the engine leaves the whole placeholder unchanged. Other variables are still replaced, and the agent still starts. For example, the engine leaves `{{now(format='HH:mm', timezone='Invalid/Zone')}}` unchanged because the time zone is invalid. It doesn't fall back to the local time.

### Common time formats

The following examples use `2026-11-04 14:35:08.123` in the `America/New_York` time zone:

| Format | Example output |
| --- | --- |
| `yyyy-MM-dd HH:mm:ss` (default) | `2026-11-04 14:35:08` |
| `yyyy-MM-dd` | `2026-11-04` |
| `HH:mm` | `14:35` |
| `yyyy-MM-dd'T'HH:mm:ss.SSSXXX` | `2026-11-04T14:35:08.123-05:00` |

Format tokens are case-sensitive: `MM` is the month, and `mm` is the minute. `XXX` outputs the time zone offset with a colon, or `Z` for a zero offset. `'T'` is a literal, and the output doesn't include the single quotes.

### Replacement rules

The engine replaces variables according to the following rules:

- `{{now}}` uses `template_variables.now` if you provide it. Otherwise, it uses the current local time of the runtime environment in the default format. `{{now()}}` and `{{now(...)}}` with arguments always call the system time function and never read `template_variables.now`.
- The engine replaces each variable value only once. It doesn't parse variables or time functions inside a replaced value.
- The time function works only in the [supported text fields](#supported-text-fields). It doesn't work in user messages or in tool request parameters.
