Voice Agent supports **human-to-agent** interaction: a person speaks with an AI agent that uses models to generate a spoken response. You define the agent's instructions, model configuration, and access to your data or tools. Agora provides the real-time connection and the **Conversational AI Engine** that runs the conversation.

## How an app conversation works

Your **client** is the application on the user's browser or device. Your **backend** supplies credentials and starts or stops the agent. The **Conversational AI Engine** connects the agent to the conversation and uses the configured models to respond.

![An app conversation starts with the client joining RTC and requesting an agent from its backend. The backend calls the Conversational AI Engine, which joins an agent to the channel. Audio passes through RTC, and the backend stops the agent when the conversation ends.](/images/developer-journey/voice-agent-session.svg)

1. The client joins an RTC channel with the credentials provided by your backend.
2. Your backend uses an **Agent SDK** or the **REST API** to start an agent in the same channel.
3. The engine receives speech and uses your model configuration to produce a response. The agent's audio returns to the client through RTC.
4. When the user ends the conversation, your backend stops the agent and the client leaves the channel.

The Agent SDK runs in your backend and calls the Agora service. It does not replace the client's RTC SDK or host the engine on your server.

You can configure the models in two ways:

- **Speech-to-text, language model, and text-to-speech pipeline**: Converts speech to text, generates an answer, then converts that answer back to speech.
- **Real-time multimodal model**: Handles speech directly, without those separate steps.

The model guides explain the configuration for each provider.
