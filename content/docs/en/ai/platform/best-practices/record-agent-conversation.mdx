This guide explains how to record conversations with a Conversational AI Platform agent using Agora [Cloud Recording](/en/api-reference/api-ref/cloud-recording), how to avoid audio interruptions when recording starts, and what to consider when you record.

## Why this needs special handling

When an agent and Cloud Recording are in the same channel, recording startup can briefly interrupt the audio. The issue is usually caused by the agent's audio scenario falling back to a default mode when Cloud Recording joins the channel.

To keep the audio stable, set the agent's audio scenario to `chorus` when you start the session.

The audio scenario is a session setting, not part of the agent. Set it only for the sessions you record. Other sessions keep the default, `aiserver`. For details, see [Optimize audio quality](/en/ai/platform/best-practices/audio-setup).

## Start recording

To record the whole conversation, start Cloud Recording first. Start the session only after the recording service joins the channel and subscribes to the audio streams.

To record conversations with an agent, Cloud Recording provides a Conversational AI compatible recording mode. Unlike regular recording, this mode doesn't use a 1-second jitter buffer. It supports audio-only individual recording and saves the user's audio and the agent's audio in separate files. Video recording and composite recording aren't supported in this mode.

{/* TODO(platform-confirm): The Voice Agent API reduces silence at the start of recorded files with `parameters.rtc.publish_audio_auto_publishing: false`. The Platform API has no equivalent session field. Confirm whether the Platform needs one. */}

1. Follow the steps in [Individual recording](/en/realtime-media/cloud-recording/build/start-a-recording/individual-mode#get-a-resource-id) to get a resource ID. Prepare the channel name, recording UID, token, and cloud storage configuration. Use a recording UID that's different from the agent's and the user's UIDs.
2. Call [Start recording](/en/api-reference/api-ref/cloud-recording/start). In the request URL, set `mode` to `raw`. In the request body, set `clientRequest.recordingConfig.streamTypes` to `0` to record audio only.
3. To enable the Conversational AI compatible recording mode, add the following configuration to `clientRequest.advanceConfig` in the request body:

   ```json
   {
     "clientRequest": {
       "advanceConfig": {
         "blankAudioVideoDuration": 2147483647,
         "convoAiCompatibleEnable": true
       }
     }
   }
   ```

4. After the recording service joins the channel and subscribes to the audio streams, [start the session](#start-the-session-with-the-chorus-audio-scenario).

The following table describes the `advanceConfig` fields:

| Field | Description |
| --- | --- |
| `blankAudioVideoDuration` | How long, in milliseconds, the audio and video streams can both stay muted before the recording service ends the current recording file. |
| `convoAiCompatibleEnable` | Set to `true` to enable the Conversational AI compatible recording mode. |

For details about each field, see the [Start recording](/en/api-reference/api-ref/cloud-recording/start) API reference.

## Considerations

Keep the following in mind when you record agent conversations:

- If you start recording during a conversation, or recording resumes after the recording service fails or restarts, the recording might miss the speech the agent is playing at that moment, or capture only its end.
- The order of speech and the points where users interrupt the agent in the recorded files can differ from what the user heard. For example, the agent's speech in the recording might stop before the user speech that interrupted it begins.
