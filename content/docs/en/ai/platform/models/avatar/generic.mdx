The `generic` avatar vendor lets you integrate a custom avatar provider into the Conversational AI Platform.

## Sample configuration

The following example shows how to configure a generic avatar provider as the agent's avatar when you create or update an agent. For a complete example, see [Create an agent and start a session](/en/ai/platform/get-started/start-stop-agent#create-an-agent).

Generic avatar providers support BYOK only. They aren't available in managed mode. Store your avatar provider's API key in a secret set, and refer to it from the agent. For details, see [Use your own provider keys](/en/ai/platform/build/use-your-own-keys).

<TabsContent value="rest-api">

Add an `avatar` block to the `pipeline`. Set `credential.mode` to `byok` and `credential.fields.api_key` to the reference. In the following example, the key is stored as `avatar` in the `support_prod` set:

```json
"avatar": {
  "enabled": true,
  "credential": {
    "mode": "byok",
    "fields": {
      "api_key": "$secrets.support_prod.avatar"
    }
  },
  "vendor": "generic",
  "params": {
    "api_base_url": "<avatar_api_base_url>",
    "avatar_id": "<avatar_id>",
    "agora_token": "<avatar_rtc_token>",
    "agora_uid": "<avatar_rtc_uid>"
  }
}
```

</TabsContent>

<TabsContent value="python">

```python
from agora_agent import Agent, GenericAvatar, secret_ref

# client is your configured Agora client
agent = (
    Agent(client=client)
    .with_stt(...)  # configure your ASR vendor
    .with_llm(...)  # configure your LLM vendor
    .with_tts(...)  # configure your TTS vendor
    .with_avatar(
        GenericAvatar(
            api_key=secret_ref("support_prod", "avatar"),
            api_base_url="<avatar_api_base_url>",
            avatar_id="<avatar_id>",
            agora_uid="<avatar_rtc_uid>",
            agora_token="<avatar_rtc_token>",
        )
    )
)
```

</TabsContent>

## Key parameters

The `avatar` block takes the following fields. In the SDKs, `GenericAvatar` sets them from its options, and passes any other parameters from its additional parameters option to `params`.

<ParameterList title="avatar" required={true}>
  <Parameter name="enabled" type="boolean" required={true}>
    Set to `true` to show the avatar.
  </Parameter>
  <Parameter name="vendor" type="string" required={true}>
    Set to `generic`.
  </Parameter>
  <Parameter name="credential" type="object" required={true}>
    Set `mode` to `byok` and `fields.api_key` to a `$secrets.<set>.<key>` reference to the API key for your avatar provider.
  </Parameter>
  <Parameter name="params" type="object" required={true}>
    <Parameter name="api_base_url" type="string" required={true}>
      The base URL of the avatar provider's API endpoint.
    </Parameter>
    <Parameter name="avatar_id" type="string" required={true}>
      The unique identifier for the avatar to use.
    </Parameter>
    <Parameter name="agora_token" type="string" required={false}>
      The RTC token that authorizes the avatar to join the video channel. Generate this token using your Agora project credentials.
    </Parameter>
    <Parameter name="agora_uid" type="string" required={true}>
      The unique identifier for the avatar's RTC connection. This must be different from other participants in the channel.
    </Parameter>
  </Parameter>
</ParameterList>

This integration is fully supported for use with the Conversational AI Platform. While it has completed functional validation, it is newer to the platform, and additional provider-specific edge cases may be identified as usage scales across a broader range of applications and workloads.
