LiveAvatar by HeyGen provides AI-powered avatars with high-quality video rendering and customizable video quality settings, enabling professional video conversations with your AI agents.

## Sample configuration

The following example shows how to configure LiveAvatar as the agent's avatar when you create or update an agent. For a complete example, see [Create an agent and start a session](/en/ai/platform/get-started/start-stop-agent#create-an-agent).

LiveAvatar supports BYOK only. It isn't available in managed mode. Store your LiveAvatar API key in a secret set, and refer to it from the agent. For details, see [Use your own provider keys](/en/ai/platform/build/use-your-own-keys).

```python
from agora_agent import Agent, LiveAvatarAvatar, secret_ref

# client is your configured Agora client
agent = (
    Agent(client=client)
    .with_stt(...)  # configure your ASR vendor
    .with_llm(...)  # configure your LLM vendor
    .with_tts(...)  # configure a TTS vendor with a 24,000 Hz sample rate
    .with_avatar(
        LiveAvatarAvatar(
            api_key=secret_ref("support_prod", "liveavatar"),
            quality="high",
            agora_uid="<avatar_rtc_uid>",
            agora_token="<avatar_rtc_token>",
            avatar_id="65f9e3c9-d48b-4118-b73a-4ae2e3cbb8f0",
        )
    )
)
```

<TabsContent value="rest-api">

Add an `avatar` block to the `pipeline`. Set `credential.mode` to `byok` and `credential.fields.api_key` to the reference. In the following example, the key is stored as `liveavatar` in the `support_prod` set:

```json
"avatar": {
  "enabled": true,
  "credential": {
    "mode": "byok",
    "fields": {
      "api_key": "$secrets.support_prod.liveavatar"
    }
  },
  "vendor": "liveavatar",
  "params": {
    "agora_token": "<avatar_rtc_token>",
    "agora_uid": "<avatar_rtc_uid>",
    "quality": "high",
    "avatar_id": "65f9e3c9-d48b-4118-b73a-4ae2e3cbb8f0"
  }
}
```

## Key parameters

The `avatar` block takes the following fields. In the SDKs, `LiveAvatarAvatar` sets them from its options, and passes any other parameters from its additional parameters option to `params`.

<ParameterList title="avatar" required={true}>
 <Parameter name="enabled" type="boolean" required={true}>
 Set to `true` to show the avatar.
 </Parameter>
 <Parameter name="vendor" type="string" required={true}>
 Set to `liveavatar`.
 </Parameter>
 <Parameter name="credential" type="object" required={true}>
 Set `mode` to `byok` and `fields.api_key` to a `$secrets.<set>.<key>` reference to your LiveAvatar API key. Get your API key from the LiveAvatar console.
 </Parameter>
 <Parameter name="params" type="object" required={true}>
  <Parameter name="quality" type="string" possibleValues="low, medium, high" required={true}>
  The video quality for the avatar rendering.

  - `"high"` (720p)
  - `"medium"` (480p)
  - `"low"` (360p)

  Higher quality provides a better visual experience but requires more bandwidth.
  </Parameter>
  <Parameter name="agora_uid" type="string" required={true}>
  The unique identifier for the avatar's RTC connection. This must be different from other participants in the channel.
  </Parameter>
  <Parameter name="agora_token" type="string" required={false}>
  The RTC token that authorizes the avatar to join the video channel. Generate this token using your Agora project credentials.
  </Parameter>
  <Parameter name="avatar_id" type="string" required={false}>
  The unique identifier for the avatar you want to use.
  </Parameter>
  <Parameter name="disable_idle_timeout" type="boolean" defaultValue="false" required={false}>
  Whether to disable the idle timeout feature.
  </Parameter>
  <Parameter name="activity_idle_timeout" type="integer" defaultValue="120" required={false}>
  The number of seconds of inactivity before the avatar session times out. Only applies when `disable_idle_timeout` is `false`.
  </Parameter>
 </Parameter>
</ParameterList>

For advanced configuration options, refer to the [LiveAvatar official documentation](https://docs.liveavatar.com/reference/create_session_token_v1_sessions_token_post).

This integration is fully supported for use with the Conversational AI Platform. While it has completed functional validation, it is newer to the platform, and additional provider-specific edge cases may be identified as usage scales across a broader range of applications and workloads.
