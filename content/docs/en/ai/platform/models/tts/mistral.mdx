Mistral provides enterprise-grade AI voice generation with text-to-speech (TTS) models.

## Sample configuration

Add a `tts` block to the `pipeline` when you create or update an agent. For a complete request, see [Create an agent and start a session](/en/ai/platform/get-started/start-stop-agent#create-an-agent). Mistral supports BYOK only. It isn't available in managed mode.

Store your Mistral API key in a secret set. Then set `credential.mode` to `byok` and `credential.api_key` to a reference to the key. For details, see [Use your own provider keys](/en/ai/platform/build/use-your-own-keys).

In the following example, the key is stored as `mistral` in the `support_prod` set:

```json
"tts": {
  "credential": {
    "mode": "byok",
    "api_key": "$secrets.support_prod.mistral"
  },
  "vendor": "mistral",
  "params": {
    "model": "voxtral-mini-tts-2603",
    "voice": "<your_mistral_voice>"
  }
}
```

## Key parameters

<ParameterList title="tts">
  <Parameter name="vendor" type="string" required={true}>
    Set to `mistral`.
  </Parameter>
  <Parameter name="credential" type="object" required={true}>
    Set `mode` to `byok` and `api_key` to a `$secrets.<set>.<key>` reference to your Mistral API key.
  </Parameter>
  <Parameter name="params" type="object" required={false}>
    <Parameter name="model" type="string" required={false}>
      The TTS model to use, for example `voxtral-mini-tts-2603`.
    </Parameter>
    <Parameter name="voice" type="string" required={false}>
      The voice identifier to use.
    </Parameter>
  </Parameter>
</ParameterList>

:::caution[Caution]
The parameters listed on this page are validated for use with the Conversational AI Platform. Required parameters must be provided as documented. Any additional parameters in `params` are passed through directly to Mistral without validation. For a full list of supported options, refer to the [Mistral documentation](https://docs.mistral.ai/api/endpoint/audio/speech).
:::

This integration is fully supported for use with the Conversational AI Platform. While it has completed functional validation, it is newer to the platform, and additional provider-specific edge cases may be identified as usage scales across a broader range of applications and workloads.
