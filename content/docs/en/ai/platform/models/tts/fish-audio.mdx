Fish Audio provides text-to-speech (TTS) with flexible models and high-quality synthetic voices.

## Sample configuration

Add a `tts` block to the `pipeline` when you create or update an agent. For a complete request, see [Create an agent and start a session](/en/ai/platform/build/start-stop-agent#create-an-agent). Fish Audio supports BYOK only. It isn't available in managed mode.

Store your Fish Audio API key in a secret set. Then set `credential.mode` to `byok` and `credential.api_key` to a reference to the key. For details, see [Use your own provider keys](/en/ai/platform/build/use-your-own-keys).

In the following example, the key is stored as `fishaudio` in the `support-prod` set:

```json
"tts": {
  "credential": {
    "mode": "byok",
    "api_key": "$secrets.support-prod.fishaudio"
  },
  "vendor": "fishaudio",
  "params": {
    "reference_id": "<voice_model_id>",
    "backend": "speech-1.5"
  }
}
```

## Key parameters

<ParameterList title="tts">
  <Parameter name="vendor" type="string" required={true}>
    Set to `fishaudio`.
  </Parameter>
  <Parameter name="credential" type="object" required={true}>
    Set `mode` to `byok` and `api_key` to a `$secrets.<set>.<key>` reference to your Fish Audio API key.
  </Parameter>
  <Parameter name="params" type="object" required={true}>
    <Parameter name="reference_id" type="string" required={true}>
      The identifier of the voice model to use for speech synthesis.
    </Parameter>
    <Parameter name="backend" type="string" required={true}>
      The backend model version to use. For example, `speech-1.5`.
    </Parameter>
  </Parameter>
</ParameterList>

:::caution[Caution]
The parameters listed on this page are validated for use with the Conversational AI Platform. Required parameters must be provided as documented. Any additional parameters in `params` are passed through directly to Fish Audio without validation. For a full list of supported options, refer to the [Fish Audio documentation](https://docs.fish.audio/sdk-reference/python/api-reference).
:::

This integration is fully supported for use with the Conversational AI Platform. While it has completed functional validation, it is newer to the platform, and additional provider-specific edge cases may be identified as usage scales across a broader range of applications and workloads.
