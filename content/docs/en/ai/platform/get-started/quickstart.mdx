Set up a working Conversational AI Platform agent in under five minutes. This page walks you through installing Agora Skills to give your AI coding assistant the official Platform quickstarts and Agora CLI workflows. You then use the CLI to sign in, clone the official Platform starter, and run it locally. You can follow the CLI steps yourself or paste the sample prompt and let your assistant handle setup for you.

If you are new to Agora, read [Core concepts](/en/introduction/core-concepts) first to understand how RTC, Signaling, channels, UIDs, and tokens fit together.

:::info
The Conversational AI Platform is in Preview. During the Preview, agent sessions run in North America (US).
:::

## Set up your tools

Install Agora Skills to let your AI coding assistant set up the starter for you, or install the Agora CLI to run each command yourself.

### Install Agora Skills

Agora Skills teach your AI coding assistant how to work with Conversational AI Platform projects using official starter repos and the Agora CLI, including signing in, project binding, generating environment files, and running diagnostics. Install the Agora CLI yourself, or ask your assistant to run the installer for you.

{/* TODO(platform-confirm): Confirm that AgoraIO/skills includes the Platform workflows, or give the name of the skill package that does. */}

```bash
npx skills add AgoraIO/skills
```

Paste the following prompt into your assistant's chat. You can replace Python with TypeScript or Go depending on your language preference:

```text
Set up and run the Agora Conversational AI Platform Python starter project locally.
```

Your assistant installs the CLI, signs you in, scaffolds the official Platform starter, and guides you through the remaining steps.

## Sign in, scaffold, and run

Sign in with the Agora CLI, clone the Platform starter project, and configure it for your chosen language.

1. Sign in to Agora Console.

    ```bash
    agora login
    ```

2. Use `agora init` to clone the official Platform starter for your chosen template, bind it to your
    Agora project, and write the runtime-specific environment file.

## What just happened

The CLI cloned the selected Platform starter, connected it to your Agora project, and wrote
the environment configuration required to run the demo locally.

The demo runs a local browser app and server-side agent controls:

- **Browser app**: Joins an RTC channel, sends your microphone audio to the agent, plays the agent's spoken responses, and shows the conversation transcript.
- **Server-side controls**: Create a saved agent in your project, generate tokens, and start or stop sessions that run the agent.

The starter saves the agent configuration in your project once. Each time you click
**Start conversation**, it starts a new session that refers to the saved agent by its ID.

{/* TODO(platform-confirm): Confirm when the starter creates the agent (on first run or with a setup command), and that it reuses the saved agent on later runs instead of creating a new one each time. */}

Agora provides the real-time path between the user and the agent. The user and
agent join the same Agora channel, and Agora transports low-latency audio and
session events between them.

{/* TODO(platform-confirm): Confirm whether the starter generates the agent's RTC token or leaves `transport.token` out and lets Agora issue it. */}

The agent uses managed mode. Agora provides access to the models, and the starter
doesn't need provider API keys. The models handle the speech pipeline:

1. ASR converts user speech to text.
2. The LLM reasons over the conversation and generates a response.
3. TTS converts the response back to speech.
