On the Conversational AI Platform, you create an agent once and save it in your project. For each conversation, you start a session that runs the agent in an RTC channel, and you stop the session when the conversation ends. This page shows the code for each step. In a production environment, run this code on your business server.

## Understand the tech

An agent is a saved configuration. A session is a single conversation that runs it. The workflow is as follows:

1. Your server creates an agent and stores the agent ID that the Platform returns. You do this once, not for every conversation.
2. Your server starts a session with the agent ID, the channel name, and the user's UID. The agent and the user, through your app, join the same RTC channel. The agent talks to the user, using the agent's ASR, LLM, and TTS models and Agora's low-latency Software-Defined Real-Time Network (SDRTN®).
3. When the conversation ends, your server stops the session, and the agent leaves the channel.

<TabsContent value="rest-api">

Send a request to [Create an agent](/en/api-reference/api-ref/conversational-ai/platform/create-agent). The `pipeline` sets the agent's ASR, LLM, and TTS models. In the `Idempotency-Key` header, pass a unique value for each agent you create. If a request times out, retry it with the same key and the same body. The Platform returns the agent it already created instead of creating a duplicate.

```bash
curl --request POST \
  --url https://preview.ai.agora.io/conversational-ai/v1/projects/<your_app_id>/agents \
  --header 'Authorization: Basic <your_base64_encoded_credentials>' \
  --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: <your_unique_key>' \
  --data '
{
  "agent_name": "Support agent",
  "instructions": "You are a friendly support agent for Acme. Address the user as {{customer_name}}. Keep your answers short.",
  "variables": {
    "customer_name": {
      "type": "str",
      "required": true
    }
  },
  "greeting": {
    "mode": "text",
    "on": "each_join",
    "text": "Hi {{customer_name}}, how can I help you today?"
  },
  "pipeline": {
    "mode": "cascaded",
    "asr": {
      "credential": { "mode": "managed" },
      "vendor": "deepgram",
      "model": "nova-3",
      "language": "en-US"
    },
    "llm": {
      "credential": { "mode": "managed" },
      "vendor": "openai",
      "style": "openai",
      "model": "gpt-4.1-mini"
    },
    "tts": {
      "credential": { "mode": "managed" },
      "vendor": "minimax",
      "params": {
        "model": "speech-2.6-turbo",
        "voice_setting": {
          "voice_id": "English_captivating_female1",
          "speed": 1
        }
      }
    }
  }
}'
```

## Start a session

To start a conversation, start a session with the agent ID and the following details:

- The RTC channel for the conversation.
- The RTC token for the agent's UID.
- The UID the agent uses in the channel. It must be different from the user's UID.
- The UID of the user the agent talks to.
- A value for each required variable that you defined when you created the agent, such as `customer_name`.

<TabsContent value="rest-api">

Send a request to [Start a session](/en/api-reference/api-ref/conversational-ai/platform/start-session). In `transport`, set:

- `type`: `rtc`, to run the session in an RTC channel. To run the session in a phone call, you use `telephony` instead. For details, see [Make outbound calls and run campaigns](/en/ai/platform/build/phone-calls/outbound-calls-campaigns).
- `channel`: The RTC channel for the conversation.
- `token`: The RTC token for the agent's UID.
- `uid`: The agent's UID.
- `subscribe_uids`: The user's UID.

In `values`, pass the variable values.

```bash
curl --request POST \
  --url https://preview.ai.agora.io/conversational-ai/v1/projects/<your_app_id>/sessions \
  --header 'Authorization: Basic <your_base64_encoded_credentials>' \
  --header 'Content-Type: application/json' \
  --data '
{
  "agent_id": "agent_k3n9x2",
  "values": {
    "customer_name": "Ada"
  },
  "transport": {
    "type": "rtc",
    "channel": "<your_channel_name>",
    "token": "<your_rtc_token>",
    "uid": "1002",
    "subscribe_uids": ["1001"]
  }
}'
```

If the request is successful, the response contains the session ID and its [status](#check-the-session-status):

```json
// 201 Created
{
  "agent_session_id": "a42ac95tp25py49fc37hp94vm67ht52h",
  "status": "running",
  "created_at": 1737111452
}
```

</TabsContent>

When the agent is in the channel, `status` is `RUNNING`. A session has one of the following statuses:

| Status | Description |
|---|---|
| `IDLE` | The session is idle. |
| `STARTING` | The session is starting, and the agent hasn't joined the channel yet. |
| `RUNNING` | The agent is in the channel. |
| `STOPPING` | The session is stopping. |
| `STOPPED` | The session has ended, and the agent has left the channel. |
| `FAILED` | The session failed. Check `message` for the reason. |
