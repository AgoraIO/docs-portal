Run an official starter with a browser client and a Python, TypeScript, or Go backend. You start a conversation, hear the agent respond, and see the transcript. The backend provides credentials and session control. Agora runs the Conversational AI Engine.

Choose how you want to set up:

- **Let your coding assistant do it.** Start with [Set up with your assistant](#set-up-with-your-assistant).
- **Run the commands yourself.** Start with [Install the Agora CLI](#install-the-agora-cli).
- **Already followed [Start with AI](/en/introduction/start-with-ai)?** Your CLI and Skills are ready. Go to [Sign in, scaffold, and run](#sign-in-scaffold-and-run).

For definitions of App ID, App Certificate, and token, see [Platform concepts](/en/introduction/core-concepts#project-credentials-and-authentication).

## Set up with your assistant

Agora Skills teaches your AI coding assistant how to work with Conversational AI projects using official starter repos and the Agora CLI. It covers signing in, project binding, generating environment files, and running diagnostics.

```bash
npx skills add AgoraIO/skills
```

Paste this prompt into your assistant's chat. To use a different language, replace Python with TypeScript or Go:

```text
Set up and run the Agora Conversational AI Python starter project locally.
```

Your assistant installs the CLI, signs you in, scaffolds the official starter, and runs it. When the app is running at `http://localhost:3000`, continue to [What just happened](#what-just-happened). If the agent does not start, see [If the agent does not start](#if-the-agent-does-not-start).

To run each command yourself instead, continue with [Install the Agora CLI](#install-the-agora-cli).

## Sign in, scaffold, and run

Sign in with the Agora CLI, clone the starter project, and configure it for your chosen language.

1. Sign in to Agora Console:

    ```bash
    agora login
    ```

2. Use `agora init` to clone the official starter for your chosen template, bind it to your Agora project, and write the runtime-specific environment file:

    <Tabs defaultValue="python" groupId="ai-sdk-language" persist>
    <TabsList>
      <TabsTrigger value="python">Python</TabsTrigger>
      <TabsTrigger value="typescript">TypeScript</TabsTrigger>
      <TabsTrigger value="go">Go</TabsTrigger>
    </TabsList>

    <TabsContent value="python">

    ```bash
    agora init my-python-demo --template python
    cd my-python-demo
    # Set up the web client and Python backend.
    bun run setup
    # Start the web client and Python backend.
    bun run dev
    ```

    </TabsContent>

    <TabsContent value="typescript">

    ```bash
    agora init my-nextjs-demo --template nextjs
    cd my-nextjs-demo
    pnpm install
    pnpm dev
    ```

    </TabsContent>

    <TabsContent value="go">

    ```bash
    agora init my-go-demo --template go
    cd my-go-demo
    make setup
    make dev
    ```

    </TabsContent>
    </Tabs>

3. Open `http://localhost:3000` and click **Start conversation**. Allow microphone access, speak, and confirm that you hear a response and see the transcript. End the conversation in the app when you are finished.

## If the agent does not start

If the agent does not join the channel, or transcripts do not appear, run the CLI diagnostic:

```bash
agora project doctor
```

It checks credential validity, feature enablement, and network reachability.

:::info
Conversational AI Engine is enabled by default for new projects and can't be disabled. If you're using an older project and the agent fails to start, verify that Conversational AI Engine is enabled on the **RTC Services** page in [Agora Console](https://console.agora.io/).
:::

## What just happened

The CLI cloned the selected starter, connected it to your Agora project, and wrote
the environment configuration required to run the demo locally.

The demo runs a local browser app and server-side agent controls:

- **Browser app**: Captures microphone audio and plays the agent response.
- **Server-side controls**: Generate tokens and use the Agent SDK to start or stop the agent session.

Agora provides the real-time path between the user and the agent. The user and
agent join the same Agora channel, and Agora transports the live audio between them. The starter also receives the session events that it uses to show transcripts in the browser.

The configured models handle the speech pipeline:

1. ASR converts user speech to text.
2. The LLM reasons over the conversation and generates a response.
3. TTS converts the response back to speech.

For a diagram of this flow, see [How an app conversation works](/en/ai#how-an-app-conversation-works).
