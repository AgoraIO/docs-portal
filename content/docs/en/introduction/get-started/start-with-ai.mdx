If you want to use an AI coding agent on an Agora project, the main problem is usually not writing more code. The real problem is giving the agent the right context, the right route through the docs, and a runnable place to start.

When working with Agora, agents usually need three things:

1. Up-to-date official documentation
The agent needs current APIs, SDK details, parameters, platform differences, and recommended patterns instead of relying on stale model memory.

2. The right integration path
Agora spans conversational AI, RTC, messaging, recording, tokens, and more. The agent needs to identify what you are building first, then choose the right quickstart, docs, and implementation order.

3. A runnable starting point
For most engineering tasks, it is better to start from an official starter, working environment files, and a diagnosable local workflow than from an empty folder.

Agora’s `MCP`, `Skills`, and `CLI` map directly to those needs.

## When to use this path

This is the best starting page when:

- you want an AI coding assistant to help with implementation
- you are not yet sure which Agora product path fits your task
- you want to start from an official starter instead of an empty repo
- you want repeatable setup, diagnostics, and product routing instead of ad hoc prompting

If you already know you need a specific quickstart, you can jump directly to [Voice agent quickstart](/en/ai/choose-your-path/quickstart-coding) or [Voice & Video quickstart](/en/realtime-media/rtc/android/quick-start/build-from-scratch).

## What coding agents need

More broadly, when a coding agent works on an Agora task, it should be able to:

- check the latest official docs before answering questions or generating code
- identify the right product and platform before selecting an implementation path
- start from an official runnable example instead of inventing project structure from scratch
- inspect local setup and run consistent diagnostics when something fails

This is why a raw API reference alone is not enough. The agent also needs workflow guidance: what to do first, what to look up, when to use an official starter, and which steps should be handled by official tooling.

## How Agora provides those capabilities

### Agora MCP: fresh official documentation

`Agora MCP` solves the freshness and accuracy problem. It gives your coding agent direct access to Agora docs so it can retrieve current APIs, SDK methods, platform details, and related documentation pages in real time.

This is useful when the agent needs to:

- find the latest setup steps for a specific platform
- confirm the meaning of an API, parameter, or error code
- read documentation before proposing or generating code

- [Integrate with MCP](/en/ai/get-started/mcp-integrate)

### Agora Skills: the right workflow and product routing

`Agora Skills` solves the “what path should I follow?” problem. It gives the agent structured guidance for product routing, setup flows, starter selection, and common multi-product combinations.

This is useful when the agent needs to:

- determine whether the task is conversational AI, RTC, RTM, recording, or token generation
- choose the most relevant official starter
- break a larger task into a primary product plus supporting capabilities
- follow Agora-specific build flows instead of improvising generic scaffolding

- [Integrate with Skills](/en/ai/get-started/skills-integrate)

### Agora CLI: turning guidance into a local working project

`Agora CLI` turns workflow guidance into local execution. It handles login, project creation or binding, official quickstart setup, environment file generation, and readiness diagnostics.

This is useful when the agent needs to:

- create or bind an Agora project
- clone an official quickstart
- write the correct environment variables for a supported template
- inspect workspace and project readiness before continuing
- expose local Agora workflows to an agent through MCP

In practice, Agora Skills often route the agent toward Agora CLI for the execution steps, especially for project setup, quickstart bootstrapping, env writing, and readiness checks.

- [Agora CLI developer documentation](https://agoraio.github.io/cli/)
- [Agora CLI GitHub](https://github.com/AgoraIO/cli)

## Recommended starting flow

The strongest setup is to combine all three capabilities:

1. Use `Agora MCP` so the agent can check the latest docs.
2. Use `Agora Skills` so the agent can identify the right product, platform, and workflow.
3. Use `Agora CLI` so the agent can bootstrap a starter, write env files, and run local diagnostics.

That gives you an assistant that can research, choose the right path, and execute locally, instead of just generating code in the abstract.

## Start from a voice agent starter

A typical workflow is to have the agent start from an official conversational AI starter instead of generating the entire project structure from scratch.

```text
Use Agora MCP and Agora Skills to help me build a conversational AI demo for the web.
Check the official docs first, then choose the right starter and use the Agora CLI to initialize it.
Use Next.js. I want users to open the page and start talking to the AI with voice immediately.
```

If you prefer to run the setup yourself, a minimal flow for a web starter is:

```bash
agora login
agora init my-nextjs-demo --template nextjs
```

That command initializes the official Next.js starter locally, binds it to your Agora project, and writes the environment you need to run the demo.

The starter gives you a production-style baseline for browser voice AI, including a web client, live transcript UI, agent state visualization, and the server routes required to start and stop a conversation.

## Best practices

- Have the agent search docs before generating code, especially for APIs, auth, parameters, and platform differences.
- Be explicit about the target product, platform, language, and goal before implementation starts.
- Prefer official starters and customize from a working baseline.
- For multi-product flows, define the primary product first, then add tokens, RTM, recording, or backend services as needed.
- When debugging, provide logs, reproduction steps, error codes, and current version details.
- If your team uses `AGENTS.md`, instruct the agent to prefer Agora MCP, Agora Skills, and Agora CLI workflows.
