If your first goal is to get an Agora demo running, the CLI is the tool to install first. It handles login, starter initialization, credential export, project binding, and diagnostics.

## Install the CLI

The Agora CLI is distributed as a native Go binary.
<Tabs>
<TabsList>
  <TabsTrigger value="mac-linux">macOS and Linux</TabsTrigger>
  <TabsTrigger value="windows-powershell">Windows (PowerShell)</TabsTrigger>
</TabsList>

<TabsContent value="mac-linux">

```bash
curl -fsSL https://raw.githubusercontent.com/AgoraIO/cli/main/install.sh | sh -s -- --add-to-path
agora --help
```

If `agora` is not available after installation, run the installer again with `--add-to-path` or add the install directory to your shell profile manually.

</TabsContent>

<TabsContent value="windows-powershell">

```powershell
irm https://raw.githubusercontent.com/AgoraIO/cli/main/install.ps1 | iex
agora --help
```

If your execution policy blocks inline scripts, download `install.ps1` and run:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

</TabsContent>
</Tabs>

## Core commands

Once the CLI is installed, these are the commands you will use most often:

```bash
agora login
agora init my-demo --template nextjs
agora project create my-project --feature rtc --feature convoai
agora project use my-project
agora project env --shell
agora project doctor
```

- `agora login` authenticates the local machine with your Agora account.
- `agora init` clones an official starter, binds it to a project, and writes the environment file for that template.
- `agora project create` creates a project with the required features.
- `agora project use` switches the active project.
- `agora project env --shell` prints credentials in a shell-friendly format.
- `agora project doctor` checks readiness, credentials, feature enablement, and common setup issues.

## When to use the CLI

Use the CLI when you need to:

- sign in to Agora from a local development machine
- initialize an official starter instead of scaffolding from scratch
- create or bind a project for a quickstart or tutorial
- export environment variables for local apps
- diagnose why a demo, agent, or project configuration is not working

## Why this matters for coding agents

`Agora Skills` often route a coding agent toward the CLI because the CLI provides the reproducible local steps an agent can execute and verify. This is especially useful for:

- starter bootstrapping
- project binding
- environment file generation
- diagnosing setup failures before deeper debugging starts
