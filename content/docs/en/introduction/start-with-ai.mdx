Use your coding assistant to build one of the following:

- **A Voice Agent app**, where a user speaks with an AI agent. The starter runs a browser client and a backend in Python, TypeScript, or Go. The client captures speech and plays the response, and the backend provides credentials and controls the agent session. Agora runs the Conversational AI Engine that connects the conversation to your configured models.
- **A voice call**, where two people hear each other. The RTC quickstart builds clients that exchange audio through Agora, and your assistant follows the guide for your target platform.

## Prepare your assistant

Your assistant must be able to edit files in your project and run terminal commands to install the Agora CLI, scaffold a starter, and run it locally. You can use Claude Code, Cursor, Windsurf, GitHub Copilot, or similar. If you already have the Agora CLI and Agora Skills, continue to [Give your assistant a goal](#give-your-assistant-a-goal).

1. **Install the Agora CLI**

    The CLI signs you in, prepares supported starters, and checks project configuration. Run the command for your operating system:

    ```bash tab="macOS and Linux" tabGroup="ai-install-os"
    curl -fsSL https://dl.agora.io/cli/install.sh | sh
    agora --help
    ```

    ```powershell tab="Windows PowerShell" tabGroup="ai-install-os"
    irm https://dl.agora.io/cli/install.ps1 | iex
    agora --help
    ```

    Confirm that `agora --help` works in the terminal your assistant uses. See [Agora CLI](/en/introduction/agora-cli) for installation alternatives and troubleshooting.

2. **Add Agora Skills**

    Agora Skills gives the assistant Agora-specific guidance for choosing and implementing a product path.

    ```bash
    npx skills add AgoraIO/skills
    ```

    Follow the installer for your coding tool. See [Agora Skills](/en/introduction/agora-skills) for manual setup.

    For documentation lookup, check whether Agora MCP is already connected in your coding tool. If it is not, follow [Agora MCP](/en/introduction/agora-mcp) to connect it. Agora Skills provides workflow guidance. Agora MCP lets the assistant search documentation.

## Give your assistant a goal

Tell your assistant what to build, which platform and backend language to use, and what a working result looks like. These examples both use a Web client, so adapt one to your own platform:

```text tab="Voice Agent web app" tabGroup="build-goal"
Use Agora Skills to run the official Python Voice Agent starter locally.
I want a browser client with a Python backend.
The Agora CLI and Skills are already installed. Use the CLI to sign in
and configure the project, then follow the official starter's run instructions.
Help me start a conversation, hear the agent respond, and see the transcript.
Explain which parts run locally and which are Agora services.
```

```text tab="Web voice call" tabGroup="build-goal"
Use Agora Skills and the official Web RTC voice-only quickstart to build a call.
Help me configure the project and run two clients in the same channel.
Use distinct user IDs and verify that both clients can send and hear audio.
Follow the Web quickstart's setup commands and explain how the call works.
```

The [Voice Agent quickstart](/en/ai/get-started/quickstart#sign-in-scaffold-and-run) provides the commands to scaffold and run the starter. The [Voice-only quickstart](/en/realtime-media/rtc/voice-quickstart) provides the RTC implementation for Web, Android, iOS, Flutter, Unity, and other platforms. Follow the selected guide for dependencies, credentials, and run commands.

## Run and check the interaction

Work through the selected guide with your assistant:

1. **Configure the project**

    Complete sign-in and credential setup. Ask your assistant to show you where it stored your project credentials and to explain each value. For definitions of App ID, App Certificate, and token, see [Platform concepts](/en/introduction/core-concepts#project-credentials-and-authentication).

2. **Run the application**

    Install dependencies and start the client and any backend required by that guide.

3. **Test the interaction**

    A running development server doesn't confirm that the interaction works. Test the conversation itself.

    | What you built | A successful first interaction |
    | --- | --- |
    | Voice Agent starter | Start a conversation, speak, hear a response, and see the transcript. End the conversation in the app when you are finished. |
    | RTC voice application | Join the same project and channel from two clients with distinct user IDs, speak, and hear the other participant. Leave the call from both clients when you are finished. |

If project setup or agent startup fails, ask your assistant to inspect the error and run the CLI diagnostic:

```bash
agora project doctor
```

For client errors, inspect the application logs and follow the product guide. Continue from the failing step.

## Understand your implementation and make changes

For a Voice Agent, read [What just happened](/en/ai/get-started/quickstart#what-just-happened) to connect the running app to its client, backend, and model roles. Then [manage agent sessions](/en/ai/build/start-stop-agent) or [configure the models](/en/ai/build/custom-model-integration/managed-mode).

For RTC, ask the assistant to show where your client joins, publishes, subscribes, and leaves. Keep using the guide for your selected platform. Before using the app in production, follow the [authentication workflow](/en/realtime-media/rtc/build/authenticate-users/authentication-workflow).

For either path, choose one change and verify it in the same application before adding more features. [Recipes](/en/api-reference/recipes) provides additional examples when you need a new capability.
