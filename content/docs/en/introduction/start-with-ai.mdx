Use your coding assistant to build a real-time call or a Voice Agent with Agora's official guidance. Choose a concrete result: two people hearing each other, or a user speaking with an AI agent.

For a **Voice Agent web app**, the starter runs a browser client and a backend in Python, TypeScript, or Go. The client captures speech and plays the response; the backend provides credentials and controls the agent session. Agora runs the Conversational AI Engine that connects the conversation to your configured models.

For a **voice call**, the RTC quickstart builds clients that exchange audio through Agora. The assistant follows the guide for your target platform.

## Prepare your assistant

Use a coding assistant that can work with your local project and terminal. If the CLI and Skills are already installed, continue to [Give your assistant a goal](#give-your-assistant-a-goal).

<Steps>
<Step>

### Install the Agora CLI

The CLI signs you in, prepares supported starters, and checks project configuration. Run the command for your operating system:

```bash tab="macOS and Linux" tabGroup="install-os"
curl -fsSL https://dl.agora.io/cli/install.sh | sh
agora --help
```

```powershell tab="Windows PowerShell" tabGroup="install-os"
irm https://dl.agora.io/cli/install.ps1 | iex
agora --help
```

Confirm that `agora --help` works in the terminal your assistant uses. See [Agora CLI](/en/introduction/agora-cli) for installation alternatives and troubleshooting.

</Step>
<Step>

### Add Agora Skills

Skills gives the assistant Agora-specific guidance for choosing and implementing a product path.

```bash
npx skills add AgoraIO/skills
```

Follow the installer for your coding tool. See [Agora Skills](/en/introduction/agora-skills) for manual setup.

For documentation lookup, check whether Agora MCP is already connected in your coding tool. If it is not, follow [Agora MCP](/en/introduction/agora-mcp) to connect it. Skills provides workflow guidance; MCP lets the assistant search documentation.

</Step>
</Steps>

## Give your assistant a goal

Include what you want to build, the client platform, and a backend language if the path needs one. Choose one example and adapt it to your project:

```text tab="Voice Agent web app" tabGroup="build-goal"
Use Agora Skills to run the official Python Voice Agent starter locally.
I want a browser client with a Python backend.
The Agora CLI and Skills are already installed. Use the CLI to sign in
and configure the project, then follow the official starter's run instructions.
Help me start a conversation, hear the agent respond, and see the transcript.
Explain which parts run locally and which are Agora services.
```

```text tab="Web voice call" tabGroup="build-goal"
Use Agora Skills and the official Web RTC voice-only quickstart to build a call.
Help me configure the project and run two clients in the same channel.
Use distinct user IDs and verify that both clients can send and hear audio.
Follow the Web quickstart's setup commands and explain how the call works.
```

The [Voice Agent apps quickstart](/en/ai/get-started/quickstart#sign-in-scaffold-and-run) provides the starter commands after tool preparation. The [Web voice-only quickstart](/en/realtime-media/rtc/voice-quickstart/web) provides the RTC implementation. Follow the selected guide for dependencies, credentials, and run commands.

## Run and check the interaction

Work through the selected guide with your assistant:

1. **Configure the project.** Complete sign-in and credential setup. Ask the assistant to explain the local environment files it creates or changes. Use [Platform concepts](/en/introduction/core-concepts) if an unfamiliar project or credential term blocks you.
2. **Run the application.** Install dependencies and start the client and any backend required by that guide.
3. **Test the interaction.** Check the result below before customizing the code.

| What you built | A successful first interaction |
| --- | --- |
| Voice Agent starter | Start a conversation, speak, hear a response, and see the transcript. End the conversation using the app's control. |
| RTC voice application | Join the same project and channel from two clients with distinct user IDs. Each client can send audio and hear the other participant. Both can leave the call. |

A development server starting successfully is only part of the setup. Verify the conversation itself.

If project setup or agent startup fails, ask your assistant to inspect the error and use the starter's CLI diagnostic:

```bash
agora project doctor
```

For client errors, inspect the application logs and follow the product guide. Continue from the failing step.

## Understand the result and make a change

For a Voice Agent, read [What just happened](/en/ai/get-started/quickstart#what-just-happened) to connect the running app to its client, backend, and model roles. Then [manage agent sessions](/en/ai/build/start-stop-agent) or [configure the models](/en/ai/build/custom-model-integration/managed-mode).

For RTC, ask the assistant to show where your client joins, publishes, subscribes, and leaves. Keep using the guide for your selected platform. Before using the app in production, follow the [authentication workflow](/en/realtime-media/rtc/build/authenticate-users/authentication-workflow).

For either path, choose one change and verify it in the same application before adding more features. [Recipes](/en/api-reference/recipes) provides additional examples when you need a new capability.
