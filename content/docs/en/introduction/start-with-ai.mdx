Start with the Agora CLI so you can run an official starter first. Then add Agora MCP when you want your assistant to check the latest docs, and add Agora Skills when you want help choosing the right Agora workflow, starter, and setup path.

If you are not sure what to install first, follow the steps on this page in order. The goal is simple: get a working baseline first, then make your assistant more useful.

## Quick start

### 1. Install the Agora CLI
<Tabs>
<TabsList>
  <TabsTrigger value="mac-linux">macOS and Linux</TabsTrigger>
  <TabsTrigger value="windows-powershell">Windows (PowerShell)</TabsTrigger>
</TabsList>

<TabsContent value="mac-linux">

```bash
curl -fsSL https://raw.githubusercontent.com/AgoraIO/cli/main/install.sh | sh -s -- --add-to-path
agora --help
```

</TabsContent>

<TabsContent value="windows-powershell">

```powershell
irm https://raw.githubusercontent.com/AgoraIO/cli/main/install.ps1 | iex
agora --help
```

If your execution policy blocks inline scripts, download `install.ps1` and run:

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

</TabsContent>
</Tabs>

### 2. Add the tools your assistant needs

At this point, decide how much guidance you want your assistant to have:

- Install [Agora MCP](/en/introduction/agora-mcp) if you want your assistant to check the latest official docs before it writes or changes code.
<Tabs>
<TabsList>
  <TabsTrigger value="codex">Codex</TabsTrigger>
  <TabsTrigger value="claude-code">Claude Code</TabsTrigger>
  <TabsTrigger value="cursor">Cursor</TabsTrigger>
</TabsList>

<TabsContent value="codex">

```bash
codex mcp add --url https://mcp.agora.io agora-docs
```

</TabsContent>

<TabsContent value="claude-code">

```bash
claude mcp add --transport http agora-docs https://mcp.agora.io
```

</TabsContent>

<TabsContent value="cursor">

Add this to your MCP configuration:

```json
{
  "mcpServers": {
    "agora-docs": {
      "url": "https://mcp.agora.io"
    }
  }
}
```

</TabsContent>
</Tabs>
- Install [Agora Skills](/en/introduction/agora-skills) if you also want product-aware routing, starter selection, and Agora-specific workflow guidance.
<Tabs>
<TabsList>
  <TabsTrigger value="skills-cli">Skills CLI</TabsTrigger>
  <TabsTrigger value="manual">Manual installation</TabsTrigger>
</TabsList>

<TabsContent value="skills-cli">

```bash
npx skills add github:AgoraIO/skills
```

</TabsContent>

<TabsContent value="manual">

Clone the repository and point your coding assistant to the Agora skill files:

```bash
git clone https://github.com/AgoraIO/skills.git ~/agora-skills
```

Use `skills/agora/` as the directory entry point, or load `SKILL.md` directly if your tool expects a single root file.

</TabsContent>
</Tabs>
If you want both fresh docs and workflow guidance, install both.

### 3. Log in and run an official starter
<Tabs>
<TabsList>
  <TabsTrigger value="typescript">TypeScript</TabsTrigger>
  <TabsTrigger value="python">Python</TabsTrigger>
  <TabsTrigger value="go">Go</TabsTrigger>
</TabsList>

<TabsContent value="typescript">

```bash
agora login
agora init my-nextjs-demo --template nextjs
cd my-nextjs-demo
pnpm install
pnpm dev
```

</TabsContent>

<TabsContent value="python">

```bash
agora login
agora init my-python-demo --template python
cd my-python-demo
bun install
bun run dev
```

</TabsContent>

<TabsContent value="go">

```bash
agora login
agora init my-go-demo --template go
cd my-go-demo
make setup
make dev
```

</TabsContent>
</Tabs>

This clones the official starter, binds it to your Agora project, and writes the environment you need locally.

### 4. Open the app

Open `http://localhost:3000` and start a conversation.

Once the app opens, run the quick smoke test below before you customize anything.

## Verify it worked

Use a quick smoke test instead of reading deeper docs immediately. If these signals line up, you have a working baseline and can move on to customization.

| Check | What success looks like |
| --- | --- |
| App startup | The local app opens without missing credentials or setup errors. |
| First interaction | You can start a conversation from the UI without manual patching. |
| Agent join | The agent joins successfully after startup. |
| Output path | Speech or transcript output appears as expected in the app. |

At that point, you have a working baseline. Only then should you start customizing prompts, runtime behavior, or architecture. This is also the right moment to make your assistant more specific: name the product, platform, language, and goal instead of asking for a generic Agora integration.

## Common failures

Most early failures are not architectural problems. They are install, path, or project-binding problems. Check the symptom first, then apply the smallest fix.

| Symptom | Check first | What to do |
| --- | --- | --- |
| `agora` command not found | Whether the installer added the binary to your shell path | Rerun the installer with `--add-to-path`, or add the install directory to your shell profile manually. |
| Starter initializes but does not run | Whether the runtime dependencies installed successfully for that starter | Reinstall dependencies for the selected starter runtime and rerun the local dev command. |
| Agent does not join or transcripts do not appear | Whether the project is enabled and credentials are valid | Run `agora project doctor`. |
| Project setup looks wrong | Whether the active project and env values match what you expect | Run `agora project env --shell` and inspect the exported credentials. |

When debugging, keep your assistant grounded in evidence. Give it logs, reproduction steps, and version details so it can reason from concrete failures instead of guessing. Keep MCP enabled whenever it is looking up APIs, auth flows, parameters, or platform differences, and use Skills when it needs help choosing the right Agora workflow instead of only reading docs.

## Choose your next tool

Now that you have the overall setup path, pick the next page based on what you want your assistant to do:

- Open [Agora CLI](/en/introduction/agora-cli) if you want the shortest path to running and troubleshooting an official starter.
- Open [Agora MCP](/en/introduction/agora-mcp) if you want your assistant to check the latest Agora docs before it writes or changes code.
- Open [Agora Skills](/en/introduction/agora-skills) if you want your assistant to choose the right Agora workflow, starter, and setup path.
