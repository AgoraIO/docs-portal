Realtime Communication (RTC) supports **human-to-human** interaction through live audio and video. Your client application captures and plays media using the RTC SDK. Agora carries it between participants. You control the user experience and which media each participant sends and receives.

## How a real-time session works

A **channel** groups participants who can exchange media. It is a logical group, not a server you deploy.

Within a channel, **publish** to send local audio or video, and **subscribe** to receive another participant's media. In a two-way call, both clients do both. In a live stream, hosts publish and audiences only subscribe.

![Two RTC clients join the same channel. Client A publishes audio or video that Client B subscribes to; Client B publishes media that Client A subscribes to.](/images/developer-journey/rtc-media-exchange.svg)

1. **Prepare the client.** Initialize the SDK with your App ID and obtain credentials from your backend.
2. **Join a channel.** Participants in the same project use the same channel name and distinct user IDs.
3. **Publish and subscribe.** Send the local media and receive the remote media required by your application.
4. **Leave the session.** Disconnect the client when the user leaves.

Your backend keeps secret credentials and provides client authentication. See Realtime Communication [Core concepts](/en/realtime-media/rtc/core-concepts) when you need details about channels, streams, roles, or connections.
