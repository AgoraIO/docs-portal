In real-time interactive scenarios such as live broadcasts, conferences, and large-class lectures, dynamically adjusting video resolution improves the user experience across terminals and network conditions.

Common use cases include:

- **Live streaming**: Push high resolution and fall back to lower resolutions under poor network conditions.
- **Video conferencing**: Use high resolution for the main speaker and lower resolution for thumbnails.
- **Multi-terminal adaptation**: Deliver different resolutions to devices with different performance capabilities.
- **Multi-screen adaptation**: Stream different resolutions for large, medium, and small screens.

This guide shows you how to use Video SDK to implement multi-bitrate video streaming in Video Calling.

## Understand the tech

Starting with v4.6.0, Video SDK introduces simulcasting. It enables you to send up to four simultaneous streams of different configurations from the same video source: one source stream and up to three additional configurations. Subscribers can choose different stream levels based on rendering window size or business logic, balancing image quality, performance, bandwidth, and network conditions.

Compared to dual-stream video, simulcasting supports more stream configurations and smoother switching. If you already use dual-stream video, see [Simulcasting vs. Dual-stream video](#simulcasting-vs-dual-stream-video).

:::info[Additional information about simulcasting]
- Each client can publish up to four simulcast configurations by default.
- Simulcasting is currently available only on native platforms. It is not supported on the Web platform.
- Cloud recording supports only the large or small stream when simulcasting is enabled.
:::

## Publish multi-bitrate video streams

To enable and implement this feature, contact [Agora support](mailto:support@agora.io).

<PlatformStructured platform="android">
Before joining a channel, call `setSimulcastConfig` and configure the `SimulcastConfig` parameters.

```java
public abstract int setSimulcastConfig(SimulcastConfig simulcastConfig);
```

### Sample code

```java
private SimulcastConfig simulcastConfig = new SimulcastConfig();

int layer1 = SimulcastConfig.StreamLayerIndex.STREAM_LAYER_1.getValue();
simulcastConfig.configs[layer1].dimensions.width = 1280;
simulcastConfig.configs[layer1].dimensions.height = 720;
simulcastConfig.configs[layer1].framerate = 30;
simulcastConfig.configs[layer1].enable = true;

engine.setSimulcastConfig(simulcastConfig);
```

### Subscribe to a stream

```java
engine.setRemoteVideoStreamType(uid, Constants.VideoStreamType.VIDEO_STREAM_LAYER_1);
```
</PlatformStructured>

<PlatformStructured platform="ios">
Before joining a channel, call `setSimulcastConfig` and configure `AgoraSimulcastConfig`.

```objc
- (int)setSimulcastConfig:(AgoraSimulcastConfig* _Nonnull)simulcastConfig;
```

### Sample code


### Subscribe to a stream

```swift
let ret = agoraKit.setRemoteVideoStream(uid, type: .layer1)
```

## Reference

### Simulcasting vs. Dual-stream video

Simulcasting and dual-stream video are mutually exclusive. The API you set later overrides the earlier one. Choose the solution that fits your business needs and disable the other.

Compared with dual-stream video, simulcasting offers:

- More subscribed stream layers
- Smoother switching between bitrate levels
- Better flexibility for different business scenarios

To better balance simulcasting performance and network consumption, Agora applies the following strategies:

- When the sender device is performance-limited, upstream configurations are automatically disabled, and subscribers adapt to the remaining streams.
- When the uplink bandwidth is limited, additional configurations are disabled first. Then, the previous dual-stream rate control strategy is applied to ensure smooth publishing and subscription.

In terms of functionality, the differences between simulcasting and dual-stream video are summarized in the following table. Agora will continue to close the feature gap in future releases.

| Feature | Simulcasting | Dual-stream video |
|---------|:------------:|:-----------------:|
| Supports multi-channel scenarios | Yes | Yes |
| Small stream automatically adapts video attributes | No | Yes |
| Publisher sends video streams based on subscriber's chosen configuration | Yes. Contact technical support to enable. | Yes |
| When the sender is performance-limited, video streams other than the source stream can be disabled | Yes | No |
| When the downlink network is limited, the upstream small stream can be enabled automatically | No | Yes |
