## v2.9

该版本于 2026 年 7 月 1 日发布。

### 升级必看

#### 开场白播放期间用户输入延后处理

该版本调整了 [POST 创建对话式智能体](../convoai/operations/start-agent) 接口中不可打断开场白场景下的用户输入处理行为。自该版本起，当 `llm.greeting_configs.interruptable = false` 时，系统会在开场白播放期间静默接收用户 ASR 结果；待开场白播放结束后，再将期间收集到的多段 ASR 文本拼接成单轮 user 消息，统一送入大模型进行一次推理和回复。

### 新增特性

#### 手动控制用户说话开始和结束

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent) 接口的 `turn_detection.config.start_of_speech.mode` 和 `turn_detection.config.end_of_speech.mode` 新增 `manual` 取值。你可以根据业务场景分别将用户开始说话或结束说话的检测方式设为手动。对于设置为 `manual` 的一侧，服务端不再自动检测，而是由客户端通过 RTM 信令显式提交对应的回合边界。

该能力适用于长回答、对讲机、面试、答题等对用户回合边界控制要求较高的场景，可减少用户停顿、思考或语气词被误判为结束说话的情况。详情见[手动控制说话开始和结束](/zh-CN/ai/user-guides/manual-turn-control-through-rtm)。

#### 获取智能体状态

该版本新增通过 RTM Message 获取智能体状态的能力。开启 RTM 服务并将 `data_channel` 设置为 `rtm` 后，你可以直接监听 `state.listening`、`state.thinking` 和 `state.speaking` 等状态事件，以消息事件的方式感知智能体状态变化。详见[获取智能体状态](/zh-CN/ai/best-practice/get-agent-state-through-rtm-message)。

#### 开场白支持录音 URL 导入

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent) 接口新增录音开场白能力。你可以通过 `llm.greeting_audio_url` 配置公网可访问的录音文件 URL，让智能体在用户加入频道后优先播放录音作为开场白。

当前支持 `mp3`、`wav` 和 `pcm` 三种格式。当录音下载失败、超时、格式不支持或解码失败时，系统会自动回退到 `greeting_message` 的 TTS 路径，确保用户仍能听到完整开场白。

#### 支持 Spatius 数字人

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent) 接口新增对 Spatius 数字人供应商的支持。你可以将 `avatar.vendor` 设为 `spatius`，并通过 `avatar.params` 配置 `spatius_api_key`、`spatius_app_id`、`spatius_avatar_id`、`agora_uid` 等参数，在对话式智能体中接入 Spatius 数字人能力。

### API 变更

#### 新增

- [POST 创建对话式智能体](../convoai/operations/start-agent)
  - `turn_detection.config.start_of_speech.mode` 新增 `manual` 取值
  - `turn_detection.config.end_of_speech.mode` 新增 `manual` 取值
  - `avatar.vendor` 新增 `spatius` 取值
  - `avatar.params` 新增 Spatius 数字人配置参数
- [POST 创建对话式智能体](../convoai/operations/start-agent) 新增 `llm.greeting_audio_url`
- [POST 创建对话式智能体](../convoai/operations/start-agent) 新增 `llm.greeting_configs.audio_download_timeout_ms`
- [POST 创建对话式智能体](../convoai/operations/start-agent) 新增 `llm.greeting_configs.audio_pcm_sample_rate`

## v2.8

该版本于 2026 年 6 月 9 日发布。

### 升级必看

#### `properties.idle_timeout` 行为变更

该版本调整了 [POST 创建对话式智能体](../convoai/operations/start-agent)接口中 `properties.idle_timeout` 的行为定义。自该版本起，将 `properties.idle_timeout` 设为 `0` 仅表示不因“频道空闲超时”退出，并不表示智能体可以无限期运行。且无论该字段取值为何，单次任务的最长运行时间均为 72 小时，达到上限后智能体会自动退出。

此外，[`102 agent left` 事件](/zh-CN/ai/webhook/ncs-events#102-agent-left)补充了任务达到最长运行时长上限时的退出原因，返回 `Task lifetime limit exceeded`。

这项变更会影响依赖 `idle_timeout = 0` 实现长时间运行的集成逻辑。如果你的业务此前将 `0` 视为“仅在手动退出时停止”，需要按新的运行时限制调整任务调度和生命周期管理逻辑。

### 新增特性

#### 配置是否留存会话数据

自该版本起，为保障服务运行、智能体迭代调优与故障排查，默认在最短必要周期内临时留存会话交互文本、音频。同时，考虑到部分场景存在安全与合规要求，该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `parameters.opt_out` 字段，支持客户按需选择关闭当前会话数据留存。

#### RTC Token 即将过期预警

该版本为消息通知服务新增 `104 agent expire` 事件。当智能体使用的 RTC Token 即将过期时，平台会主动向你的业务服务器发送预警通知，帮助你提前感知 Token 生命周期状态。

收到该事件后，你可以立即调用 [POST 更新智能体配置](../convoai/operations/agent-update) 接口并传入新的 `properties.token`，完成 Token 刷新，避免因 Token 过期影响智能体继续在频道内提供服务。该事件仅用于预警，智能体在收到预警时不会退出频道，也不会中断当前会话。详见[事件类型](/zh-CN/ai/webhook/ncs-events#104-agent-expire)。

### 改进

#### 智能体短期记忆新增语音时间相关字段

该版本为消息通知服务的 `103 agent history` 事件以及 [GET 获取智能体短期记忆](../convoai/operations/get-history)接口新增 `speech_start_ms`、`speech_end_ms` 和 `speech_algorithmic_delay` 字段。上述字段仅在 `llm.vendor = custom` 时返回，用于定位用户语音输入和智能体 TTS 播报在音频中的位置；其中，`speech_algorithmic_delay` 可进一步辅助对齐云录制原始音频时间戳。详见[事件类型](/zh-CN/ai/webhook/ncs-events#103-agent-history)和[获取智能体短期记忆](../convoai/operations/get-history)。

### API 变更

#### 新增

- [POST 创建对话式智能体](../convoai/operations/start-agent)新增 `parameters.opt_out`
- [`103 agent history` 事件](/zh-CN/ai/webhook/ncs-events#103-agent-history)新增 `contents[].speech_start_ms`、`contents[].speech_end_ms` 和 `contents[].speech_algorithmic_delay`
- [GET 获取智能体短期记忆](../convoai/operations/get-history)响应新增 `contents[].speech_start_ms`、`contents[].speech_end_ms` 和 `contents[].speech_algorithmic_delay`
- [消息通知事件](/zh-CN/ai/webhook/ncs-events#104-agent-expire)新增事件 `104 agent expire`

#### 变更

- [POST 创建对话式智能体](../convoai/operations/start-agent) 的 `properties.idle_timeout`
    - 补充取值范围 `[0, 259200]`，其中 259200 秒即 72 小时
    - `0` 仅表示不因频道空闲超时退出
    - 无论 `idle_timeout` 取值为何，单次任务最长运行时间均为 72 小时

## v2.7

该版本于 2026 年 5 月 20 日发布。

### 升级必看

#### 响应状态码优化

该版本调整了 RESTful API 的响应状态码和错误原因（`reason`）定义，新增了 `401`、`429` 和 `500` 等状态码，并新增 `ServiceNotEnabled`、`AccountSuspended` 和 `ResourceAllocationFailed` 等 `reason`，同时将原 `InvalidRequest` 细分为 `InvalidRequestBody`、`MissingRequiredField` 和 `InvalidFieldValue`。详见[响应状态码](/zh-CN/ai/api/response-code)。

这项变更会影响依赖 `reason` 做错误处理的集成逻辑。若你的业务中存在基于原 `InvalidRequest` 的分支判断、重试策略或告警规则，需要按新返回值更新兼容逻辑。

#### 查询对话轮次信息接口改为分页返回

自该版本起，[GET 查询对话轮次信息](../convoai/operations/get-turns)接口不再返回全部对话轮次数据，改为分页返回。默认请求第 1 页，且默认每页返回 50 个对话轮次的数据。

这项变更会影响查询对话轮次数超过 50 的单个会话。你需要适配响应 Body 新增的分页相关字段（`total_turn_count` 和 `pagination`），根据分页信息补全后续页面的数据，详见[查询对话轮次信息](/doc/convoai/restful/convoai/operations/get-turns)。

此外，该版本新增 `112 turns finished` 消息通知事件，用于在会话结束后按批次回调对话轮次数据，便于你进行更灵活的数据分析与处理。详见[事件类型](/zh-CN/ai/webhook/ncs-events#116)。

#### 发送自定义指令接口行为与动作模型优化

该版本为 [POST 发送自定义指令](../convoai/operations/agent-think)接口的 `on_listening_action` 参数新增 `interrupt` 动作，用于在智能体处于倾听状态时立即响应发送自定义指令的内容，而用户语音识别出的文本会在后续单独响应。

这项变更会影响在智能体处于倾听状态时发送自定义指令的默认行为。上一版本中，在智能体处于倾听状态时发送自定义指令，默认会按 `inject` 方式处理；自该版本起，该场景改为默认按新增的 `interrupt` 方式处理。

### 新增特性

#### 配置问候语是否可被打断

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `llm.greeting_configs.interruptable` 字段，用于控制智能体问候语播报期间是否允许被用户打断。

### API 变更

#### 新增

- [POST 创建对话式智能体](../convoai/operations/start-agent)新增 `llm.greeting_configs.interruptable`
- [GET 查询对话轮次信息](../convoai/operations/get-turns)
    - 查询参数新增 `page_index` 和 `page_size` 字段
    - 响应 Body 新增 `agent_id`、`name`、`channel`、`total_turn_count` 和 `pagination` 字段
- [POST 发送自定义指令](../convoai/operations/agent-think) 的 `on_listening_action` 新增 `interrupt`

## v2.6

该版本于 2026 年 4 月 22 日发布。

### 升级必看

#### 对话检测与打断能力架构重构

该版本从原有 `turn_detection` 字段剥离了**打断决策**能力，专注于**轮次检测**；同时全新新增同级配置模块 `interruption`，统一管理全局打断策略。

**`turn_detection` 能力精简**

原 `turn_detection` 字段承载语音检测、语义判定、打断开关、关键词打断等逻辑，2.6 版本仅保留纯对话轮次检测能力，专注负责用户开始说话（SOS）、结束说话（EOS）的 VAD 语音检测与语义识别，只输出语音事件信号，不再承载任何业务层打断控制逻辑。

**新增 `interruption` 全局打断模块**

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `properties.interruption` 字段，用于统一配置智能体被用户打断的行为策略。该字段将原有内嵌在 `turn_detection` 中的打断开关与执行能力统一抽离迁移至该模块；支持全局一键开关打断功能，提供人声触发打断、关键词打断两种模式，同时可配置关闭打断后的后置策略（追加录入 / 直接忽略），适配更多业务场景的防误打断、免打扰交互诉求。

**配置迁移说明**

原 V2.5 版本中 `turn_detection.config.start_of_speech` 下的 `keywords` 和 `disabled` 打断模式及对应配置字段废弃，需迁移至 `interruption` 同级配置中完成适配升级。

### 新增特性

#### 配置智能体问候语播报延迟时间

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `llm.greeting_configs.delay_ms` 字段，用于配置智能体问候语的播报延迟时间。配置后，智能体问候语会在用户加入频道后等待指定时间再播报。该功能可用于确保用户正常听到问候语。

#### 自定义 LLM 请求头信息

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `llm.headers` 字段，用于请求 LLM 时附带自定义请求 Header。如果你接入的 LLM 服务要求在请求 Header 中携带特定信息，如租户标识、业务自定义字段等业务相关信息，你可以通过该字段透传这些信息。

#### 新增智能体状态回调

对话式 AI 引擎客户端组件新增三个用于分别监听智能体的倾听 (Listening)、思考 (Thinking) 和说话 (Speaking) 状态变化的细粒度状态回调。这些回调是对原有智能体状态变化回调 (`onAgentStateChanged`) 的补充，便于你更精细地驱动界面状态和业务逻辑。

#### 发送自定义指令

该版本新增 [POST 发送自定义指令](../convoai/operations/agent-think)接口，用于将一段文本作为用户输入注入现有对话链路，并由对话式 AI 引擎继续按照普通用户输入的处理逻辑进行推理和响应。该能力适用于以下场景：

- 隐式指令注入：在不通过 ASR 模块处理语音输入的情况下静默注入业务提示或前置设定。
- 客户端事件触发：将按钮点击、页面切换等客户端事件转换为文本注入，让智能体结合当前对话状态做出响应。
- 语音与文本协同：在用户说话的同时补充文本信息，由对话式 AI 引擎合并输入后，LLM 统一处理。

该接口支持通过 `on_listening_action`、`on_thinking_action` 和 `on_speaking_action` 分别配置智能体处于不同状态时的处理方式：

- `inject`：注入当前轮次，不打断当前轮次。
- `interrupt`：打断当前状态，并发起新一轮对话。
- `ignore`：忽略本次请求。

### 改进

该版本为消息通知服务所有事件回调和 [GET 查询智能体状态](../convoai/operations/query-agent-status)接口响应体新增 `name` 字段，用于返回智能体名称。你可以使用该字段定位和关联业务实例。

## v2.5

该版本于 2026 年 3 月 30 日发布。

### 新增特性

#### 优雅打断支持判断对话暂停意图

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口的 `turn_detection.config.end_of_speech.semantic_config` 字段新增 `pause_state_enabled` 字段，用于配置智能体是否识别用户的暂停意图。开启后（默认开启），当用户说"等一下"、"稍等"等暂停词时，智能体将判断为暂停意图，等待用户后续输入而非立即响应。

#### 实时更新 TTS 参数

接入[自定义大模型](/zh-CN/ai/user-guides/custom-llm)场景下，该版本新增支持在用户和智能体互动期间实时更新 TTS 参数，实现更沉浸的对话交互体验。该功能可应用于以下场景：

- 自定义大模型识别到用户要求智能体换一个声音。
- 自定义大模型识别到用户高兴的情绪时，实时提高 TTS 的音量、音调和语速等，使智能体的回应更符合用户的心情。

实现方式可参考[实时更新 TTS 参数](/zh-CN/ai/user-guides/custom-llm#实时更新-tts-参数)。

#### 查询对话轮次信息

该版本新增 [GET 查询对话轮次信息](../convoai/operations/get-turns)接口，用于在与智能体对话结束后，查询本次会话的对话轮次信息，包含每个对话轮次的开始信息、结束信息和性能指标。

:::info[信息]
目前仅支持查询 7 天内的会话。
:::

### API 变更

#### 新增

- [POST 创建对话式智能体](../convoai/operations/start-agent)的 `properties.turn_detection.config.end_of_speech.semantic_config` 字段新增 `pause_state_enabled` 字段
- [GET 查询对话轮次信息](../convoai/operations/get-turns)

## v2.4

该版本于 2026 年 2 月 2 日发布。

### 新增特性

#### 接入 MCP 服务器

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `llm.mcp_servers` 字段，用于接入 MCP (Model Context Protocol) 服务器。你可以在创建智能体时配置 MCP 服务器，并开启工具调用 (`advanced_features.enable_tools` 设为 `true`)，让智能体调用外部服务提供的工具 (tools)，实现更复杂的业务逻辑。

#### 垫词功能 (Beta)

该版本为 [POST 创建对话式智能体](../convoai/operations/start-agent)接口新增 `filler_words` 字段，用于配置垫词功能。垫词功能可在 LLM 响应等待时播报垫词，缓解用户等待焦虑，提升对话流畅度。

### 改进

#### turn_detection 层级优化

该版本对 [POST 创建对话式智能体](../convoai/operations/start-agent)接口的 `turn_detection` 字段进行了层级优化，采用 `mode` + `config` 的双字段配置方式，提供更灵活的对话轮次检测能力。

新的配置结构包括：

**基础配置**

- `mode`：对话轮次检测模式（当前支持 `default`）
- `config.speech_threshold`：语音识别灵敏度

**对话开始检测 (Start of Speech, SoS)**

`config.start_of_speech` 支持三种检测模式：

- **VAD 模式** (`vad`)：基于语音活动检测触发，支持配置打断阈值、前缀填充和忽略词列表
- **关键词模式 (Beta)** (`keywords`)：基于关键词触发，智能体听到指定关键词后开始对话
- **禁用模式** (`disabled`)：禁用打断，支持追加或忽略策略

**对话结束检测 (End of Speech, EoS)**

`config.end_of_speech` 支持两种检测模式：

- **VAD 模式** (`vad`)：基于静音持续时间判定对话结束
- **语义模式** (`semantic`)：基于语义理解判定对话结束，支持配置最大等待时间

该版本进行了以下改进：

- 接入 Minimax TTS 时，新增支持透传 `emotion`、`latex_read`、`pronunciation_dict` 等字段，详见[示例代码](../convoai/operations/start-agent)。
- 和智能体对话期间，智能体的实时状态支持通过数据流回调至 RTC SDK。
- [POST 更新智能体配置](../convoai/operations/agent-update)接口新增 `llm.system_messages` 和 `llm.params` 字段，用于更新智能体调用大模型时携带的系统提示词和配置参数。

### API 变更

    - `llm.vendor`
    - `turn_detection.interrupt_mode`

- [POST 更新智能体配置](../convoai/operations/agent-update)新增：
    - `llm.system_messages`
    - `llm.params`

### 新增特性

#### 获取智能体短期记忆

用户和智能体之间的对话消息、智能体创建和停止的时间戳等会被存储在智能体的短期记忆中。该版本新增了以下两种方式获取智能体的短期记忆：

- 调用 [GET 获取智能体短期记忆](../convoai/operations/get-history)接口获取指定运行中智能体的短期记忆。
- 通过[声网消息通知服务](/zh-CN/ai/webhook/enable-ncs)订阅[智能体短期记忆事件](/zh-CN/ai/webhook/ncs-events#103-agent-history)，当智能体停止时，声网将通过 Webhook 回调的方式自动发送智能体的短期记忆到你的业务服务器。

#### 支持智谱 AI 大模型

自该版本起，对话式 AI 引擎支持智谱 AI 大模型，你可以在调用 [POST 创建对话式智能体](../convoai/operations/start-agent)接口时，将 `llm.url` 设置为智谱 AI 大模型的 API 地址来接入智谱 AI 大模型。

### 改进

#### 自定义播报信息优先级

该版本升级了 [POST 播报自定义信息](../convoai/operations/agent-speak)接口，新增了两种与播报行为打断逻辑相关的配置：

- `priority`：配置播报行为的优先级。支持配置打断并播报（高）、追加播报（中）和空闲时播报（低）三种优先级。
- `interruptable`：配置是否允许人声打断智能体播报。

#### 发送静默提示消息

[POST 创建对话式智能体](../convoai/operations/start-agent)新增 `silence_timeout` 和 `llm.silence_message` 参数，用于设置智能体最大静默时间和静默提示消息。智能体创建成功，且用户加入频道后，智能体不处于倾听、思考或说话状态的持续时间称为智能体静默时间，静默时间达到设定值后，智能体将播报中填写的静默提示消息。

### API 变更

#### 新增

- [GET 获取智能体短期记忆](../convoai/operations/get-history)

- [POST 播报自定义信息](../convoai/operations/agent-speak)新增 `priority` 和 `interruptable` 参数

### 核心功能

#### 实时语音对话

支持与 AI 进行自然流畅的实时语音对话，如同与真人交流，提供低延迟、极速响应的交互体验。

#### 端上降噪

SDK 会智能识别和消除背景噪音，即使在嘈杂的公共场所，都能够确保声音传输的清晰度，为用户提供高质量的对话体验。

#### 背景人声抑制

智能抑制背景人声，精准保留对话人清晰语音，确保在多人声环境中仍能实现清晰、专注的交互体验。

#### 优雅打断

支持用户随时打断 AI 并快速响应，实现自然过渡和流畅对话，避免机械式交互。

#### 智能传输

针对与 AI 智能体对话场景优化的传输算法，支持在弱网环境（如 80% 丢包率）下仍能稳定传输语音数据，确保对话的连续性和可靠性，适应多样化的复杂网络环境。

#### 灵活编排

支持全球主流的 LLM（大语言模型）、TTS（语音合成） 适配，快速实现灵活编排，满足不同场景和业务需求，提供高度定制化的 AI 智能体对话解决方案。

#### 实时字幕

支持用户与 AI 智能体的对话内容实时以文本输出并显示到终端界面上。

#### 多平台支持

支持 iOS、Android、Web、 小程序、以及各类嵌入式硬件等客户端，提供跨平台的一致性和无缝集成体验，满足不同场景的应用需求。
