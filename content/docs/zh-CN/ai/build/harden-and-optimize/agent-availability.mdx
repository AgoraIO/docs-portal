---
title: 保障智能体启动与运行
description: 在业务服务端处理智能体创建请求超时、同名冲突和通知丢失，并按用户重连时间设置空闲超时。
---

当业务服务端调用[创建对话式智能体](/zh-CN/api-reference/api-ref/conversational-ai/join)后没有收到响应，智能体可能已经加入频道。为每次业务会话分配唯一的智能体名称（`name`），同一次启动的所有重试都沿用这个名称、频道和 UID。收到成功响应后，将 `agent_id` 与业务会话一起保存，后续用它查询或停止智能体。

## 根据创建结果决定是否重试

| 创建结果 | 业务服务端的处理 |
| --- | --- |
| `200` | 保存 `agent_id`。响应中的 `status` 为 `RUNNING` 时，可确认智能体正在运行，无需等待通知再判定启动成功。 |
| `409`：智能体冲突 | 停止重试创建。根据服务返回的任务信息确认是否为本次会话的智能体，再查询该实例的状态。不要为了绕过冲突而更换名称，否则可能为同一次会话启动第二个智能体。 |
| `422`：访问超限 | 检查项目的并发用量。如果是短时占满配额，等待已有会话结束后再退避重试。若正常业务量持续触及配额，联系技术支持提升配额。 |
| `429`：请求频率超限 | 降低请求频率，退避后再试。 |
| `5xx` 或请求超时 | 对可能是临时故障的请求，用相同参数有限次退避重试。`503`、`504` 可直接采用此策略；`500` 持续出现或收到 `502` 时，按[响应状态码](/zh-CN/api-reference/conversational-ai/rest-api/api/response-code)联系技术支持。 |
| `400`、`401`、`403` | 根据响应中的 `reason` 和 `detail` 检查参数、凭证或服务权限；修正后再发起请求。 |

例如，可以依次等待 1 秒、3 秒、6 秒，最多重试三次。只要拿到目标实例的信息，就结束创建重试。如果达到次数上限仍无法确定结果，记录频道、智能体名称、请求时间和错误信息，转为查询和排查。

### 网络故障时切换域名

直接调用 RESTful API 时，如果 DNS 解析失败或连接超时，可以先在原域名重试一次；仍然失败，再切换到同一服务区域的备用域名。切换前后的请求共用上述重试次数和等待间隔。

以中国大陆为例，按[对话式 AI 引擎的区域与域名映射](/zh-CN/api-reference/conversational-ai/agent-go#区域与域名映射)，主区域前缀为 `api-cn-east-1`，备用前缀为 `api-cn-north-1`；域名后缀可用 `sd-rtn.com` 和 `agora.io`。例如，主机可从 `api-cn-east-1.sd-rtn.com` 切换到 `api-cn-north-1.agora.io`，保留原请求中从 `/cn/api/conversational-ai-agent` 开始的完整路径。切换域名不能解决配额、鉴权或任务冲突问题。

## 用通知和查询确认状态

开通[消息通知服务（NCS）](/zh-CN/ai/build/handle-runtime-events/webhooks)后，可监听[智能体加入和离开频道事件](/zh-CN/ai/reference/event-types)：`101` 表示加入，`102` 表示离开。通知可能延迟或未能送达。如果在业务允许的启动等待时间内没有收到加入通知，使用已保存的 `agent_id` 调用 [GET 查询智能体状态](/zh-CN/api-reference/api-ref/conversational-ai/query)，根据响应体的 `status` 处理：

- `RUNNING`：确认启动成功，结束启动阶段的查询。
- `STARTING`：启动仍在进行，退避后继续查询，直到进入运行或终止状态，或达到业务等待上限。
- `STOPPING`、`STOPPED` 或 `FAILED`：实例正在退出、已退出或执行失败。记录返回的 `message` 并排查原因。

如果创建响应丢失，手头没有 `agent_id`，可以按频道和启动时间范围[获取智能体列表](/zh-CN/api-reference/api-ref/conversational-ai/list)。列表默认只查运行中的实例；要找正在启动的实例，单独查询 `state=1`。用候选 `agent_id` 查询详情，并核对返回的 `name` 与本次会话一致，再关联该实例。

对状态准确性要求较高的业务，可在运行期间周期性查询，例如每 2 分钟一次，并根据并发会话数和接口限频调整间隔。查询遇到超时或 `5xx` 时，重试的是 **GET 查询**，不要据此重新创建智能体。确认实例已退出或执行失败后，停止轮询。

## 按用户重连时间设置空闲超时

创建智能体时，可以用 `properties.idle_timeout` 设置等待用户重连的时间，默认 30 秒。当 `remote_rtc_uids` 指定的用户全部离开 RTC 频道后，系统开始计时；超过该时长，智能体自动停止并退出频道。用户仍在频道里但没有说话，不会触发这个超时。

如果业务允许用户断线后继续原会话，可根据实际重连耗时留出余量。用户明确结束会话时，直接调用[停止对话式智能体](/zh-CN/api-reference/api-ref/conversational-ai/leave)，无需等空闲超时。`idle_timeout` 设为 `0` 会关闭空闲退出；无论如何设置，单次任务最长运行 72 小时。
