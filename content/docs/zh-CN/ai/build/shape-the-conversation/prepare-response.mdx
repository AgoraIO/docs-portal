---
title: 让智能体更快回复
---

为了缩短回复等待时间，系统可以在用户结束说话前提前请求大模型生成回复。系统支持以下两种触发方式：

- `asr_auto`：由支持自动触发能力的语音识别服务根据中间识别结果触发。
- `eager_eos`：由系统预测用户即将结束说话时触发。

用户结束说话后，系统会将候选文本与本轮最终转写文本归一化后比较。文本匹配时，系统复用提前请求；不匹配时，系统丢弃该请求的输出，根据最终转写重新生成回复。系统只比较文本：即使两次识别得到的情绪、性别等信息不同，也不会因此重新生成回复。

:::info[信息]

- 候选文本变化时，系统可能取消旧请求并发起新请求。未被采用的请求仍可能产生模型和音频生成费用；如果实际调用了 TTS，也可能产生 TTS 费用。不要假定取消请求就能免除这些费用。
- 引擎会等到收到最终转写并采用该回复后，才执行其中的工具调用。被取消的请求不会触发引擎执行工具。如果你的大模型服务会自行下单、扣款等，请在服务端防止提前或重复执行；引擎取消请求无法撤销这些操作。

:::

## 前提条件

- 已参考[使用 RESTful API 实现对话式 AI 引擎](/zh-CN/ai/get-started/quick-start)完成基本接入。

## 实现方式

### 使用 `asr_auto` 提前回复

在国内，`asr_auto` 仅支持 `vendor` 为 `bytedance_bigmodel` 的语音识别服务。系统会根据中间识别结果自动发起提前请求。使用此方式不要求将结束说话方式设为 `semantic`。

创建智能体时，在 `properties` 中加入以下配置：

```json
{
  "properties": {
    "parameters": {
      "eager_llm_response": true,
      "turn_detector": {
        "prefetch": {
          "trigger_by": ["asr_auto"]
        }
      }
    }
  }
}
```

### 使用 `eager_eos` 提前回复

`eager_eos` 由系统根据结束说话信号预测用户即将结束说话时触发提前请求。当前实现要求将正式结束说话方式设为 `semantic`。

创建智能体时，在 `properties` 中加入以下配置：

```json
{
  "properties": {
    "turn_detection": {
      "config": {
        "end_of_speech": {
          "mode": "semantic"
        }
      }
    },
    "parameters": {
      "eager_llm_response": true,
      "turn_detector": {
        "prefetch": {
          "trigger_by": ["eager_eos"]
        }
      }
    }
  }
}
```

### 提前准备音频回复（v2.17 规划）

如果你的大模型接收 ASR 转写文本并能直接输出音频，v2.17 计划支持提前生成音频回复。该配置不适用于直接向模型发送音频的实时会话。

以下示例使用 `asr_auto`，仅列出需要合并到现有创建请求中的三个参数。将 `output_modalities` 设为 `["audio"]` 可仅输出音频；如需同时输出文本和音频，改为 `["text", "audio"]`。

```json
{
  "properties": {
    "llm": {
      "output_modalities": ["audio"]
    },
    "parameters": {
      "eager_llm_response": true,
      "turn_detector": {
        "prefetch": {
          "trigger_by": ["asr_auto"]
        }
      }
    }
  }
}
```

在最终转写与候选文本匹配前，用户不会听到提前生成的音频，也不会看到对应的文本或字幕。匹配并采用回复后，引擎按各自的生成顺序播放音频、发布文本或字幕；被取消或未匹配的回复即使随后返回了新片段，也不会播放或显示。提前请求失败或超时时，沿用已有的大模型请求错误处理方式。

## 参数说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `properties.turn_detection.config.end_of_speech.mode` | String | `eager_eos` 方式的正式结束说话检测方式。目前仅支持设为 `semantic`。`asr_auto` 不要求此项设为 `semantic`。 |
| `properties.parameters.eager_llm_response` | Boolean | 是否开启大模型提前回复总开关。设为 `true` 才会启用提前准备，默认值为 `false`。 |
| `properties.parameters.turn_detector.prefetch.trigger_by` | String[] | 提前回复的触发方式。可配置 `asr_auto` 或 `eager_eos`。默认值为 `asr_auto`。 |

`trigger_by` 支持以下配置：

| 配置 | 行为 |
| --- | --- |
| `["asr_auto"]` | 仅使用 ASR 自动触发提前请求。 |
| `["eager_eos"]` | 仅使用 `eager_eos` 触发提前请求。 |
| `["asr_auto", "eager_eos"]` | 同时使用两种触发方式，结束说话方式须设为 `semantic`。同一轮内，两种方式对相同候选文本只发起一次请求。 |
| 未配置或 `[]` | 使用默认值 `asr_auto`。 |
