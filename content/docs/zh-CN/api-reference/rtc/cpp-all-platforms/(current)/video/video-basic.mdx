## disableVideo

禁用视频模块。

<a id="api_irtcengine_disablevideo__prototype"></a>

```text
virtual int disableVideo() = 0;
```

<a id="api_irtcengine_disablevideo__detailed_desc"></a>

该方法会影响内部引擎，且可以在离开频道后调用。调用该方法会重置整个引擎，可能导致响应时间变慢。你可以根据实际需求，使用以下方法分别控制视频模块的具体功能：

- [enableLocalVideo](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#api_irtcengine_enablelocalvideo)：是否启用摄像头以创建本地视频流。
- [muteLocalVideoStream](/zh-CN/api-reference/rtc/cpp-all-platforms/publishnsubscribe#api_irtcengine_mutelocalvideostream)：是否发布本地视频流。
- [muteRemoteVideoStream](/zh-CN/api-reference/rtc/cpp-all-platforms/publishnsubscribe#api_irtcengine_muteremotevideostream)：是否订阅并播放远端视频流。
- [muteAllRemoteVideoStreams](/zh-CN/api-reference/rtc/cpp-all-platforms/publishnsubscribe#api_irtcengine_muteallremotevideostreams)：是否订阅并播放所有远端视频流。

<a id="api_irtcengine_disablevideo__timing"></a>

### 调用时机

该方法可以在加入频道前或加入频道后调用：

- 如果在加入频道前调用，则进入纯语音模式。
- 如果在加入频道后调用，则从视频模式切换为纯语音模式。

之后调用 [enableVideo](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#api_irtcengine_enablevideo) 可重新切换回视频模式。

<a id="api_irtcengine_disablevideo__related"></a>

### 相关回调

成功调用该方法后，远端会触发 `onUserEnableVideo(false)` 回调，报告视频被禁用。

<a id="api_irtcengine_disablevideo__return_values"></a>

### 返回值

- 0：方法调用成功。
- &lt; 0：方法调用失败。详见[错误码](/zh-CN/api-reference/rtc/error-code)了解详情和解决建议。

### 所属接口类

- [IRtcEngine](/zh-CN/api-reference/rtc/cpp-all-platforms/rtc-interface-class#class_irtcengine)

## enableLocalVideo

启用或关闭本地视频采集。

<a id="api_irtcengine_enablelocalvideo__prototype"></a>

```text
virtual int enableLocalVideo(bool enabled) = 0;
```

<a id="api_irtcengine_enablelocalvideo__detailed_desc"></a>

该方法用于关闭或重新启用本地视频采集，不影响接收远端视频流。调用 [enableVideo](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#api_irtcengine_enablevideo) 后，默认启用本地视频采集。如果在频道内调用 `enableLocalVideo(false)` 关闭本地视频采集，则会同时停止在频道内发布视频流。若需重新开始视频采集，可调用 `enableLocalVideo(true)`，然后调用 [updateChannelMediaOptions](/zh-CN/api-reference/rtc/cpp-all-platforms/channel#api_irtcengine_updatechannelmediaoptions) 设置 `options` 参数以在频道中发布本地采集的视频流。

:::note
注：

- 可以在加入频道前或加入频道后调用该方法。但如果在加入频道前调用，设置仅在加入频道后生效。
- 该方法会启用内部引擎，并在离开频道后依然有效。
:::

<a id="api_irtcengine_enablelocalvideo__related"></a>

### 相关回调

成功关闭或重新启用本地视频采集后，SDK 会在远端客户端触发 [onRemoteVideoStateChanged](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#callback_irtcengineeventhandler_onremotevideostatechanged) 回调报告状态变化。

<a id="api_irtcengine_enablelocalvideo__parameters"></a>

### 参数

### enabled

是否启用本地视频采集：

- true：（默认）启用本地视频采集。
- false：关闭本地视频采集。关闭后，远端用户无法接收到本地用户的视频流，但本地用户仍可接收远端用户的视频流。设置为 false 时，无需本地摄像头。

<a id="api_irtcengine_enablelocalvideo__return_values"></a>

### 返回值

- 0：方法调用成功。
- &lt; 0：方法调用失败。详见[错误码](/zh-CN/api-reference/rtc/error-code)了解详情和解决建议。

## setVideoScenario

设置视频应用场景。

<a id="api_irtcengine_setvideoscenario__prototype"></a>

```text
virtual int setVideoScenario(VIDEO_APPLICATION_SCENARIO_TYPE scenarioType) = 0;
```

<a id="api_irtcengine_setvideoscenario__detailed_desc"></a>

### 自从

自 v4.2.0 版本新增。

:::note
注： 请在加入频道前调用该方法。
:::

<a id="api_irtcengine_setvideoscenario__parameters"></a>

### 参数

### scenarioType

视频应用场景类型，详见 [VIDEO_APPLICATION_SCENARIO_TYPE](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-videoapplicationscenariotype)。

- `APPLICATION_SCENARIO_MEETING`（1）：适用于会议场景。SDK 会自动启用以下策略：

  - 当低画质视频流需要较高码率时，SDK 会启用多种抗网络拥塞技术，提升低画质视频流的性能，确保订阅端流畅接收。
  - SDK 实时监控高画质视频流的订阅人数，并动态调整其配置：

    - 若无人订阅高画质视频流，SDK 会自动降低其码率和帧率以节省上行带宽。
    - 若有人订阅高画质视频流，SDK 会将其重置为最近一次调用 [setVideoEncoderConfiguration](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#api_irtcengine_setvideoencoderconfiguration) 设置的 [VideoEncoderConfiguration](/zh-CN/api-reference/rtc/cpp-all-platforms/class-videoencoderconfiguration) 配置；若未设置，则使用以下默认值：

      - 分辨率：（Windows 和 macOS）1280 × 720；（Android 和 iOS）960 × 540。
      - 帧率：15 fps。
      - 码率：（Windows 和 macOS）1600 Kbps；（Android 和 iOS）1000 Kbps。
  - SDK 实时监控低画质视频流的订阅人数，并根据订阅情况动态启用或禁用该流。

    - 若用户调用了 `setDualStreamMode` 并设置为永不发送低画质视频流（`DISABLE_SIMULCAST_STREAM`），则该策略不生效。
    - 若无人订阅低画质视频流，SDK 会自动禁用该流以节省上行带宽。
    - 若有人订阅低画质视频流，SDK 会启用该流，并重置为最近一次调用 `setDualStreamMode` 设置的 [SimulcastStreamConfig](/zh-CN/api-reference/rtc/cpp-all-platforms/class-simulcaststreamconfig) 配置；若未设置，则使用以下默认值：

      - 分辨率：480 × 272。
      - 帧率：15 fps。
      - 码率：500 Kbps。
- `APPLICATION_SCENARIO_1V1`（2）：适用于一对一直播场景。SDK 会优化策略，以满足低延迟和高画质的需求，提升视频质量、首帧渲染速度、中低端设备的延迟表现以及弱网环境下的流畅性。注意：该枚举值仅适用于主播对主播的场景。
- `APPLICATION_SCENARIO_LIVESHOW`（3）：适用于秀场场景。SDK 会启用多项性能优化，包括自动启用音视频帧加速渲染（无需调用 [enableInstantMediaRendering](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-rendering#api_irtcengine_enableinstantmediarendering)）以减少首帧延迟，以及启用 B 帧编码以提升图像质量和带宽效率，即使在弱网或低端设备上也能提供更好的视频质量和播放流畅性。

<a id="api_irtcengine_setvideoscenario__return_values"></a>

### 返回值

- 0：方法调用成功。
- &lt; 0：方法调用失败。详见[错误码](/zh-CN/api-reference/rtc/error-code)了解详情和解决建议。

  - -1：发生通用错误（无具体原因）。
  - -4：不支持视频应用场景，可能是因为使用了语音 SDK 而非视频 SDK。
  - -7：[IRtcEngine](/zh-CN/api-reference/rtc/cpp-all-platforms/rtc-interface-class#class_irtcengine) 对象尚未初始化。请在调用该方法前初始化 [IRtcEngine](/zh-CN/api-reference/rtc/cpp-all-platforms/rtc-interface-class#class_irtcengine) 对象。

## onLocalVideoStateChanged

本地视频状态发生变化回调。

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__prototype"></a>

```text
virtual void onLocalVideoStateChanged(VIDEO_SOURCE_TYPE source, LOCAL_VIDEO_STREAM_STATE state, LOCAL_VIDEO_STREAM_REASON reason)
```

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__detailed_desc"></a>

:::note
注： 请注意，视频帧重复检测仅适用于分辨率大于 200 × 200、帧率大于等于 10 fps 且码率小于 20 Kbps 的视频帧。
通常情况下，如果视频采集出现异常，可以通过该回调中的 `reason` 参数排查问题。但在部分设备上，采集异常（如卡顿）时，Android 系统不会抛出任何错误回调，导致 SDK 无法上报本地视频状态变化的原因。此时，你可以通过以下方式判断是否未采集到视频帧：该回调上报的 `state` 为 `LOCAL_VIDEO_STREAM_STATE_CAPTURING` 或 `LOCAL_VIDEO_STREAM_STATE_ENCODING`，且 [onLocalVideoStats](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#callback_irtcengineeventhandler_onlocalvideostats) 回调中的 `captureFrameRate` 为 0。
:::

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__timing"></a>

### 触发时机

SDK 在以下情况下会触发该回调，并将 `state` 设置为 `LOCAL_VIDEO_STREAM_STATE_FAILED`，`reason` 设置为 `LOCAL_VIDEO_STREAM_REASON_CAPTURE_FAILURE`：

- 应用切换到后台，系统回收了摄像头资源。
- 在 Android 9 及以上版本中，应用在后台运行一段时间后，系统自动回收摄像头权限。
- 在 Android 6 及以上版本中，摄像头被第三方应用占用一段时间后释放，SDK 会触发该回调并上报 [onLocalVideoStateChanged](/zh-CN/api-reference/rtc/cpp-all-platforms/video/video-basic#callback_irtcengineeventhandler_onlocalvideostatechanged) 回调，`state` 为 `LOCAL_VIDEO_STREAM_STATE_CAPTURING`，`reason` 为 `LOCAL_VIDEO_STREAM_REASON_OK`。
- 摄像头正常启动，但连续四秒未输出视频帧。
- 当摄像头输出采集的视频帧时，若 SDK 检测到连续 15 帧重复的视频帧，会触发该回调，`state` 为 `LOCAL_VIDEO_STREAM_STATE_CAPTURING`，`reason` 为 `LOCAL_VIDEO_STREAM_REASON_CAPTURE_FAILURE`。

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__parameters"></a>

### 参数

### source

视频源的类型，详见 [VIDEO_SOURCE_TYPE](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-videosourcetype)。

### state

本地视频的状态，详见 [LOCAL_VIDEO_STREAM_STATE](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-localvideostreamstate)。

### reason

本地视频状态变化的原因，详见 [LOCAL_VIDEO_STREAM_REASON](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-localvideostreamreason)。

### 参数

### sourceType

视频源类型。详见 [VIDEO_SOURCE_TYPE](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-videosourcetype)。

### uid

发生视频尺寸或旋转变化的用户 ID。本地用户的 `uid` 为 0，表示本地用户的视频预览。

### width

视频流的宽度（单位为像素）。

### height

视频流的高度（单位为像素）。

### rotation

视频旋转角度，取值范围为 [0, 360)。

:::note
注： `rotation` 参数在 iOS 平台上始终为 0。
