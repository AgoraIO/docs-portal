## complain

允许用户在通话结束后投诉通话质量。

<a id="api_irtcengine_complain__prototype"></a>

```cpp
virtual int complain(const char* callId, const char* description) = 0;
```

<a id="api_irtcengine_complain__detailed_desc"></a>

请在用户离开频道后调用该方法。

<a id="api_irtcengine_complain__parameters"></a>

### 参数

#### `callId`

当前通话的通话 ID。你可以通过调用 [getCallId](/zh-CN/api-reference/rtc/cpp-all-platforms/network#api_irtcengine_getcallid) 获取。

#### `description`

（可选）对通话的描述。字符串长度应小于 800 字节。

<a id="api_irtcengine_complain__return_values"></a>

### 返回值

- 0：方法调用成功。
- &lt; 0：方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/windows/error-code)了解详情和解决建议。
  - -1：发生通用错误（无明确原因）。
  - -2：参数无效。
  - -7：在 IRtcEngine 初始化之前调用该方法。

### 所属接口类
- [IRtcEngine](/zh-CN/api-reference/rtc/cpp-all-platforms/rtc-interface-class#class_irtcengine)

<a id="api_irtcengine_enableencryption"></a>

## enableEncryption

启用或关闭内置加密功能。

<a id="api_irtcengine_enableencryption__prototype"></a>

```cpp
virtual int enableEncryption(bool enabled, const EncryptionConfig& config) = 0;
```

<a id="api_irtcengine_enableencryption__detailed_desc"></a>

用户离开频道后，SDK 会自动关闭内置加密功能。若需启用该功能，请在用户重新加入频道前调用该方法。

:::info[注]
- 同一频道内的所有用户在调用该方法时必须设置相同的加密配置。
- 启用内置加密功能后，无法使用旁路推流功能。
:::

<a id="api_irtcengine_enableencryption__scenario"></a>

### 适用场景

适用于安全性要求较高的场景。

<a id="api_irtcengine_enableencryption__timing"></a>

### 调用时机

请在加入频道前调用该方法。

<a id="api_irtcengine_enableencryption__parameters"></a>

### 参数

#### `enabled`

是否启用内置加密功能：

- true：启用内置加密功能。
- false：（默认）关闭内置加密功能。

#### `config`

内置加密配置。详见 [EncryptionConfig](/zh-CN/api-reference/rtc/cpp-all-platforms/class-encryptionconfig)。

<a id="api_irtcengine_enableencryption__return_values"></a>

### 返回值

- 0：方法调用成功。
- &lt; 0：方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/windows/error-code)了解详情和解决建议。
  - -2：参数无效，请传入有效参数。
  - -4：内置加密模式错误或 SDK 加载外部加密库失败，请检查枚举值或重新加载外部加密库。
  - -7：SDK 未初始化，请先初始化 IRtcEngine 实例后再调用该方法。

### 所属接口类
- [IRtcEngine](/zh-CN/api-reference/rtc/cpp-all-platforms/rtc-interface-class#class_irtcengine)

## getNetworkType

获取本地网络连接类型。

<a id="api_irtcengine_getnetworktype__prototype"></a>

```cpp
virtual int getNetworkType() = 0;
```

<a id="api_irtcengine_getnetworktype__detailed_desc"></a>

:::info[注]
[getNetworkType](/zh-CN/api-reference/rtc/cpp-all-platforms/network#api_irtcengine_getnetworktype) 方法可在加入频道前或加入频道后调用。
:::

<a id="api_irtcengine_getnetworktype__return_values"></a>

### 返回值

- 0：方法调用成功，返回本地网络连接类型。
  - 0：SDK 与网络断开连接。
  - 1：网络类型为 LAN。
  - 2：网络类型为 Wi-Fi（包括热点）。
  - 3：网络类型为移动 2G。
  - 4：网络类型为移动 3G。
  - 5：网络类型为移动 4G。
  - 6：网络类型为移动 5G。
- &lt; 0：方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/windows/error-code)了解详情和解决建议。
  - -1：网络类型未知。

- [IRtcEngine](/zh-CN/api-reference/rtc/cpp-all-platforms/rtc-interface-class#class_irtcengine)

## queryDeviceScore

查询设备评分。

<a id="api_irtcengine_querydevicescore__prototype"></a>

```cpp
virtual int queryDeviceScore() = 0;
```

<a id="api_irtcengine_querydevicescore__detailed_desc"></a>

在高清或超高清的视频场景中，可以调用该方法查询设备评分。如果返回的评分较低（例如低于 60），建议降低视频分辨率，以避免影响视频体验。不同业务场景对设备评分的最低要求不同，具体建议请[联系技术支持](https://ticket.shengwang.cn/)。

<a id="api_irtcengine_querydevicescore__return_values"></a>

### 返回值

- 方法调用成功，返回当前设备评分，范围为 [0, 100]，数值越大表示设备性能越强。大多数设备评分在 60 到 100 之间。
- &lt; 0：方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/windows/error-code)了解详情和解决建议。

### 所属接口类

## onNetworkQuality

报告频道中每个用户的 Last-mile 网络质量。

<a id="callback_irtcengineeventhandler_onnetworkquality__prototype"></a>

```cpp
virtual void onNetworkQuality(uid_t uid, int txQuality, int rxQuality)
```

<a id="callback_irtcengineeventhandler_onnetworkquality__detailed_desc"></a>

该回调报告频道中每个用户的 Last-mile 网络状况。Last-mile 指的是本地设备与声网边缘服务器之间的连接。SDK 每两秒触发一次该回调。如果频道中有多个用户，SDK 会触发多次该回调。该回调通过在频道内发送和接收广播数据包来反馈网络质量。为避免广播风暴导致频道内数据传输量过大，该回调默认最多同时反馈 4 个远端用户的网络质量。

:::info[注]
`txQuality` 在用户未发送流时为 `UNKNOWN`； `rxQuality` 在用户未接收流时为 `UNKNOWN`。
:::

<a id="callback_irtcengineeventhandler_onnetworkquality__parameters"></a>

### 参数

#### `uid`

用户 ID。用于指定要报告网络质量的用户。如果该值为 0，则表示报告本地用户的网络质量。

#### `txQuality`

用户的上行网络质量评分，依据上行网络的传输码率、丢包率、平均往返时延（RTT）和抖动情况评估。该评分有助于判断当前上行网络是否能支持所选的视频编码器配置。例如，1000 Kbps 的上行网络可能足以支持分辨率为 640 × 480、帧率为 15 fps 的视频帧，但可能不足以支持高于 1280 × 720 的分辨率。详见 [QUALITY_TYPE](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-qualitytype)。

#### `rxQuality`

用户的下行网络质量评分，依据下行网络的丢包率、平均 RTT 和抖动情况评估。详见 [QUALITY_TYPE](/zh-CN/api-reference/rtc/cpp-all-platforms/enum-qualitytype)。

<a id="callback_irtcengineeventhandler_onremotesubscribefallbacktoaudioonly__detailed_desc"></a>

如果你调用了 [setRemoteSubscribeFallbackOption](/zh-CN/api-reference/rtc/cpp-all-platforms/network#api_irtcengine_setremotesubscribefallbackoption) 并将 `option` 设置为 `STREAM_FALLBACK_OPTION_AUDIO_ONLY`，SDK 会在以下情况下触发该回调：

- 下行网络条件较差，已订阅的视频流被降级为纯音频流。
- 下行网络条件改善，已订阅的流恢复为视频流。

:::info[注]
当远端媒体流因网络较弱切换为视频小流时，你可以通过 [onRemoteVideoStats](/zh-CN/api-reference/rtc/cpp-all-platforms/video-basic#callback_irtcengineeventhandler_onremotevideostats) 回调监控高质量与视频小流之间的切换。
:::

<a id="callback_irtcengineeventhandler_onremotesubscribefallbacktoaudioonly__parameters"></a>

### 参数

#### `uid`

远端用户 ID。

#### `isFallbackOrRecover`

是否因网络变化导致媒体流切换：

- true：由于网络条件差，已订阅的媒体流降级为纯音频流。
- false：网络条件改善后，已订阅的媒体流恢复为视频流。
