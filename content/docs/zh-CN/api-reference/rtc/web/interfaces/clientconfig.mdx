### aiClientMode

<ApiSignature labels="Optional">

aiClientMode: boolean

</ApiSignature>

AI 客户端模式。开启后，SDK 会在创建客户端时准备 AI QoS 所需的媒体 DataChannel。

需要支持的桌面浏览器并安装 AI 音频服务。移动端浏览器和 Firefox 回退为 WebRTC 音频接收。`agora-rtc-sdk-ng/full` 构建已安装 `AiAudioModeService`，默认构建未安装。使用 ESM 时，从 `agora-rtc-sdk-ng/services/ai-audio-mode` 导入 `AiAudioModeService`，并在创建客户端前通过 `AgoraRTC.use` 安装。

<a id="mode"></a>

### mode

<ApiSignature>

mode: [SDK_MODE](/zh-CN/api-reference/rtc/web/globals#sdk_mode)

</ApiSignature>

频道场景。

Agora Web SDK 需知道 app 的使用场景（例如通信场景或直播场景），从而使用不同的优化手段。

声网频道支持以下场景:

- `"live"`: 直播场景，有主播和观众两种用户角色，可以通过 [setClientRole](/zh-CN/api-reference/rtc/web/interfaces/iagorartcclient#setclientrole) 方法设置用户角色为主播或观众。主播可以发布和订阅音视频轨道，而观众只能订阅音视频轨道，无法发布。
- `"rtc"`: 通信场景，频道中的任何用户均可发布音视频。

:::caution[注意]
通信场景（`"rtc"`）存在兼容性问题，不推荐使用。建议使用直播场景（`"live"`），该场景同时适用于一对一通话和多人互动。
:::

### multiopus

<ApiSignature labels="Optional">

multiopus: boolean

</ApiSignature>

是否启用 Multiopus 多声道音频，默认值为 `false`。

设置为 `true` 后，客户端可发送和接收 4、6、8 声道音频。收发两端均需启用该配置。
 发送自定义多声道音频时，通过 [CustomAudioTrackInitConfig.channelCount](/zh-CN/api-reference/rtc/web/interfaces/customaudiotrackinitconfig#channelcount) 指定声道数。

:::caution[注意]
Multiopus 支持 Chrome 94 及以上版本，不支持 Firefox 和 Safari。
 多声道音频处理需要浏览器支持 `MediaStreamTrackProcessor` 和 `MediaStreamTrackGenerator`。
:::

### role

<ApiSignature labels="Optional">

role: [ClientRole](/zh-CN/api-reference/rtc/web/globals#clientrole)

</ApiSignature>

直播场景中（[mode](/zh-CN/api-reference/rtc/web/interfaces/clientconfig#mode) 为 `"live"` 时）的用户角色。

用户角色确定用户在 SDK 层的权限，包含是否可以发布和订阅音视频轨道、是否可以推流到 CDN。用户角色有 `"host"`（主播）和 `"audience"`（观众）。主播既可发布轨道，也可订阅轨道；观众不能进行 [publish](/zh-CN/api-reference/rtc/web/interfaces/iagorartcclient#publish) 操作。直播场景中的用户角色默认为观众。如需发布音视频，必须将角色角色为主播。

在创建客户端之后，你可以随时调用 [setClientRole](/zh-CN/api-reference/rtc/web/interfaces/iagorartcclient#setclientrole) 来改变用户角色。
