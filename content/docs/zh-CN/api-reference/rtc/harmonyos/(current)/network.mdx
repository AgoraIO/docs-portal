## enableEncryption

开启或关闭内置加密。

<a id="api_irtcengine_enableencryption__prototype"></a>

```text
public abstract enableEncryption(enabled: boolean, config: EncryptionConfig): number;
```

<a id="api_irtcengine_enableencryption__detailed_desc"></a>

用户离开频道后，SDK 会自动关闭加密。如需重新开启加密，你需要在用户再次加入频道前调用该方法。

<a id="api_irtcengine_enableencryption__scenario"></a>

### 适用场景

对安全要求较高的场景。

<a id="api_irtcengine_enableencryption__timing"></a>

### 调用时机

该方法需要在加入频道前调用。

<a id="api_irtcengine_enableencryption__restriction"></a>

### 调用限制

- 同一频道内的所有用户在调用该方法时，必须设置相同的加密模式和密钥。
- 如果开启了内置加密，则不能使用旁路推流功能。

<a id="api_irtcengine_enableencryption__parameters"></a>

### 参数

### enabled

是否开启内置加密：

- true: 开启内置加密。
- false:（默认）关闭内置加密。

### config

配置内置加密模式和密钥。详见 [EncryptionConfig](/zh-CN/api-reference/rtc/harmonyos/class-encryptionconfig)。

<a id="api_irtcengine_enableencryption__return_values"></a>

### 返回值

- 0: 方法调用成功。
- &lt; 0: 方法调用失败

  - -2: 调用了无效的参数。需重新指定参数。
  - -4: 设置的加密模式不正确或加载外部加密库失败。需检查枚举值是否正确或重新加载外部加密库。
  - -7: SDK 尚未初始化。需在调用 API 之前已创建 [RtcEngine](/zh-CN/api-reference/rtc/harmonyos/rtc-interface-class#class_irtcengine) 对象并完成初始化。

## getCurrentMonotonicTimeInMs

获取 SDK 当前的 Monotonic Time。

<a id="api_irtcengine_getcurrentmonotonictimeinms__prototype"></a>

```text
public abstract getCurrentMonotonicTimeInMs(): number;
```

<a id="api_irtcengine_getcurrentmonotonictimeinms__detailed_desc"></a>

Monotonic Time 是指一个单调递增的时间序列，它的值会随着时间的推移而增加。单位为毫秒。

在自定义视频采集、自定义音频采集场景中，为确保音视频同步，声网建议你调用该方法获取 SDK 当前的 Monotonic Time 后，将该值传入采集的视频帧（[VideoFrame](/zh-CN/api-reference/rtc/harmonyos/class-videoframe)）、音频帧（[AudioFrame](/zh-CN/api-reference/rtc/harmonyos/class-audioframe)）的时间戳参数。

<a id="api_irtcengine_getcurrentmonotonictimeinms__timing"></a>

### 调用时机

加入频道前后均可调用。

<a id="api_irtcengine_getcurrentmonotonictimeinms__restriction"></a>

### 调用限制

无。

<a id="api_irtcengine_getcurrentmonotonictimeinms__return_values"></a>

### 返回值

- ≥ 0: 方法调用成功，返回 SDK 当前的 Monotonic Time（毫秒）。
- &lt; 0: 方法调用失败。详见[错误码](/zh-CN/api-reference/rtc/error-code)了解详情和解决建议。

## startLastmileProbeTest

开始通话前网络质量探测。

<a id="api_irtcengine_startlastmileprobetest__prototype"></a>

```text
public abstract startLastmileProbeTest(config: LastmileProbeConfig): number;
```

<a id="api_irtcengine_startlastmileprobetest__detailed_desc"></a>

开始通话前网络质量探测，向用户反馈上下行网络的带宽、丢包、网络抖动和往返时延数据。

<a id="api_irtcengine_startlastmileprobetest__timing"></a>

### 调用时机

该方法需要在加入频道前调用，且在收到 onLastmileQuality 和 onLastmileProbeResult 回调之前请不要调用其他方法，否则可能会由于 API 操作过于频繁导致此方法无法执行。

<a id="api_irtcengine_startlastmileprobetest__restriction"></a>

### 调用限制

无。

<a id="api_irtcengine_startlastmileprobetest__related"></a>

### 相关回调

成功调用该方法后，SDK 会依次触发如下 2 个回调：

- [onLastmileQuality](/zh-CN/api-reference/rtc/harmonyos/network#callback_irtcengineeventhandler_onlastmilequality)，视网络情况约 2 秒内返回。该回调通过打分反馈上下行网络质量，更贴近用户的主观感受。
- [onLastmileProbeResult](/zh-CN/api-reference/rtc/harmonyos/network#callback_irtcengineeventhandler_onlastmileproberesult)，视网络情况约 30 秒内返回。该回调通过具体数据反馈上下行网络质量，更加客观。

<a id="api_irtcengine_startlastmileprobetest__parameters"></a>

### 参数

### config

Last mile 网络探测配置，详见 [LastmileProbeConfig](/zh-CN/api-reference/rtc/harmonyos/class-lastmileprobeconfig)。

<a id="api_irtcengine_startlastmileprobetest__return_values"></a>

### 返回值

- 0: 方法调用成功。
- &lt; 0: 方法调用失败。详见[错误码](/zh-CN/api-reference/rtc/error-code)了解详情和解决建议。

## onConnectionLost

网络连接中断，且 SDK 无法在 10 秒内连接服务器回调。

<a id="callback_irtcengineeventhandler_onconnectionlost__prototype"></a>

```text
onConnectionLost?:() => void;
```

<a id="callback_irtcengineeventhandler_onconnectionlost__detailed_desc"></a>

SDK 在调用 joinChannelWithOptions 后，无论是否加入成功，只要 10 秒和服务器无法连接就会触发该回调。如果 SDK 在断开连接后，20 分钟内还是没能重新加入频道，SDK 会停止尝试重连。

## onNetworkQuality

通话中每个用户的网络上下行 last mile 质量报告回调。

<a id="callback_irtcengineeventhandler_onnetworkquality__prototype"></a>

```text
onNetworkQuality? : (uid: number, txQuality: Constants.NetworkQuality, rxQuality: Constants.NetworkQuality) => void;
```

<a id="callback_irtcengineeventhandler_onnetworkquality__detailed_desc"></a>

<a id="callback_irtcengineeventhandler_onnetworkquality__desc1"></a>

该回调描述每个用户在通话中的 last mile 网络状态，其中 last mile 是指设备到声网边缘服务器的网络状态。

<a id="callback_irtcengineeventhandler_onnetworkquality__desc2"></a>

该回调每 2 秒触发一次。如果远端有多个用户，该回调每 2 秒会被触发多次。

该回调通过频道内的广播包反馈网络质量。过多的广播包可能引发广播风暴。为防止广播风暴导致频道内大量数据传输，该回调默认支持同时反馈最多 4 个远端主播的网络质量。

:::note
注： 用户不发流时，txQuality 为 `UNKNOWN`；用户不收流时，rxQuality 为 `UNKNOWN`。
:::

<a id="callback_irtcengineeventhandler_onnetworkquality__parameters"></a>

### 参数

### uid

用户 ID。表示该回调报告的是持有该 ID 的用户的网络质量。如果当 uid 为 0 时，返回的是本地用户的网络质量。

### txQuality

该用户的上行网络质量，基于发送码率、上行丢包率、平均往返时延和网络抖动计算。 该值代表当前的上行网络质量，帮助判断是否可以支持当前设置的视频编码属性。 假设上行码率是 1000 Kbps，那么支持直播场景下 640 × 480 的分辨率、15 fps 的帧率没有问题，但是支持 1280 × 720 的分辨率就会有困难。详见 [NetworkQuality](/zh-CN/api-reference/rtc/harmonyos/enum-qualitytype)。

### rxQuality

该用户的下行网络质量，基于下行网络的丢包率、平均往返延时和网络抖动计算。详见 [NetworkQuality](/zh-CN/api-reference/rtc/harmonyos/enum-qualitytype)。
