## <span id="toc_media_push"></span>startRtmpStreamWithoutTranscoding [#api_irtcengine_startrtmpstreamwithouttranscoding]

开始向 CDN 推送音视频流（不进行转码）。

<a id="api_irtcengine_startrtmpstreamwithouttranscoding__prototype"></a>

```java
public abstract int startRtmpStreamWithoutTranscoding(String url);
```

<a id="api_irtcengine_startrtmpstreamwithouttranscoding__detailed_desc"></a>

声网推荐你使用更加完善的服务端推流功能，详见[实现服务端旁路推流](https://doc.shengwang.cn/doc/media-push/restful/landing-page)。 你可以调用该方法将音频或视频流推送到指定的 CDN 地址。该方法每次只能向一个 CDN 地址推送媒体流，如果需要推送到多个地址，请多次调用该方法。

:::info[注]
- 请在加入频道后调用该方法。
- 只有在 `LIVE_BROADCASTING` 模式下的主播角色可以调用该方法。
- 如果推流失败后需要重试，请先调用 [stopRtmpStream](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_stoprtmpstream) 停止推流，再调用该方法重新推流；否则，SDK 会返回与上次失败相同的错误码。
:::

### 相关回调 [#api_irtcengine_startrtmpstreamwithouttranscoding__related]

成功调用该方法后，SDK 会触发 [onRtmpStreamingStateChanged](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#callback_irtcengineeventhandler_onrtmpstreamingstatechanged) 回调报告推流状态。

### 参数 [#api_irtcengine_startrtmpstreamwithouttranscoding__parameters]

#### `url`

推流地址，格式为 RTMP 或 RTMPS，长度不能超过 1024 字节。不支持中文等特殊字符。

### 返回值 [#api_irtcengine_startrtmpstreamwithouttranscoding__return_values]

- 0：方法调用成功。
- &lt; 0：方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/android/error-code)了解详情和解决建议。

  - -2： `url` 不合法。
  - -7：调用该方法前未初始化 SDK。
  - -19：推流地址已被使用，请更换地址。

- [RtcEngine](/zh-CN/api-reference/rtc/android/rtc-interface-class#class_irtcengine)

## onRtmpStreamingStateChanged [#callback_irtcengineeventhandler_onrtmpstreamingstatechanged]

旁路推流状态发生变化回调。

<a id="callback_irtcengineeventhandler_onrtmpstreamingstatechanged__prototype"></a>

```java
public void onRtmpStreamingStateChanged(String url, int state, int reason)
```

<a id="callback_irtcengineeventhandler_onrtmpstreamingstatechanged__detailed_desc"></a>

该回调用于指示旁路推流的状态。当旁路推流状态发生变化时，SDK 会触发该回调，并返回对应的 URL 地址和当前的推流状态。当出现异常时，你可以参考错误码参数中的详细错误信息进行排查。

### 触发时机 [#callback_irtcengineeventhandler_onrtmpstreamingstatechanged__timing]

该回调在旁路推流状态发生变化时被触发。

### 参数 [#callback_irtcengineeventhandler_onrtmpstreamingstatechanged__parameters]

#### `url`

发生状态变化的旁路推流地址。

#### `state`

当前旁路推流的状态：

- `RTMP_STREAM_PUBLISH_STATE_IDLE` (0)：旁路推流尚未开始或已结束。
- `RTMP_STREAM_PUBLISH_STATE_CONNECTING` (1)：正在连接推流服务器和 CDN 服务器。
- `RTMP_STREAM_PUBLISH_STATE_RUNNING` (2)：正在推流。SDK 成功推送 RTMP 或 RTMPS 流并返回该状态。
- `RTMP_STREAM_PUBLISH_STATE_RECOVERING` (3)：正在恢复推流。当 CDN 出现异常或旁路推流中断时，SDK 会尝试恢复推流并返回该状态。

  - 如果 SDK 成功恢复推流，则返回 `RTMP_STREAM_PUBLISH_STATE_RUNNING` (2)。
  - 如果在 60 秒内未恢复推流或服务器发生错误，则返回 `RTMP_STREAM_PUBLISH_STATE_FAILURE` (4)。你也可以通过调用 [startRtmpStreamWithTranscoding](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_startrtmpstreamwithtranscoding)、 [startRtmpStreamWithoutTranscoding](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_startrtmpstreamwithouttranscoding) 和 [stopRtmpStream](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_stoprtmpstream) 方法重新连接服务器。
- `RTMP_STREAM_PUBLISH_STATE_FAILURE` (4)：推流失败。你可以参考错误码参数中的详细错误信息进行排查，也可以尝试重新推流。
- `RTMP_STREAM_PUBLISH_STATE_DISCONNECTING` (5)：SDK 正在断开与声网旁路推流服务器和 CDN 服务器的连接。当你调用 [stopRtmpStream](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_stoprtmpstream) 正常停止旁路推流时，SDK 会依次返回 `RTMP_STREAM_PUBLISH_STATE_DISCONNECTING` 和 `RTMP_STREAM_PUBLISH_STATE_IDLE` 状态。

#### `reason`

旁路推流状态变化的原因：

- `RTMP_STREAM_PUBLISH_REASON_OK` (0)：推流成功。
- `RTMP_STREAM_PUBLISH_REASON_INVALID_ARGUMENT` (1)：参数无效。请检查参数设置。
- `RTMP_STREAM_PUBLISH_REASON_ENCRYPTED_STREAM_NOT_ALLOWED` (2)：加密流无法推送。
- `RTMP_STREAM_PUBLISH_REASON_CONNECTION_TIMEOUT` (3)：推流超时。你可以尝试重新推流。
- `RTMP_STREAM_PUBLISH_REASON_INTERNAL_SERVER_ERROR` (4)：声网推流服务器内部错误。你可以尝试重新推流。
- `RTMP_STREAM_PUBLISH_REASON_RTMP_SERVER_ERROR` (5)：CDN 服务器错误。
- `RTMP_STREAM_PUBLISH_REASON_TOO_OFTEN` (6)：保留参数。
- `RTMP_STREAM_PUBLISH_REASON_REACH_LIMIT` (7)：主播推送的 URL 超过 10 个。你可以停止向不必要的 URL 推流。
- `RTMP_STREAM_PUBLISH_REASON_NOT_AUTHORIZED` (8)：主播操作了其他主播的 URL，例如更新或停止其他主播的流。请检查你的应用逻辑。
- `RTMP_STREAM_PUBLISH_REASON_STREAM_NOT_FOUND` (9)：声网服务器未找到旁路推流的媒体流。
- `RTMP_STREAM_PUBLISH_REASON_FORMAT_NOT_SUPPORTED` (10)：旁路推流地址格式不支持。请检查 URL 格式是否正确。
- `RTMP_STREAM_PUBLISH_REASON_NOT_BROADCASTER` (11)：用户角色不是主播，无法使用旁路推流功能。请检查你的应用代码逻辑。
- `RTMP_STREAM_PUBLISH_REASON_TRANSCODING_NO_MIX_STREAM` (13)：在无转码的旁路推流场景中调用了 [updateRtmpTranscoding](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_updatertmptranscoding) 方法更新转码配置。请检查你的应用代码逻辑。
- `RTMP_STREAM_PUBLISH_REASON_NET_DOWN` (14)：主播端网络异常。
- `RTMP_STREAM_PUBLISH_REASON_INVALID_PRIVILEGE` (16)：项目无权限使用旁路推流服务。
- `RTMP_STREAM_UNPUBLISH_REASON_OK` (100)：已正常停止旁路推流。调用 [stopRtmpStream](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_stoprtmpstream) 停止推流后，SDK 返回该值。

## onTranscodingUpdated [#callback_irtcengineeventhandler_ontranscodingupdated]

发布端云端转码配置更新回调。

<a id="callback_irtcengineeventhandler_ontranscodingupdated__prototype"></a>

```java
public void onTranscodingUpdated() {}
```

<a id="callback_irtcengineeventhandler_ontranscodingupdated__detailed_desc"></a>

当调用 [startRtmpStreamWithTranscoding](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_startrtmpstreamwithtranscoding) 更新 [LiveTranscoding](/zh-CN/api-reference/rtc/android/class-livetranscoding) 配置时，SDK 会触发该回调以报告更新信息。

:::info[注]
如果首次调用 [startRtmpStreamWithTranscoding](/zh-CN/api-reference/rtc/android/cloud-media-relay/media-push#api_irtcengine_startrtmpstreamwithtranscoding) 设置 [LiveTranscoding](/zh-CN/api-reference/rtc/android/class-livetranscoding) 配置，SDK 不会触发该回调。
:::

### 触发时机 [#callback_irtcengineeventhandler_ontranscodingupdated__timing]

该回调在发布端的云端转码配置发生更新时被触发。
