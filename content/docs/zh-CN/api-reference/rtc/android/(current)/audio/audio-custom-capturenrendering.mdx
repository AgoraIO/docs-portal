## createCustomAudioTrack

创建一个自定义音频轨道。

<a id="api_irtcengine_createcustomaudiotrack__prototype"></a>

```text
public abstract int createCustomAudioTrack(Constants.AudioTrackType trackType, AudioTrackConfig config)
```

<a id="api_irtcengine_createcustomaudiotrack__detailed_desc"></a>

你可以通过以下步骤发布自定义音频源：

1. 调用该方法创建一个自定义音频轨道，并获取音频轨道 ID。
2. 调用 `joinChannel` 加入频道。在 [ChannelMediaOptions](/zh-CN/api-reference/rtc/android/class-channelmediaoptions) 中，将 `publishCustomAudioTrackId` 设置为步骤 1 中获取的音频轨道 ID，并将 `publishCustomAudioTrack` 设置为 true。
3. 调用 [pushExternalAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-custom-capturenrendering#api_irtcengine_pushaudioframe2)，并将 `trackId` 设置为步骤 2 中的音频轨道 ID，即可在频道中发布对应的自定义音频源。

:::note
注： 该方法需要在加入频道前调用。
:::

<a id="api_irtcengine_createcustomaudiotrack__parameters"></a>

### 参数

<ParameterList>
<a id="tracktype"></a>
<Parameter name="trackType">

自定义音频轨道的类型，详见 [AudioTrackType](/zh-CN/api-reference/rtc/android/enum-audiotracktype)。

:::note
注： 如果该参数设置为 `AUDIO_TRACK_DIRECT`，则在调用 `joinChannel` 加入频道时，必须将 [ChannelMediaOptions](/zh-CN/api-reference/rtc/android/class-channelmediaoptions) 中的 `publishMicrophoneTrack` 设置为 false，否则加入频道会失败并返回错误码 -2。
:::

</Parameter>
<a id="config"></a>
<Parameter name="config">

自定义音频轨道的配置，详见 [AudioTrackConfig](/zh-CN/api-reference/rtc/android/class-audiotrackconfig)。

</Parameter>
</ParameterList>

<a id="api_irtcengine_createcustomaudiotrack__return_values"></a>

### 返回值

- 方法调用成功，返回音频轨道 ID，作为该音频轨道的唯一标识。
- 方法调用失败，返回 `0xffffffff`。

## pullPlaybackAudioFrame [1/2]

拉取远端混音后的音频数据用于播放。

<a id="api_irtcengine_pullaudioframe__prototype"></a>

```text
public abstract int pullPlaybackAudioFrame(byte[] data, int lengthInByte);
```

<a id="api_irtcengine_pullaudioframe__detailed_desc"></a>

调用该方法前，请先调用 [setExternalAudioSink](/zh-CN/api-reference/rtc/android/audio/audio-custom-capturenrendering#api_irtcengine_setexternalaudiosink) 并设置 `enabled` 为 true，以启用外部音频渲染。

:::note
注： `pullPlaybackAudioFrame` 方法和 [onPlaybackAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-raw#callback_iaudioframeobserver_onplaybackaudioframe) 回调都可用于获取远端混音后的音频数据。启用外部音频渲染（调用 [setExternalAudioSink](/zh-CN/api-reference/rtc/android/audio/audio-custom-capturenrendering#api_irtcengine_setexternalaudiosink)）后，无法再通过 [onPlaybackAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-raw#callback_iaudioframeobserver_onplaybackaudioframe) 回调获取数据。请根据实际业务需求选择使用 `pullPlaybackAudioFrame` 方法或 [onPlaybackAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-raw#callback_iaudioframeobserver_onplaybackaudioframe) 回调。两者区别如下：

- 调用 `pullPlaybackAudioFrame` 方法后，App 会自动从 SDK 拉取音频数据。通过设置音频数据参数，SDK 会调整帧缓冲区以帮助 App 处理延迟，有效避免音频播放抖动。
- 注册 [onPlaybackAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-raw#callback_iaudioframeobserver_onplaybackaudioframe) 回调后，SDK 会通过回调将音频数据发送给 App。若处理音频帧存在延迟，可能会导致音频抖动。

该方法仅用于获取远端混音后的音频数据。如需获取采集、播放等其他音频处理阶段的数据，可通过调用 [registerAudioFrameObserver](/zh-CN/api-reference/rtc/android/audio/audio-raw#api_irtcengine_registeraudioframeobserver) 注册相应的回调。
:::

<a id="api_irtcengine_pullaudioframe__timing"></a>

## pullPlaybackAudioFrame [2/2]

拉取远端音频数据。

<a id="api_irtcengine_pullaudioframe2__prototype"></a>

```text
public abstract int pullPlaybackAudioFrame(ByteBuffer data, int lengthInByte);
```

<a id="api_irtcengine_pullaudioframe2__detailed_desc"></a>

在调用该方法之前，你需要调用 [setExternalAudioSink](/zh-CN/api-reference/rtc/android/audio/audio-custom-capturenrendering#api_irtcengine_setexternalaudiosink) 方法，并将 `enabled` 设置为 true，以启用并设置外部音频播放。调用该方法成功后，App 会拉取解码并混音后的音频数据用于播放。

:::note
注：

- 该方法需要在加入频道后调用。
- 该方法与 [onPlaybackAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-raw#callback_iaudioframeobserver_onplaybackaudioframe) 回调的区别如下：

  - [onPlaybackAudioFrame](/zh-CN/api-reference/rtc/android/audio/audio-raw#callback_iaudioframeobserver_onplaybackaudioframe)：SDK 通过该回调将音频数据发送给 App。若 App 处理音频帧存在延迟，可能会导致音频抖动。
  - `pullPlaybackAudioFrame`：App 主动拉取远端音频数据。设置音频参数后，SDK 会调整帧缓冲区，避免外部音频播放中因抖动引发的问题。
:::
