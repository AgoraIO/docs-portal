## DisableVideo

关闭视频模块。

<a id="api_irtcengine_disablevideo__prototype"></a>

```csharp
public abstract int DisableVideo();
```

<a id="api_irtcengine_disablevideo__detailed_desc"></a>

该方法用于关闭视频模块。

:::info[注]
- 该方法设置的是内部引擎为禁用状态，在离开频道后仍然有效。
- 调用该方法会重置整个引擎，响应时间较慢。你可以根据实际需求用以下方法来独立控制视频模块的某一项功能：

  - [EnableLocalVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablelocalvideo): 是否启动摄像头采集并创建本地视频流。
  - [MuteLocalVideoStream](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_mutelocalvideostream): 是否发布本地视频流。
  - [MuteRemoteVideoStream](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_muteremotevideostream): 是否接收并播放远端视频流。
  - [MuteAllRemoteVideoStreams](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_muteallremotevideostreams): 是否接收并播放所有远端视频流。
:::

<a id="api_irtcengine_disablevideo__timing"></a>

### 调用时机

加入频道前后均可调用：

- 如果在加入频道前调用，则开启纯音频模式。
- 如果在加入频道后调用，则由视频模式切换为纯音频模式，然后再调用 [EnableVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablevideo) 方法可开启视频模式。

<a id="api_irtcengine_disablevideo__related"></a>

### 相关回调

成功调用该方法后，远端会触发 [OnUserEnableVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#callback_irtcengineeventhandler_onuserenablevideo) (false) 回调。

<a id="api_irtcengine_disablevideo__return_values"></a>

### 返回值

- 0: 方法调用成功。
- &lt; 0: 方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/unity/error-code)了解详情和解决建议。

- [IRtcEngine](/zh-CN/api-reference/rtc/unity/rtc-interface-class#class_irtcengine)

## EnableLocalVideo

开关本地视频采集。

<a id="api_irtcengine_enablelocalvideo__prototype"></a>

```csharp
public abstract int EnableLocalVideo(bool enabled);
```

<a id="api_irtcengine_enablelocalvideo__detailed_desc"></a>

该方法禁用或重新启用本地视频采集，不影响接收远端视频。 调用 [EnableVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablevideo) 后，本地视频采集即默认开启。 如果你在频道内调用 [EnableLocalVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablelocalvideo) (false) 关闭本地视频采集，也会同时停止在频道内发布视频流。如果想要重新开启，则可调用 [EnableLocalVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablelocalvideo) (true)，然后调用 [UpdateChannelMediaOptions](/zh-CN/api-reference/rtc/unity/channel#api_irtcengine_updatechannelmediaoptions) 并设置 `options` 参数，将本地采集的视频流发布到频道中。 成功禁用或启用本地视频采集后，远端会触发 [OnRemoteVideoStateChanged](/zh-CN/api-reference/rtc/unity/video/video-basic#callback_irtcengineeventhandler_onremotevideostatechanged) 回调。

:::info[注]
- 该方法在加入频道前后均可调用，但加入频道前调用的设置，在加入频道后才会生效。
- 该方法设置内部引擎为启用状态，在离开频道后仍然有效。
:::

<a id="api_irtcengine_enablelocalvideo__parameters"></a>

### 参数

#### `enabled`

是否开启本地视频采集。

- true:（默认）开启本地视频采集。
- false: 关闭本地视频采集。关闭后，远端用户会接收不到本地用户的视频流；但本地用户依然可以接收远端用户的视频流。设置为 false 时，该方法不需要本地有摄像头。

<a id="api_irtcengine_enablelocalvideo__return_values"></a>

### 返回值

- 0: 方法调用成功。
- &lt; 0: 方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/unity/error-code)了解详情和解决建议。

- [IRtcEngine](/zh-CN/api-reference/rtc/unity/rtc-interface-class#class_irtcengine)

- 调用该方法会重置整个引擎，响应时间较慢。你可以根据实际需求用以下方法来独立控制视频模块的某一项功能：

  - [EnableLocalVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablelocalvideo): 是否启动摄像头采集并创建本地视频流。
  - [MuteLocalVideoStream](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_mutelocalvideostream): 是否发布本地视频流。
  - [MuteRemoteVideoStream](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_muteremotevideostream): 是否接收并播放远端视频流。
  - [MuteAllRemoteVideoStreams](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_muteallremotevideostreams): 是否接收并播放所有远端视频流。
- 在频道内调用该方法时，会重置 [EnableLocalVideo](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_enablelocalvideo)、 [MuteRemoteVideoStream](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_muteremotevideostream) 和 [MuteAllRemoteVideoStreams](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_muteallremotevideostreams) 的设置，需谨慎使用。
:::

<a id="api_irtcengine_enablevideo__timing"></a>

### 调用时机

- 如果在加入频道前调用，则开启视频模块。

<a id="api_irtcengine_setvideoencoderconfiguration__prototype"></a>

```csharp

```

<a id="api_irtcengine_setvideoencoderconfiguration__detailed_desc"></a>

## SetVideoScenario

设置视频业务场景。

<a id="api_irtcengine_setvideoscenario__prototype"></a>

```csharp
public abstract int SetVideoScenario(VIDEO_APPLICATION_SCENARIO_TYPE scenarioType);
```

<a id="api_irtcengine_setvideoscenario__detailed_desc"></a>

成功调用该方法设置视频业务场景后，SDK 会基于指定场景启用最佳实践策略，自动调整关键性能指标，进而优化视频体验质量。

:::info[注]
该方法需要在加入频道前调用。
:::

<a id="api_irtcengine_setvideoscenario__parameters"></a>

### 参数

#### `scenarioType`

视频业务场景。详见 [VIDEO_APPLICATION_SCENARIO_TYPE](/zh-CN/api-reference/rtc/unity/enum-videoapplicationscenariotype)。 `APPLICATION_SCENARIO_MEETING` (1) 适用于会议场景。如果用户已调用 [SetDualStreamMode [2/2]](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_setdualstreammode2) 将小流设置为始终不发送 (`DISABLE_SIMULCAST_STREAM`)，会议场景对小流的动态开关不生效。 该枚举值仅适用于主播 vs 主播场景。SDK 会针对该场景启用以下策略：

- 针对会议场景对小流码率要求较高的情况，自动启用多项抗弱网技术，提升小流的抗弱网能力，确保多路流订阅时接收端的流畅性。
- 实时监测接收端大流的订阅人数，根据订阅人数动态调节大流配置：

  - 无人订阅大流时，会自动降低大流的码率和帧率，节省上行带宽和消耗。
  - 有人订阅大流时，大流会重置为用户最近一次调用 [SetVideoEncoderConfiguration](/zh-CN/api-reference/rtc/unity/video/video-basic#api_irtcengine_setvideoencoderconfiguration) 时的 [VideoEncoderConfiguration](/zh-CN/api-reference/rtc/unity/class-videoencoderconfiguration) 配置。如果用户此前没有进行设置，则使用如下值：

    - 视频分辨率：桌面端为 1280 × 720；移动端为 960 × 540
    - 视频帧率：15 fps
    - 码率：桌面端为 1600 Kbps；移动端为 1000 Kbps
- 实时监测接收端小流的订阅人数，根据订阅人数动态开启和关闭小流：

  - 无人订阅小流时，自动关闭小流，节省上行带宽和消耗。
  - 有人订阅小流时，开启小流并重置为用户最近一次调用 [SetDualStreamMode [2/2]](/zh-CN/api-reference/rtc/unity/publishnsubscribe#api_irtcengine_setdualstreammode2) 时的 [SimulcastStreamConfig](/zh-CN/api-reference/rtc/unity/class-simulcaststreamconfig) 配置。如果用户此前没有进行设置，则使用如下值：

    - 视频分辨率：480 × 272
    - 视频帧率：15 fps
    - 码率：500 Kbps

`APPLICATION_SCENARIO_1V1` (2) 适用于[视频 1v1 通话](https://doc.shengwang.cn/doc/one-to-one-live/android/rtm/overview/product-overview)场景。针对该场景低延迟、高画质的体验要求，SDK 进行了策略调优，提升了画质、首帧出图、中低端机延迟及弱网流畅度等性能表现。 `APPLICATION_SCENARIO_LIVESHOW` (3) 适用于[秀场直播](https://doc.shengwang.cn/doc/showroom/android/overview/product-overview)场景。针对该场景对首帧出图时间和画质清晰度的高要求，SDK 进行了策略调优，例如，默认开启音视频帧加速渲染来提升首帧出图体验，无需再额外调用 [EnableInstantMediaRendering](/zh-CN/api-reference/rtc/unity/video/video-rendering#api_irtcengine_enableinstantmediarendering)，同时会默认开启 B 帧来确保较高的图像质量、提高传输效率。此外，也增强了在弱网环境和低端设备上的画质和流畅度表现。

<a id="api_irtcengine_setvideoscenario__return_values"></a>

### 返回值

- 0: 方法调用成功。
- &lt; 0: 方法调用失败。详见[错误码](https://doc.shengwang.cn/api-ref/rtc/unity/error-code)了解详情和解决建议。

  - -1：一般性的错误（未明确归类）。
  - -4：不支持设置视频业务场景。可能的原因是当前使用的是音频 SDK。
  - -7： [IRtcEngine](/zh-CN/api-reference/rtc/unity/rtc-interface-class#class_irtcengine) 对象尚未初始化。你需要在调用该方法前成功初始化 [IRtcEngine](/zh-CN/api-reference/rtc/unity/rtc-interface-class#class_irtcengine) 对象。

- [IRtcEngine](/zh-CN/api-reference/rtc/unity/rtc-interface-class#class_irtcengine)

## OnLocalVideoStateChanged

本地视频状态发生改变回调。

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__prototype"></a>

```csharp
public virtual void OnLocalVideoStateChanged(VIDEO_SOURCE_TYPE source, LOCAL_VIDEO_STREAM_STATE state, LOCAL_VIDEO_STREAM_REASON reason)
```

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__detailed_desc"></a>

本地视频的状态发生改变时，SDK 会触发该回调，报告当前的本地视频状态以及状态改变的原因。

:::info[注]
- 帧重复检测仅针对分辨率大于 200 × 200、帧率大于等于 10 fps、码率小于 20 Kbps 的视频帧。
- 如果视频采集出现异常，正常情况下可以通过该回调的 `reason` 参数来排查问题。但在部分设备上，采集出现问题时（如卡死） Android 系统不会抛出任何错误回调，因此 SDK 无法报告本地视频状态改变的原因，此时你可以通过下列方式来判断采集是否无帧：该回调报告 `state` 为 `LOCAL_VIDEO_STREAM_STATE_CAPTURING` 或 `LOCAL_VIDEO_STREAM_STATE_ENCODING`，且 [OnLocalVideoStats](/zh-CN/api-reference/rtc/unity/video/video-basic#callback_irtcengineeventhandler_onlocalvideostats) 回调的 `captureFrameRate` 为 0。
:::

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__timing"></a>

### 触发时机

- SDK 会在如下情况触发该回调，且 `state` 为 LOCAL_VIDEO_STREAM_STATE_FAILED， `reason` 为 `LOCAL_VIDEO_STREAM_REASON_CAPTURE_FAILURE`：

  - 应用退到后台，系统回收摄像头。
  - Android 9 及以上版本，App 切后台一段时间后，系统会收回相机权限。
  - Android 6 及以上版本，如果相机被第三方应用占用一段时间后释放，则 SDK 会触发该回调，并报告 [OnLocalVideoStateChanged](/zh-CN/api-reference/rtc/unity/video/video-basic#callback_irtcengineeventhandler_onlocalvideostatechanged) (`LOCAL_VIDEO_STREAM_STATE_CAPTURING，LOCAL_VIDEO_STREAM_REASON_OK`) 回调。
  - 摄像头正常启动，但连续 4 秒都没有输出采集的视频。
- 当摄像头输出采集的视频帧时，如果 SDK 检测到连续 15 个重复的视频帧，会触发该回调，且 `state` 为 `LOCAL_VIDEO_STREAM_STATE_CAPTURING`， `reason` 为 `LOCAL_VIDEO_STREAM_REASON_CAPTURE_FAILURE`。

<a id="callback_irtcengineeventhandler_onlocalvideostatechanged__parameters"></a>

### 参数

#### `source`

视频源的类型。详见 [VIDEO_SOURCE_TYPE](/zh-CN/api-reference/rtc/unity/enum-videosourcetype)。

#### `state`

本地视频状态，详见 [LOCAL_VIDEO_STREAM_STATE](/zh-CN/api-reference/rtc/unity/enum-localvideostreamstate)。

#### `reason`

本地视频状态改变原因，详见 [LOCAL_VIDEO_STREAM_REASON](/zh-CN/api-reference/rtc/unity/enum-localvideostreamreason)。

视频源的类型。详见 [VIDEO_SOURCE_TYPE](/zh-CN/api-reference/rtc/unity/enum-videosourcetype)。

#### `uid`

图像尺寸和旋转信息发生变化的用户 ID（本地用户的 `uid` 为 0。此时视频为本地用户的视频预览）。

#### `width`

视频流的宽度（像素）。

#### `height`

视频流的高度（像素）。

#### `rotation`

旋转信息，取值范围 [0,360)。

:::info[注]
在 iOS 平台上，该参数值始终为 0。
:::
