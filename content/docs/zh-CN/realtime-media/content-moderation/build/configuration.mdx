本文介绍内容审核接入时的关键配置项，帮助你在开始联调前确定业务字段、回调地址和业务关联方式。

## 先理解两类配置入口

- 视频审核：推荐通过 SDK 的 `extraInfo` 透传业务上下文。
- 音频审核：推荐在调用 `/start` 接口时，通过 `serviceParam` 中的业务字段和回调地址完成关联配置。

如果你的业务同时使用音频审核和视频审核，建议提前设计一套统一的房间、用户和业务上下文字段，便于后续在回调侧做统一关联和处置。

## 视频审核透传字段

视频审核推荐通过 SDK 的 `extraInfo` 透传业务上下文。`extraInfo` 按 SDK 定义是字符串类型；如果需要传递结构化数据，建议先序列化为 JSON 字符串。

推荐至少包含以下字段：

- `cname`：频道名，用于关联具体房间或会话。
- `uid`：发流用户 ID，用于定位触发审核的用户。
- `clientInfo`：业务自定义信息，例如房间类型、主播身份、活动标签、风控策略版本或工单号。

示例：

```json
{"cname":"428743","uid":"996","clientInfo":"dic"}
```

## 音频审核透传字段

音频审核通常在调用 `/start` 接口时，通过 `serviceParam` 中的业务字段与回调参数完成业务关联。建议重点规划以下字段：

- `dataId`：每次送审数据的唯一标识，便于定位具体审核记录。
- `roomNo`：房间号，便于在回调侧快速关联业务房间。
- `callback`：建议放入可唯一定位本次请求的业务标识。
- `extension`：自定义扩展参数，建议使用 JSON 字符串承载主播 ID、场次 ID、风控策略版本等业务字段。

建议让 `extension` 与视频审核中的 `extraInfo` 尽量承载相同的核心业务信息，便于在服务端统一处理音频审核与视频审核的回调结果。

## 回调地址要求

建议将内容审核回调地址配置为稳定、可监控、可重试的服务端接口，并满足以下要求：

- 能正常接收审核厂商的 HTTP 回调。
- 支持验签和幂等处理。
- 能根据透传字段准确关联到业务记录。
- 能根据审核结果继续执行提醒、禁言、断播、复核或处罚等后续动作。

## 推荐配置顺序

建议按以下顺序准备内容审核配置：

1. 先统一房间 ID、用户 ID 和业务标识的命名方式。
2. 再分别设计视频审核的 `extraInfo` 和音频审核的 `extension` 字段内容。
3. 最后配置回调地址，并在联调阶段验证透传字段是否能准确映射到业务记录。

更偏联调和排障层面的推荐做法，请参考[内容审核最佳实践](/zh-CN/realtime-media/content-moderation/build/best-practices)。
