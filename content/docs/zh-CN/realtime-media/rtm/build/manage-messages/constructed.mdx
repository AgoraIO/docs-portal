消息负载的结构应该具备易读性和可扩展性，以减少程序的构建和维护成本，以及在未来版本升级时新老版本可以更容易地兼容。

于通过 RTM 发送的消息只能为字符串（String）或二进制（Binary）类型，RTM 无法直接提供可解析、可扩展的消息数据结构。但你可以根据业务需求自行构建结构化消息负载，并使用 `customType` 参数来标识和解析它。

你在业务流程中可能会涉及到以下类型的消息：

- **纯文本消息**
- **文本消息**：包含有图片、文件等附件的 URL。
- **视频文件消息**：包含文本说明、视频地址和缩略图地址等。
- **问卷调查、答题消息**：可能包含预先设置的答案选项。
- **邀请消息**：例如邀请其他用户参加私聊或者群聊。
- **信令消息**：例如发起视频或音频聊天的邀请指令。
- **指令消息**：例如平行驾驶或者 IoT 应用中向设备下发控制指令消息或传感器上传的设备状态消息。
- **状态同步消息**：例如元宇宙或游戏中玩家的位置、视角或当前状态消息。

假设你收到以下三条消息负载：

- `"This is a Message!"`
- `{ message: "https://cdn.agora.io/assets/avatar.png"}`
- `{ message: { x =1 0, y = 100, z = 55 } }`

当你收到这些消息负载时，你很难快速判断这是一条带有图片地址的消息或是一条包含位置信息的消息。即便可以扫描所有消息，检查文本中是否包含 `jpg` 字符串或含有 `x,y,z` 字符，这个方法也会随着 App 用户和消息类型的增加而变得困难。

为了解决这类问题，你可以在消息负载结构中引入预定义的字段，通过结构化消息负载增加可解析性和扩展性。例如，在上面的例子中，我们在消息结构中引入 `type` 字段，改动如下：

| 原消息结构                                             | 结构化消息结构                                                   |
| --------------- | -------- |
| `"Hello, This is a Message!"`                          | `{type: "text", message: "Hello, This is a Message!"}`           |
| `{message: "https://cdn.agora.io/assets/avatar.png"} ` | `{type: "image", url: "https://cdn.agora.io/assets/avatar.png"}` |
| `{message: { x =1 0, y = 100, z = 55 }}`               | `{type: "position", coordinate: { x: 10, y: 100, z: 55 }}`       |

现在你可以根据接收到消息负载中的 `type` 字段来解析消息格式和数据，并对不同消息类型进行不同的处理。你也可以充分利用 `message.publish` 方法中的 `customType` 字段将你自定义的附加信息随着消息一起发送给接收端。用户接收到 Message Event 后可以通过 `customType` 字段来解析出数据。详见：[消息负载序列化](/zh-CN/realtime-media/rtm/build/manage-messages/serialized)。

```javascript tab="JavaScript" tabGroup="rtm-build-manage-messages-constructed-1" showLineNumbers
// Define message structure
const message = {
    type: "image",
    asset_url: "https://my.app/image.png",
    thumb_url: "https://my.app/thumbnail/image.png",
    mentionedUsers: ["Tony","Lily"],
    sender: "Max"
}
// Message string serialization
const payload = JSON.stringify(message);
// Send message with customType set
try {
    const result = await rtm.publish( "my_channel", payload, {customType : "image", channelType: "MESSAGE"} );
    console.log(result);
} catch (status) {
    console.log(status);
}
// When receiving a message, use the custom Type field to parse the message type。
// Handle message event
rtm.addEventListener("message", event => {
    if (event.customType === "image" ) {
        console.log("It is a image message!");
        const message = JSON.parse(event.message);
    }
});
```

```typescript tab="TypeScript" tabGroup="rtm-build-manage-messages-constructed-1"
import { PublishOptions, RtmChannelType, MessageEvent } from '@shengwang/rtm-full';
import { RtmError } from '@shengwang/rtm-full';

// Define message structure interface
interface ImageMessage {
  type: string;
  asset_url: string;
  thumb_url: string;
  mentionedUsers: string[];
  sender: string;
}

// Define message structure
const message: ImageMessage = {
    type: "image",
    asset_url: "https://my.app/image.png",
    thumb_url: "https://my.app/thumbnail/image.png",
    mentionedUsers: ["Tony", "Lily"],
    sender: "Max"
};

// Message string serialization
const payload = JSON.stringify(message);

// Send message with customType set
const options: PublishOptions = {
  channelType: RtmChannelType.MESSAGE,
  customType: "image"
};

try {
  const response = await rtmClient.publish("my_channel", payload, options);
  console.log("Publish message success:", response);
} catch (error) {
  console.error("Publish message failed:", error);
  if (error instanceof RtmError) {
    console.error(`Publish failed: ${error.reason} (code: ${error.errorCode})`);
  }
}

// When receiving a message, use the customType field to parse the message type
rtmClient.addEventListener("message", (event: object) => {
  const msgEvent = event as MessageEvent;
  if (msgEvent.customType === "image") {
    console.log("It is an image message!");
    const messageData = JSON.parse(msgEvent.message as string) as ImageMessage;
    console.log("Image URL:", messageData.asset_url);
  }
});
```
