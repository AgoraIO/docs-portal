你可以使用 RTSA C SDK 在 Linux 平台上实现媒体流加速的功能。本页提供 RTSA C SDK 的发版说明。

## 1.9.7 版

该版本于 2025 年 11 月 27 日发布。

### 升级必看

#### 删除 audio_process_opt

该版本对 <glossary>3A</glossary> 模块进行了优化。主要接口变更如下：

- 从 [`rtc_channel_options_t`](/api-ref/rtsa/c/structrtc__channel__options__t.html) 中移除了 `audio_process_opt`，及其关联结构体 `rtc_audio_process_options_t`。
- 在 `rtc_channel_options_t` 中新增 `enable_audio_downlink_aec` 和 `enable_audio_downlink_aec_pcm_dump` 用于替代上述选项。

新的实现支持用户输入硬件回采信号，从而显著提高下行 <glossary>3A</glossary> 处理效果。如从旧版本升级，请确保同步更新相关集成逻辑。

#### 删除错误码 221 和 222

该版本删除了[错误码](/api-ref/rtsa/c/agora__rtc__api_8h#agora_err_code_e)中的 `ERR_AUDIO_DECODER_NOT_MATCH`(221) 和 `ERR_AUDIO_DECODER_NOT_ENABLE`(222)。

### 改进

#### 音频收发 Codec 解耦

该版本将音频的发送和接收编解码格式解耦，不再要求两者保持一致。相关接口更新为在 [`rtc_channel_options_t`](/api-ref/rtsa/c/structrtc__channel__options__t.html) 中添加了 `enable_audio_decode`，用于控制是否开启下行音频解码。

#### 音频模块改进

- 重构音频 Jitter Buffer 模块，新增支持处理任意时长的音频包；优化 Jitter 评估算法，提升音频播放效果；优化数据结构，提升整体性能。
- 重构音频 Mixer 模块，新增支持处理任意时长的音频包；优化混音逻辑，以改善混音效果。
- 优化下行接收缓冲队列的取包策略，并改进丢包场景下的停等机制，显著提升音频播放效果。
- 新增适用于支持对话式 AI 场景的下行音频快收模式。
- 优化 G722 解码器，降低因丢包引起的爆音问题。

### 问题修复

修复了视频 RTP 时间戳偶现错误的问题。

## 1.9.6 版

该版本于 2025 年 8 月 8 日发布。

### 升级必看

#### 代码更名

该版本对如下代码进行了更名。如果你由之前的版本升级到 v1.9.6 且集成过相应代码，请重新集成：

- 错误码 `ERR_RTM_EXCEED_TCP_SKB` (1006) 更名为 `ERR_RTM_EXCEED_SND_BUFFER` (1006)。
- 回调 `on_send_rtm_data_result` 更名为 [`on_rtm_send_data_result`](/api-ref/rtsa/c/structagora__rtm__handler__t#a15b2dba380611e1974686f74a3ec0ca7)。

#### 区域码清理

该版本对 [`area_code_e`](/api-ref/rtsa/c/agora__rtc__api_8h#area_code_e) 中不支持的区域进行了清理，并作为预览特性放置在 `area_code_ex_e` 中。声网对预览特性不做可用性保证。

清理后的 `area_code_e` 支持如下区域：

- `AREA_CODE_CN`: 中国大陆
- `AREA_CODE_NA`: 北美
- `AREA_CODE_EU`: 欧洲
- `AREA_CODE_AS`: 亚洲（除中国大陆）
- `AREA_CODE_JP`: 日本
- `AREA_CODE_IN`: 印度
- `AREA_CODE_GLOB`: （默认）全球。

### 新增特性

#### RTM 服务支持自研 AUT 传输

在之前的版本中，RTSA 的实时消息传输 (RTM) 服务采用 TCP 传输层。自该版本起，RTM 服务引入了声网自研的 AUT 传输层技术，显著提高了传输性能。具体改进如下：

- 连接稳定性大幅提升。与之前版本在 30% 丢包率下触发掉线相比，v1.9.6 版本即使在 70% 的丢包环境下仍能保持稳定连接。
- 抗丢包能力显著增强。相较于之前版本在 30% 丢包率时传输能力就会急剧下降，v1.9.6 版本可以在上行 70% 丢包率或者双向 60% 丢包率的极限网络环境下依然保持正常服务。

### 问题修复

该版本修复了如下问题：

- 与 RTC Web 端互通时，如果 Web 端频繁进行开启/停止发送音视频流的操作 (`mute`/`unmute`)，可能导致 RTSA 端无法接收媒体流。
- 在部分性能受限的设备上，系统定时器可能出现累计误差。
- 当频繁调整 RTSA 运行设备的系统时间时，移动接收端可能出现视频画面卡顿现象。
- 在特定网络环境下（MTU 值较小），使用 RDT 传输大型帧数据时可能发生接收失败的问题。

## 1.9.5 版

该版本于 2025 年 3 月 21 日发布。

### 新增特性

#### String 型 UID 功能

该版本新增 String 型 UID 功能，支持用户使用 String 型的 User Account 加入频道实现互通。相关 API 包括：

- [`agora_rtc_join_channel_with_user_account`](/api-ref/rtsa/c/agora__rtc__api_8h#a64a24029bfaa5408e987122261385013)：使用 User Account 加入频道
- [`agora_rtc_get_user_info_by_user_account`](/api-ref/rtsa/c/agora__rtc__api_8h#a68efcfa431803942c8fdc733b00c30c1)：通过 User Account 获取远端用户信息
- [`agora_rtc_get_user_info_by_uid`](/api-ref/rtsa/c/agora__rtc__api_8h#ad6b1be785d6c2b4fa8fb0eac90290194)：通过 UID 获取远端用户信息
- [`on_user_info_updated`](/api-ref/rtsa/c/structagora__rtc__event__handler__t#a4c8f017cc2fa8aaa6e91c966b97a8aee)：远端用户信息变更回调
- [`on_user_joined_with_user_account`](/api-ref/rtsa/c/structagora__rtc__event__handler__t#aa57af03ef9f26ab68917fa7a30f703bd)：远端用户使用 User Account 加入频道回调
- [`on_user_offline_with_user_account`](/api-ref/rtsa/c/structagora__rtc__event__handler__t#af3a7f207010bafca7aa99fdba5a9b1ab)：使用 User Account 的场景下，远端用户离开频道回调

详细实现步骤和开发注意事项可以参考[使用 String 型 UID](/zh-CN/realtime-media/rtsa/advanced-features/string-uid)。

:::warning[注意]
使用 String 型 UID 首次加入频道时会略有延迟。我们更建议使用 Int 型 UID 实现相关功能。
:::

#### 数据流 (Data Stream) 消息

为方便用户在频道内以广播的形式发送消息，该版本新增数据流功能。相关 API 包括：

- [`agora_rtc_create_data_stream`](/api-ref/rtsa/c/agora__rtc__api_8h#aa6b288b479c7048b4cceb85d995771ed)：创建数据流
- [`agora_rtc_send_stream_message`](/api-ref/rtsa/c/agora__rtc__api_8h#aee89fa14447b4529d45275afe5b5a86f)：发送数据流消息
- [`on_stream_message`](/api-ref/rtsa/c/structagora__rtc__event__handler__t#a7c73b2bb0558e2b695d8838ee542c87a)：收到远端用户发送的数据流消息回调

详细实现步骤和开发注意事项可以参考[发送和接收数据流 (Data Stream)](/zh-CN/realtime-media/rtsa/advanced-features/data-stream)。

#### 媒体控制信息

为方便用户向指定频道或所有频道内的用户发送消息，该版本新增媒体控制信息功能。相关 API 包括：

- [`agora_rtc_send_media_ctrl_msg`](/api-ref/rtsa/c/agora__rtc__api_8h#a83dd3f91afbae5d54548c4d8e546aafc)：发送媒体控制信息
- [`on_media_ctrl_msg`](/api-ref/rtsa/c/structagora__rtc__event__handler__t#ab0a6462ac391a960f767d2cf6ce8078a)：收到远端用户发送的媒体控制信息回调

### 问题修复

该版本修复了如下问题：

- 调用 `agora_rtc_logout_rtm` 后迅速调用 `agora_rtc_login_rtm` 时，因为状态竞争可能导致后者调用失败。
- 当 `rtc_channel_options_t.audio_codec_opt.pcm_channel_num` 被设置为非法的 0 时，会出现崩溃。
- 发送 Jpeg 文件时 FEC 包错误。
- 调用 `agora_rtc_init` 后快速调用 `agora_rtc_fini` 时偶现崩溃。

## 1.9.4 版

该版本于 2025 年 1 月 9 日发布。

### 新增特性

#### RDT 功能开关

该版本在 `rtc_channel_options_t` 中新增 `enable_rdt` 参数，用来设置是否在加入 RTC 频道时开关 RDT 数据通道功能。原来的 `auto_connect_rdt` 参数转为私有参数控制，默认为 `true`。

该版本还新增对 RDT 数据通道的加密支持。

#### 私参配置支持多频道

该版本在 `agora_rtc_set_params` 接口中增加 `conn_id` 参数，用来对指定 Connection 进行私有参数配置。

#### 支持 IPV6

该版本新增支持 IPV6。有 IPV4 和 IPV6 时， SDK 会根据实际情况自动选择 IPV6 或 IPV4，无需额外设置。

#### RTM 消息状态

该版本增加 `RTM_MSG_STATE_TIMEOUT` 消息状态，用来表示服务端 10 秒内没有响应，SDK 会删除这条未知状态的消息。你可以对用户进行提醒，如果觉得这条消息重要，需要重新发送该消息。

### 改进

#### 规整错误码

为提升 SDK 易用性，该版本对错误码进行了规整。API 调用时返回的错误和 `on_error` 回调中报告的错误都收口进了 `agora_err_code_e` 中，并细分为通用、RTN、音频、视频、RDT、RTM 模块，方便开发者快速定位问题。你可以在 [API 参考](/api-ref/rtsa/c/agora__rtc__api_8h#agora_err_code_e)或[错误码文档](/zh-CN/realtime-media/rtsa/error-codes)中了解详情。

在之前的版本中，API 调用时返回的错误没有对外开放，开发者需要调用 `agora_rtc_err2str` 才能获取描述信息。你可以参考最新的 API 代码调整相关逻辑。

#### 细化 RTM 离线状态原因

该版本对 `rtm_event_type_e` 中用户 RTM 离线的原因进行了细化。当 RTM 事件类型为 `RTM_EVENT_TYPE_EXIT` 时，可能的原因有：

- `ERR_RTM_SERVER_TIMEOUT`：服务器没有收到我发的心跳包
- `ERR_RTM_LOCAL_INTERRUPT`：本地用户网络中断
- `ERR_RTM_LOCAL_TIMEOUT`：本地用户没收到服务端响应的心跳包
- `ERR_RTM_LOCAL_NETDOWN`：检测到网卡出现故障

该改动更好地区分了 RTM 离线事件 `rtm_event_type_e` 的类别，方便用户对事件进行响应：

- `RTM_EVENT_TYPE_LOGIN`(0)：如果对应的事件码是 `ERR_RTM_OK`(0)，表示成功登录 RTM 服务。否则登录失败，也不可恢复。
- `RTM_EVENT_TYPE_KICKOFF`(1)：由于 UID 重复被踢出频道，也不可恢复。
- `RTM_EVENT_TYPE_EXIT`(2)：中断退出，可以自动恢复。

#### 其它改进

该版本还进行了如下改进：

- 优化了物联网卡的连接逻辑，减少连接失败概率，提升连接速度。
- 提升弱网下更新 Token 的可靠性，防止丢包过高导致操作失败。
- 优化了加入频道的速度。
- 优化了弱网下视频的流畅度。
- 降低了 CPU 的占有率。

### 问题修复

该版本修复了如下问题：

- 由于视频包重传次数限制逻辑错误，导致重传包发送过少。
- 视频发送 Pacer 逻辑错误，导致 Pacer 缓冲区满时只能发送 I 帧。
- 音频混音模块和物联网卡连接模块的两处内存泄露。
- 在加入频道前进行 mute/unmute 远端用户的操作可能不生效。
- 弱网下进行 mute/unmute 远端用户的操作偶现失败。
- 修复多个 Connection 时，mute/unmute 针对指定连接进行操作时，会误将所有连接都设置的问题。
- 偶现加入频道后无法触发 `on_user_joined` 回调。
- 当 License 设置错误被服务器通知被 ban 时，SDK 触发错误回调后崩溃。
- 一端 `auto_connect_rdt` 为 `true`，另一端为 `false` 时，20 秒内非预期退出频道又加入，RDT 无法重建。
- 在纯 IPV6 网络下，发生网络切换时可能导致获取网络信息错误，从而无法加入频道。
- 丢包重传较多时网络 jitter 数据统计错误。
- 使用 RTM 服务时，`remote_id` 填写为 `NULL` 时，导致 `RTM` 连接工作异常，且 SDK 不会报错。现在会报错 `ERR_INVALID_PARAM`。
- `rtm_event_handler` 异步调用传递时没有深拷贝，可能导致的崩溃问题。
- 修复与小程序 RTC 和 RTM 的互通问题。

## 1.9.2 版

该版本于 2024 年 1 月 9 日发布。

### 新增特性

#### 基于 RDT 通道的消息传输

为满足文件传输、文件下载等业务场景对可靠性的要求，该版本支持通过可靠数据传输（Reliable Data Transmission，以下简称 RDT）通道传输控制消息 (`RDT_STREAM_CMD`) 和数据消息 (`RDT_STREAM_DATA`)。配套新增的方法及回调如下：

- `agora_rtc_send_rdt_msg` 方法：通过 RDT 通道发送消息
- `agora_rtc_get_rdt_status_info` 方法：获取 RDT 通道的信息。
- `on_rdt_state` 回调：RDT 通道的连接状态已改变。
- `on_rdt_msg` 回调：在 RDT 通道中收到消息。

具体使用方法见[通过 RDT 通道发送消息](/zh-CN/realtime-media/rtsa/advanced-features/send-message-through-rdt-channel)。

#### 音频时长设置

该版本在 `audio_codec_option_t` 结构体中新增 `pcm_duration` 成员，用于设置音频时长，取值范围为 20 到 100 毫秒。该设置对任意格式的音频数据都有效。

### 改进

#### RTM 模块

该版本对 RTM 模块进行了如下改进：

- 优化了被踢出 RTM 系统后的行为：
  - 如果被踢出的原因是网络超时，则 SDK 会报告错误码 `ERR_RTM_NOTICE_INTERRUPT` 并尝试自动重连。
  - 如果被踢出的原因是有人使用相同用户 ID 登录 RTM 系统，则 SDK 会报告错误码 `ERR_RTM_NOTICE_KICKED_OUT`，你需要更换用户 ID 登录并保证用户 ID 的唯一性。
- 提升了 `agora_rtc_send_rtm_data` 方法的易用性：
  - 将 `msg_id` 参数由输出参数改为输入参数，你可以为每条消息设置唯一的消息 ID，且相同消息的 ID 不变，方便你在需要重传消息的时候快速定位到指定的消息。
  - 将 `msg_len` 参数的长度最大值由 32 KB 修改为 31 KB。之前版本的限制是协议头加消息的总长度至多为 32 KB，因为协议头长度不固定且用户无法获取，所以该版本将限制修改为消息长度至多为 31 KB，无需关心协议头长度。
  - 新增调用失败的错误码，你可以根据提示快速定位问题并解决：
    | 错误码 | 描述 |
    | --- | --- |
    | `RTM_ERR_NOT_LOGINED` | `-1001`：未登录 RTM 系统 |
    | `RTM_ERR_SEND_TO_SELF` | `-1002`：在 `rtm_uid` 参数中误填了自己的用户 ID。 |
    | `RTM_ERR_EXCEED_MSG_SIZE` | `-1003`：RTM 消息长度超出限制。消息长度至多为 31 KB。 |
    | `RTM_ERR_EXCEED_MSG_CNT` | `-1004`：发送频率超出限制。每秒至多发送 60 条消息。 |
    | `RTM_ERR_EXCEED_TCP_SKB` | `-1005`：消息通道已满。等待一秒后重新发送。 |

- 优化了保活机制，减少了掉线概率。
- 缩短了 RTM 的登录时间。

#### 下行回声消除

为提升回声消除效果并降低功耗，该版本在 `rtc_audio_process_options_t` 结构体中新增 `enable_downlink_aec` 成员，你可以通过该成员设置是否开启下行回声消除。声网推荐你使用下行回声消除 (`enable_downlink_aec`) 替代上行回声消除 (`enable_aec`)。

#### 音频编码格式

该版本支持采样率为 8000 Hz 的 AAC-LC 音频编码格式，你可以在发送音频帧时设置 `audio_data_type_e` 为 `AUDIO_DATA_TYPE_AACLC_8K`。

#### 混音数据回调

该版本解除了 `on_mixed_audio` 回调对 `on_audio_data` 回调的依赖，你无需监听 `on_audio_data` 回调，也可以正常接收 `on_mixed_audio` 回调。

### 问题修复

该版本修复了如下问题：

- H.265 视频数据的 FEC 功能解析异常。
- 特定场景下的视频卡顿。
- 调用 `agora_rtc_renew_token` 方法更新 Token 后，SDK 在加入频道时未使用新的 Token。

## 1.9.1 版

该版本于 2023 年 7 月 11 日发布。

### 升级必看

#### 视频帧率

为满足不同用户对视频帧率的需求，该版本将 `video_frame_info_t` 结构体中的 `frame_rate` 成员由枚举型修改为整型，你可以设置视频帧率为 [1,60] 间的任意整数。同时，该版本也删除了 `video_frame_rate_e` 枚举类中的所有枚举值。

### 新增特性

#### 媒体流加密

在安全要求高的场景中，为保证数据的保密性、完整性和真实性，提高数据加密的计算效率，该版本在 `rtc_channel_options_t` 结构体中新增 `crypto_opt` 成员并删除 `enable_aut_encryption` 成员。你可以在加入频道时通过 `crypto_opt` 设置是否开启媒体流加密、加密模式、密钥和盐。

:::warning[注意]
开启媒体流加密后，同一频道内的所有用户都必须使用相同的加密模式和密钥，包括服务端用户（例如声网录制服务）。
:::

#### 区域访问限定

该版本支持限定用户的访问区域为香港澳门、美国或俄罗斯，你可以在 `area_code_e` 枚举类中设置如下区域码：

- `AREA_CODE_HKMC`: 香港和澳门
- `AREA_CODE_US`: 美国
- `AREA_CODE_RU`: 俄罗斯

#### 音频编码格式

为方便在低性能设备中存储、传输、处理 AAC-LC 音频数据，该版本在 `audio_data_type_e` 枚举类中新增 `AUDIO_DATA_TYPE_AACLC_16K` 枚举，支持按照 16000 Hz 采样率对 AAC-LC 音频数据进行编码。

### 改进

#### SDK 连接状态与用户加入/离开频道回调

为更好地分辨 SDK 断连、重连的状态，更准确地报告远端用户加入和离开频道的状态，该版本新增 `on_reconnecting` 回调并对 `on_connection_lost`、 `on_user_joined` 和 `on_user_offline` 回调的行为进行如下改进：

| 回调 | v1.9.1 之前的触发场景 | v1.9.1 的触发场景 |

### 新增特性

#### Connection ID 机制

自该版本起，SDK 使用 Connection ID 机制连接 RTC 频道。一个 Connection 有唯一的 ID，每个 Connection 可以关联多个 RTC 频道。你可以通过操作 Connection ID 来影响相关的 RTC 频道。

SDK 将所有 `channel_name` 参数更新为 `connection_id` 参数（`agora_rtc_join_channel` 除外），并新增与 `connection_id` 相关的接口：

 - `agora_rtc_create_connection`：创建 Connection
 - `agora_rtc_destroy_connection`：销毁 Connection
 - `agora_rtc_get_connection_info`：获取 Connection 信息

Connection 通过 `agora_rtc_join_channel` 与 RTC 频道和用户 ID 进行绑定。在你调用 `agora_rtc_leave_channel` 之后，绑定结束。

你可以通过  Connection ID 机制实现多频道推流和单频道推多路流，详见[多频道发流和单频道多路发流](/zh-CN/realtime-media/rtsa/advanced-features/multi-channel)。

## 1.9.2 版

该版本于 2024 年 1 月 9 日发布。

### 新增特性

#### 基于 RDT 通道的消息传输

为满足文件传输、文件下载等业务场景对可靠性的要求，该版本支持通过可靠数据传输（Reliable Data Transmission，以下简称 RDT）通道传输控制消息 (`RDT_STREAM_CMD`) 和数据消息 (`RDT_STREAM_DATA`)。配套新增的方法及回调如下：

- `sendRdtMsg` 方法：通过 RDT 通道发送消息
- `getRdtStatusInfo` 方法：获取 RDT 通道的信息。
- `onRdtState` 回调：RDT 通道的连接状态已改变。
- `onRdtMsg` 回调：在 RDT 通道中收到消息。

具体使用方法见[通过 RDT 通道发送消息](/zh-CN/realtime-media/rtsa/advanced-features/send-message-through-rdt-channel)。

#### 音频时长设置

该版本在 `AudioCodecOption` 结构体中新增 `pcmDuration` 成员，用于设置音频时长，取值范围为 20 到 100 毫秒。该设置对任意格式的音频数据都有效。

### 改进

#### RTM 模块

该版本对 RTM 模块进行了如下改进：

- 优化了被踢出 RTM 系统后的行为：
  - 如果被踢出的原因是网络超时，则 SDK 会报告错误码 `ERR_RTM_NOTICE_INTERRUPT` 并尝试自动重连。
  - 如果被踢出的原因是有人使用相同用户 ID 登录 RTM 系统，则 SDK 会报告错误码 `ERR_RTM_NOTICE_KICKED_OUT`，你需要更换用户 ID 登录并保证用户 ID 的唯一性。
- 提升了 `sendRtm` 方法的易用性：
  - 将 `messageId` 参数由输出参数改为输入参数，你可以为每条消息设置唯一的消息 ID，且相同消息的 ID 不变，方便你在需要重传消息的时候快速定位到指定的消息。
  - 将消息长度最大值由 32 KB 修改为 31 KB。之前版本的限制是协议头加消息的总长度至多为 32 KB，因为协议头长度不固定且用户无法获取，所以该版本将限制修改为消息长度至多为 31 KB，无需关心协议头长度。
  - 新增调用失败的错误码，你可以根据提示快速定位问题并解决：
    | 错误码 | 描述 |
    | --- | --- |
    | `RTM_ERR_NOT_LOGINED` | `-1001`：未登录 RTM 系统 |
    | `RTM_ERR_SEND_TO_SELF` | `-1002`：在 `rtmUid` 参数中误填了自己的用户 ID。 |
    | `RTM_ERR_EXCEED_MSG_SIZE` | `-1003`：RTM 消息长度超出限制。消息长度至多为 31 KB。 |
    | `RTM_ERR_EXCEED_MSG_CNT` | `-1004`：发送频率超出限制。每秒至多发送 60 条消息。 |
    | `RTM_ERR_EXCEED_TCP_SKB` | `-1005`：消息通道已满。等待一秒后重新发送。 |

- 优化了保活机制，减少了掉线概率。
- 缩短了 RTM 的登录时间。

#### 下行回声消除

为提升回声消除效果并降低功耗，该版本在 `RtcAudioProcessOption` 结构体中新增 `enableDownlinkAec` 成员，你可以通过该成员设置是否开启下行回声消除。声网推荐你使用下行回声消除 (`enableDownlinkAec`) 替代上行回声消除 (`enableAec`)。

#### 音频编码格式

该版本支持采样率为 8000 Hz 的 AAC-LC 音频编码格式，你可以在发送音频帧时设置 `AudioDataType` 为 `AUDIO_DATA_TYPE_AACLC_8K`。

#### 混音数据回调

该版本解除了 `onMixedAudioData` 回调对 `onAudioData` 回调的依赖，你无需监听`onAudioData` 回调也可以正常接收 `onMixedAudioData` 回调。

### 问题修复

该版本修复了如下问题：

- H.265 视频数据的 FEC 功能解析异常。
- 特定场景下的视频卡顿。
- 调用 `renewToken` 方法更新 Token 后，SDK 在加入频道时未使用新的 Token。

## 1.9.1 版

### 升级必看

#### 视频帧率

为满足不同用户对视频帧率的需求，该版本将 `video_frame_info_t` 结构体中的 `frame_rate` 成员由枚举型修改为整型，你可以设置视频帧率为 [1,60] 间的任意整数。同时，该版本也删除了 `video_frame_rate_e` 枚举类中的所有枚举值。

#### 媒体流加密

在安全要求高的场景中，为保证数据的保密性、完整性和真实性，提高数据加密的计算效率，该版本在 `rtc_channel_options_t` 结构体中新增 `crypto_opt` 成员并删除 `enable_aut_encryption` 成员。你可以在加入频道时通过 `crypto_opt` 设置是否开启媒体流加密、加密模式、密钥和盐。

:::warning[注意]
开启媒体流加密后，同一频道内的所有用户都必须使用相同的加密模式和密钥，包括服务端用户（例如声网录制服务）。
:::

#### 区域访问限定

该版本支持限定用户的访问区域为香港澳门、美国或俄罗斯，你可以在 `area_code_e` 枚举类中设置如下区域码：

- `AREA_CODE_HKMC`: 香港和澳门
- `AREA_CODE_US`: 美国
- `AREA_CODE_RU`: 俄罗斯

#### 音频编码格式
