---
title: "响应状态码"
description: "查询旁路推流的响应状态码、错误码含义、常见原因和处理建议。"
---
在调用旁路推流 API 过程中，你可能收到如下 HTTP 响应状态码：

- 如果 HTTP 状态码为 2XX，则请求成功。

- 如果 HTTP 状态码不为 2XX，则请求失败。你可以根据对应的响应体中可能出现的 `message` 以及 `reason` 字段排查问题。

例如，请求失败时，你可能收到如下响应：

```json
# 400 Bad Request
# 仅有 message
{
  "message": "appid is invalid"
}
```

```json
# 403 Forbidden
# 仅有 reason
{
  "reason": "No invalid permission to use this function. Contact us."
}
```

| 状态码 | 可能的 `message` 或 `reason` 字段内容 | 原因 | 建议措施 |
| --- | --- | --- | --- |
| `200 OK` | 无该字段。 | 创建成功。 | 无需处理。 |
| `400 Bad Request` | <Slot name="response-code-markdown-0-2-1" /> | 请求参数错误。 | 参考 HTTP 响应 Body 中的 `message` 或 `reason` 字段进行排查。 |
| `401 Unauthorized` | Invalid authentication credentials. | RESTful API 鉴权失败。 | 重新进行 [HTTP 基本认证](/zh-CN/realtime-media/media-push/build/setup-and-access/http-basic-auth)。 |
| `403 Forbidden` | No valid permission to use this function. Contact us. | 未开通服务。 | 开通[旁路推流服务](/zh-CN/realtime-media/media-push/build/setup-and-access/enable-service#开通旁路推流服务)。 |
| `404 Not Found` | Resource is not found and destroyed. | 并未成功启动推流任务、启动任务后中途退出、自动迁移中、正在销毁 Converter。 | 使用[退避策略重试](/zh-CN/realtime-media/media-push/build/optimize-and-operate/rest-availability#使用退避策略重试)。 |
| `409 Conflict` | Resource with the same name has already existed. Use the existing resource, otherwise delete it and create a new resource. | 已存在相同名称的 Converter。 | 删除已有 Converter 并重新创建。 |
| `429 Too Many Requests` | <Slot name="response-code-markdown-0-7-1" /> | 并发请求过多，超出配额限制。 | 等待一段时间再请求。 |
| `500 Internal Server Error` | Internal errors. Contact us for troubleshooting. | 服务端内部错误。 | 使用[退避策略重试](/zh-CN/realtime-media/media-push/build/optimize-and-operate/rest-availability#使用退避策略重试)。 |
| `501 Not Implemented` | The method requested has not been implemented. | 服务端内部错误。 | 使用[退避策略重试](/zh-CN/realtime-media/media-push/build/optimize-and-operate/rest-availability#使用退避策略重试)。 |
| `503 Service Unavailable` | <Slot name="response-code-markdown-0-10-1" /> | 服务端内部错误。 | 使用[退避策略重试](/zh-CN/realtime-media/media-push/build/optimize-and-operate/rest-availability#使用退避策略重试)。 |
| `504 Gateway Timeout` | Gateway timeout. Check whether the resource is created, if not, re-create a new resource. | 服务端内部错误。 | 使用[退避策略重试](/zh-CN/realtime-media/media-push/build/optimize-and-operate/rest-availability#使用退避策略重试)。 |

<Slot for="response-code-markdown-0-2-1">

- Invalid parameter: rtmpUrl. Replace it and retry.
- Invalid parameter: idleTimeout. Replace it and retry.

</Slot>

<Slot for="response-code-markdown-0-7-1">

- Request rate limit exceeded.
- Resource quota limit exceeded.
- No available resources.

</Slot>

<Slot for="response-code-markdown-0-10-1">

- The server is temporarily overloading. Retry with a backoff strategy and contact us for troubleshooting.
- The server is temporarily down. Retry with a backoff strategy.

</Slot>

:::info[信息]
如果以上排查方法并未解决问题，请务必在日志中打印出响应 Header 中的 `X-Request-ID` 和 `X-Resource-ID` 字段值，并请[联系技术支持](https://docs.agora.io/cn/Agora%20Platform/ticket?platform=All%20Platforms)。
:::

以下是一个排查问题的示例：

使用 `Create` 创建 Converter 时，如果响应状态码为 `409(Conflict)` ，`message` 为 `"Resource with the same name already exists."`，则代表本次请求想创建的 Converter 和已经创建的 Converter 名字（`name`）重复，响应 Header 中的 `X-Resource-ID` 字段为那个同名 Converter 的 ID。请检查并修改本次请求填写的 Converter 名字，然后重新创建 Converter。
