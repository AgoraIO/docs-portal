## v4.6.3

该版本于 2026 年 2 月 9 日发布。

:::warning[注意]
- 通过 Maven Central 集成并升级至 v4.6.0 及以上版本时，除更新版本号外，还需将包名从 `io.agora.rtc` 修改为 `cn.shengwang.rtc`。
- 自 4.5.0 起，RTC SDK 和 RTM SDK (2.2.0 及以上版本) 都包含 `libaosl.so` 库。如果你通过 CDN 手动集成 RTC SDK 且同时集成了 RTM SDK，为避免冲突，请手动删除版本较低的 `libaosl.so` 库。
- 4.6.3 RTC SDK `libaosl.so` 库版本为 1.3.5。
:::

### 问题修复

该版本修复了以下问题：

- 部分机型开启美颜功能进行音视频互动场景下，偶现发送端黑屏或 App 崩溃。
- 音视频互动场景下偶现 App 崩溃。

## v4.6.2

该版本于 2026 年 1 月 16 日发布。

:::warning[注意]
- 通过 Maven Central 集成并升级至 v4.6.0 及以上版本时，除更新版本号外，还需将包名从 `io.agora.rtc` 修改为 `cn.shengwang.rtc`。
- 自 4.5.0 起，RTC SDK 和 RTM SDK (2.2.0 及以上版本) 都包含 `libaosl.so` 库。如果你通过 CDN 手动集成 RTC SDK 且同时集成了 RTM SDK，为避免冲突，请手动删除版本较低的 `libaosl.so` 库。
- 4.6.2 RTC SDK `libaosl.so` 库版本为 1.3.5。
:::

### 升级必看

#### EncodedVideoFrameInfo 结构体删除参数 uid

该版本删除了 `EncodedVideoFrameInfo` 结构体中的 `uid` 参数。你可以直接从 [`onEncodedVideoFrameReceived`](/api-ref/rtc/android/API/toc_video_encoded#callback_ivideoencodedframeobserver_onencodedvideoframereceived) 回调中获取远端用户的 `remoteUid` 信息。如果你之前集成过相关代码，请相应更新集成逻辑。

#### Lite 和 Voice 包中去除音频频谱功能

为进一步优化 SDK 包体积，该版本将音频频谱（Audio Spectrum）功能从 Lite 和 Voice SDK 包中移除。如果你需要使用音频频谱功能，请集成完整（Full）包。

#### 其他

- 为保证整体解码兼容性，相关解码器插件已内置在 SDK 中。

### 新增特性

#### 新增支持共享单个 App

从 Android 14 开始，系统支持用户在屏幕共享时选择共享整个屏幕或共享单个 App，以提升隐私保护和多任务处理能力。

该版本适配了该系统能力，在支持共享整个屏幕的基础上，新增支持共享单个 App。同时，为便于管理相关事件，新增 [`onLocalVideoEvent`](/api-ref/rtc/android/API/toc_video_basic#callback_irtcengineeventhandler_onlocalvideoevent) 回调，用于报告本地视频，尤其是屏幕共享相关的事件。

#### 新增权限被授予回调

为便于确认屏幕共享场景下的权限授权情况，该版本新增 [`onPermissionGranted`](/api-ref/rtc/android/API/toc_network#callback_irtcengineeventhandler_onpermissiongranted) 回调。你可以通过该回调判断当前用户授予的是相机（Camera）权限还是屏幕（Screen）权限。

#### Media Player 支持获取音频缓冲延迟

为解决 K 歌场景中可能会出现的主唱与伴唱伴奏不同步的问题，该版本在 Media Player 模块中新增 [`getAudioBufferDelay`](/api-ref/rtc/android/API/toc_mediaplayer_info#api_imediaplayer_getaudiobufferdelay) 方法，用于获取播放媒体文件时毫秒级的音频缓冲延迟。

### 改进

#### playEffect 支持无缝切换

该版本新增支持音效文件的无缝切换。对于同一个音效文件，如果先调用 `preloadEffect` 再调用 `playEffect`，在播放完成或通过 `stopEffect` 停止播放后，SDK 不会关闭该音效文件。当再次调用 `playEffect` 时，SDK 会直接复用已加载的文件进行播放，从而实现循环播放和无缝切换。该能力同样适用于多频道场景。

#### onNetworkQuality 准确性提升

该版本提升了 `onNetworkQuality` 回调中网络质量评估的准确性，使回调数据更贴近用户的主观体验。

#### onPlaybackAudioFrame 支持 24k 采样率的音频帧

该版本在 `onPlaybackAudioFrame` 中新增支持采样率为 **24000 Hz** 的音频数据。在调用 [`setPlaybackAudioFrameParameters`](/api-ref/rtc/android/API/toc_audio_raw#api_irtcengine_setplaybackaudioframeparameters) 设置播放音频数据格式时，可以将 `sampleRate` 设为 `24000`。

#### onEncodedVideoFrameReceived 回调支持获取频道 ID

该版本在 `onEncodedVideoFrameReceived` 回调中新增 `channelId` 参数，方便你在获取编码后视频数据时识别其所属频道。

#### 其他改进

该版本还进行了如下改进：

- 新增错误码 `ERR_PCMSEND_FORMAT (200)` 和 `ERR_PCMSEND_BUFFEROVERFLOW (201)`，用于报告 PCM 数据发送相关错误。
- 在弱光或暗光场景下，优化了部分设备的视频采集效果，使画面更亮。
- 录制模块 Media Recorder 新增支持录制 Media Player 和 Audio Mixing 的声音。

### 问题修复

该版本修复了以下问题：

- 接收端使用部分机型（如 Redmi 14C）进行音视频互通时，偶现发送端用户画面出现黑边的问题。
- `startLocalTranscoder` 接口中设置的 `bitrate` 不生效。
- 在部分模拟器（如雷电 9）上进行音视频互通时，接收端偶现听到电流声的问题。
- 在直播 PK 场景中，观众端启用合图视频流单独渲染功能时，偶现单独渲染的用户画面显示异常。
- 音视频互通场景下，本地调用 `playEffect` 播放音效后，当远端用户换为主播角色并开始说话时，本地偶现听到电流声。
- 在部分 vivo 机型上，运行 Android 15 系统的设备在关闭摄像头时，偶现 App 崩溃。
- 用户以主播身份在音频 Scenario 为 `AUDIO_SCENARIO_CHATROOM` 的情况下加入频道且未发布本地音频，调用 `startAudioMixing` 播放音乐文件后，再将音频 Scenario 切换为 `AUDIO_SCENARIO_GAMESTREAMING` 时，偶现听到杂音。
- 在音视频互通场景下，偶现 App 无响应（ANR）的问题。
- 修复了音视频互通过程中偶现崩溃的问题。
- 美颜功能在部分场景下不生效。

### 新增特性

#### 多路分辨率视频流

   该版本新增多路分辨率视频流（Adaptive Bitrate Video Streaming，简称 ABR）功能，支持对同一视频源设置同时发送多路不同分辨率的视频流，并支持多频道场景。接收端通过自动/手动订阅目标分辨率的视频流。

   启用 ABR 后，你可以配置不同分辨率的视频流（最多四层分辨率，即一个最高分辨率的主流和三层其他较低分辨率的视频流），并设置视频流的分辨率、码率、是否启用分层推流回退等选项来灵活控制流的发布。启用分层推流回退后，SDK 会在弱网环境下自动回退到低分辨率的视频流，确保流畅的观看体验。订阅端可根据实际需求选择想要接收的视频流。适用于会议场景、大班课、互动直播等多终端、多网络环境，可显著提升弱网下的观看体验。

   具体实现方法以及和视频双流的对比可以参考进阶功能[发布多路视频流 (ABR)](/zh-CN/realtime-media/rtc/advanced-features/simulcast.android.android)。

#### 多路径网络传输

   该版本新增多路径传输功能，适用于终端支持多网卡传输（比如 5G、Wi-Fi、LAN）的设备，可以有效降低甚至消除弱网带来的体验回退，适用于弱网环境、对传输稳定性要求高的实时音视频通信场景，如车载、IoT、火车、高速公路等复杂网络环境。通过在 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 中设置 `enableMultipath` 为 `true`，可开启多路径传输能力。支持两种传输模式（[`MultipathMode`](/api-ref/rtc/android/API/enum_multipathmode)）：

- 动态模式：（默认）根据网络状况动态选择最佳路径进行传输，适用于流量敏感、对体验要求比较高的场景，如会议、教育等。动态模式下，你可以通过 `preferMultipathType` 指定首选的网络传输路径（如优先 Wi-Fi 或移动网络）。
- 全冗余模式：数据会在所有可用网络路径上同时传输，适用于流量不敏感，对体验有极致要求的场景，如户外采播、平行操控等。该模式会产生额外费用，如需使用请[联系技术支持](https://ticket.shengwang.cn/)。

上下行还可分别通过 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 中的 `uplinkMultipathMode`、`downlinkMultipathMode` 配置。启用后，SDK 会通过回调 [`onMultipathStats`](/api-ref/rtc/android/API/toc_network#callback_irtcengineeventhandler_onmultipathstats) 实时上报各路径的传输统计信息，包括每一个传输路径的流量消耗，便于开发者监控和优化网络表现。

#### 视频质量评分

   该版本在 [`RemoteVideoStats`](/api-ref/rtc/android/API/class_remotevideostats) 中新增 `mosValue` 成员，报告声网实时视频 MOS（平均主观意见分）评估系统对接收到的远端视频流的质量评分。评分共有 5 个档次，5 分表示视频画质优秀，画面清晰无噪点，1 分表示视频画质极差，画面严重模糊。你可以通过该参数实时观测远端视频流的主观画质表现，便于动态调整视频参数、优化用户体验，或用于质量监控和告警等场景。如需启用该功能，请[联系技术支持](https://ticket.shengwang.cn/)。

#### 支持添加多个水印

   该版本废弃了 [`addVideoWatermark`](/api-ref/rtc/android/API/toc_watermark#api_irtcengine_addvideowatermark2)[2/3] 和 [`addVideoWatermarkEx`](/api-ref/rtc/android/API/toc_watermark#api_irtcengineex_addvideowatermarkex)[1/2] 方法，新增 [`addVideoWatermark`](/api-ref/rtc/android/API/toc_watermark#api_irtcengine_addvideowatermark3)[3/3] 和 [`addVideoWatermarkEx`](/api-ref/rtc/android/API/toc_watermark#api_irtcengineex_addvideowatermarkex1)[2/2] 方法，支持通过水印 ID 来给视频添加多个水印，并可对水印进行排序。如果你需要移除指定水印，可调用 [`removeVideoWatermark`](/api-ref/rtc/android/API/toc_watermark#api_irtcengine_removevideowatermark) 方法。

#### 异步销毁引擎

   该版本新增 `destroy` [2/2] 方法，用于销毁 RTC 引擎，且支持通过参数配置以同步或异步方式销毁引擎。异步销毁引擎时，SDK 会触发 `onEngineReleased` 回调。

#### 美颜功能拓展

   新增白牙、去法令纹、去黑眼圈、亮眼等美肤功能；美妆特效新增卧蚕和面部高光；美型功能从 11 个增加到 29 个。

#### Token 更新结果回调

   该版本新增 [`onRenewTokenResult`](/api-ref/rtc/android/API/toc_channel#callback_irtcengineeventhandler_onrenewtokenresult) 回调及 `RENEW_TOKEN_ERROR_CODE` 错误码。当调用 `renewToken` 方法更新 Token 后，SDK 会通过 [`onRenewTokenResult`](/api-ref/rtc/android/API/toc_channel#callback_irtcengineeventhandler_onrenewtokenresult) 回调通知 Token 更新的结果，并通过 `RENEW_TOKEN_ERROR_CODE` 返回详细的错误码，开发者可在回调中根据错误码及时处理 Token 更新失败的场景。

#### 其他

   - 新增 [`setPlaybackAudioFrameBeforeMixingParameters`](/api-ref/rtc/android/API/toc_audio_raw#api_irtcengine_setplaybackaudioframebeforemixingparameters1)[2/2] 方法用于设置 [`onPlaybackAudioFrameBeforeMixing`](/api-ref/rtc/android/API/toc_audio_raw#callback_iaudioframeobserver_onplaybackaudioframebeforemixing) 回调中返回的音频帧格式，包括采样率、声道数以及每次回调的数据采样点数。调用此方法后，SDK 会按照设定的参数返回混音前的原始音频数据，便于开发者进行自定义处理或分析。
   - 新增 `preloadEffectEx` 方法，用于将指定音效文件预加载到指定频道，支持本地或在线音效文件，便于后续快速播放，适合多频道场景。
   - 新增 `playEffectEx` 方法，用于在指定频道播放音效文件，支持设置循环次数、音调、空间位置、音量、是否发布到频道及播放起始位置等参数，满足丰富的音效播放需求。
   - 本地截图上传功能支持通过 [`ContentInspectModule`](/api-ref/rtc/android/API/class_contentinspectmodule) 中新增的 `position` 成员设置截图的视频观测位置，从而实现对原始视频数据或效果处理前后的视频流进行截图并上传。
   - 为了提升用户使用绿幕或蓝幕开启虚拟背景功能时，人像分割的准确性和稳定性，该版本在 [`SegmentationProperty`](/api-ref/rtc/android/API/class_segmentationproperty) 中新增 `screenColorType` 属性，支持指定背景幕布的颜色为绿色、蓝色或自动识别。

### 改进

#### 美颜重构

   该版本对美颜功能进行了彻底重构和升级，不仅拓展了美颜功能，提升了美颜效果和性能，还解决了美颜参数配置复杂、集成成本高、美颜资源依赖网络易失效等痛点。主要改进包括：

   - **新增美颜功能**：新增白牙、去法令纹、去黑眼圈、亮眼等美肤功能；美妆特效新增卧蚕和面部高光；美型功能从 11 个增加到 29 个。
   - **API 大幅简化**：将过去版本中的基础美颜、美型、美妆、滤镜功能整合为 `BEAUTY`、`STYLE_MAKEUP`、`FILTER` 三个核心节点 (node)，通过 [`IVideoEffectObject`](/api-ref/rtc/android/API/rtc_interface_class#class_ivideoeffectobject) 统一管理生命周期和参数设置，减少频繁 API 调用带来的性能负担。
   - **预设模板开箱即用**：提供多套预设风格模板（如“自然美颜”、“学姐妆”、“冷白滤镜”），大幅简化集成流程，无需手动调试数十项参数。

   在对视频渲染帧率要求不高的场景（例如：屏幕共享、在线教育）或者远端使用中低端设备的场景下，你可以通过这一组方法限制视频渲染帧率，从而减小 CPU 消耗、提升系统性能。

#### URL 拉流播放

   URL 拉流播放功能主要用于直播场景，观众端可以直接通过 [`openWithUrl`](/api-ref/rtc/android/API/toc_rte_player#api_player_openwithurl) 打开特定的 URL 来播放实时媒体流，无需显示调用加入频道、订阅等 API，极大简化了观众端观看直播流的 API 调用。

   在播放的过程中，观众端可以通过 [`setAbrSubscriptionLayer`](/api-ref/rtc/android/API/toc_rte_player#api_playerconfig_setabrsubscriptionlayer) 设置订阅视频大小流，并可以在大小流之间实现平滑切换。如果对视频体验有更高要求，可以[联系技术支持](https://ticket.shengwang.cn/)开通 ABR（Adaptive Bitrate，自适应码率）功能。启用该功能后，可以自定义不同层级的视频流分辨率，观众可以实现不同分辨率视频流的平滑切换。

   当网络情况不稳定时，观众端可以调用 [`setAbrFallbackLayer`](/api-ref/rtc/android/API/toc_rte_player#api_playerconfig_setabrfallbacklayer) 来设置订阅的视频流的回退选项。SDK 会以你指定的最低质量层级对应的视频流分辨率为下限，在此范围内根据网络状况动态调整分辨率。实现细节详见[观众端 URL 拉流](/zh-CN/realtime-media/rtc/best-practice/playing-url)。

#### 滤镜效果

   该版本新增 [`setFilterEffectOptions`](/api-ref/rtc/android/API/toc_video_enhance_option#api_irtcengine_setfiltereffectoptions)[1/2] 方法，你可以在 **config** 参数中传入指定格式的立方体贴图文件 (.cube)，从而实现美白、鲜艳、冷色、黑白等自定义滤镜效果。此外，SDK 提供了一个内置的 `built_in_whiten_filter.cube` 文件，用于快速实现美白滤镜效果。

#### 本地音频合流

   该版本新增本地音频合流功能，你可以调用 [`startLocalAudioMixer`](/api-ref/rtc/android/API/toc_audiomixer#api_irtcengine_startlocalaudiomixer) 方法，将本地麦克风采集的音频流、媒体播放器中的音频流、声卡采集的音频流、远端音频流等合并为一路音频流，你可以将合并后的音频流发布到频道中。不再需要音频合流时，你可以调用 [`stopLocalAudioMixer`](/api-ref/rtc/android/API/toc_audiomixer#api_irtcengine_stoplocalaudiomixer) 方法停止本地音频合流；在合流过程中，可以调用 [`updateLocalAudioMixerConfiguration`](/api-ref/rtc/android/API/toc_audiomixer#api_irtcengine_updatelocalaudiomixerconfiguration) 方法更新正在合流的音频流配置。

   该功能的使用场景示例如下：

   - 结合本地合图功能一起使用，可将合图视频流相关的音频流同步采集和发布。
   - 在直播场景下，用户接收频道内的音频流，在本地进行多路音频流合流后转发到其他频道。
   - 在教育场景下，老师可将跟学生连麦互动的音频在本地进行合流，然后将合并的音频流转发到其他频道。

#### 外部 MediaProjection

该版本新增 [`setExternalMediaProjection`](/api-ref/rtc/android/API/toc_screencapture#api_irtcengine_setexternalmediaprojection) 方法，该方法支持你自行设置外部 `MediaProjection`，并取代 SDK 申请的 `MediaProjection`。

如果你具备自行申请 `MediaProjection` 的开发能力，可通过该功能实现更加灵活的屏幕采集。

#### EGL 环境上下文

该版本新增了 [`setExternalRemoteEglContext`](/api-ref/rtc/android/API/toc_video_custom_capturenrendering#api_irtcengine_setexternalremoteeglcontext) 方法，用于设置远端视频流渲染的 EGL 环境上下文。使用 Texture 格式的视频数据进行远端视频自渲染时，你可以通过该方法替换 SDK 默认的远端 EGL 环境上下文，实现统一的 EGL 上下文管理。

#### 色彩空间设置

   该版本在 `VideoFrame` 和 `ExternalVideoFrame` 中新增了 **colorSpace**，你可以通过该参数设置视频帧的色彩空间属性。默认情况下，色彩空间采用 Full Range 和 BT.709 标准配置，你可以根据自采集或自渲染的需求灵活调整，进一步提升视频处理的定制化能力。

### 改进

#### 虚拟背景算法优化

   该版本升级了虚拟背景的算法，分割人像主体部分与背景时更加准确，背景无露出，人像身体轮廓无缺块，手指细节辨识显著提高。同时，人像与背景的边缘更加稳定，减少了连续视频帧中人像边缘的跳变和闪烁现象。

#### 录制本地预览视频

   该版本在 [`RecorderStreamInfo`](/api-ref/rtc/android/API/class_recorderstreaminfo) 中新增 **type** 成员。当调用 [`createMediaRecorder`](/api-ref/rtc/android/API/toc_recording#api_irtcengine_createmediarecorder) 时，可通过该成员指定录制的视频流类型为本地预览视频流，并在 [`MediaRecorderConfiguration`](/api-ref/rtc/android/API/class_mediarecorderconfiguration) 中设置录制预览视频的高、宽、帧率、采样率等参数，之后调用 [`startRecording`](/api-ref/rtc/android/API/toc_recording#api_imediarecorder_startrecording) 即可开始录制本地预览的视频。

#### 指定视频观测位置截图

   该版本新增 [`takeSnapshot`](/api-ref/rtc/android/API/toc_snapshot#api_irtcengine_takesnapshot2)[2/2] 和 [`takeSnapshotEx`](/api-ref/rtc/android/API/toc_snapshot#api_irtcengineex_takesnapshotex2)[2/2] 方法，你可以在调用该方法时通过 **config** 参数，在指定的视频观测点进行截图，比如：编码前、编码后或渲染前的数据，以实现更加灵活的截图效果。

#### 自定义音频采集改进

   该版本在 [`AudioTrackConfig`](/api-ref/rtc/android/API/class_audiotrackconfig) 中新增了 `enableAudioProcessing` 成员参数，用于控制是否对 `AUDIO_TRACK_DIRECT` 类型的自定义音频采集轨道启用 3A 音频处理。该参数默认值为 `false`，即不启用音频处理，用户可以按需开启，此项改动提升了自定义音频处理的灵活性。

#### 其他改进

   - 通过拼接视频帧和 Alpha 数据实现 Alpha 透明特效的应用场景下，提升了接收端的渲染性能，有效减少卡顿和延迟。
   - 优化了调用 [`queryDeviceScore`](/api-ref/rtc/android/API/toc_network#api_irtcengine_querydevicescore) 获取设备评分等级的设计逻辑，提升了等级评分结果的准确性。
   - 调用 [`switchSrc`](/api-ref/rtc/android/API/toc_mediaplayer_open#api_imediaplayer_switchsrc) 切换不同分辨率的直播流或点播流时，可以实现平滑且无感知的切换效果，并在切换失败时新增自动重试机制。SDK 会在切换失败后自动重试 3 次，如果依旧失败，会通过 [`onPlayerEvent`](/api-ref/rtc/android/API/toc_mediaplayer_observer#callback_imediaplayersourceobserver_onplayerevent) 回调报告 `PLAYER_EVENT_SWITCH_ERROR` 事件，表示媒体资源切换时发生错误。
   - 调用 `setPlaybackSpeed` 设置音频文件的播放速度时，最低支持 0.3 倍速播放。

### 问题修复

该版本修复了以下问题：

- 当发送端视频源类型为 JPEG 格式时，偶现接收端帧率低于预期。
- 在播放音乐内容中心的音乐资源时，偶现杂音和卡顿。
- 在 App 没有获取麦克风权限时，通过 [`IAgoraMusicPlayer`](/api-ref/rtc/android/API/rtc_interface_class#class_imusicplayer) 播放伴奏音乐偶现卡顿。
- 音视频互动过程中被系统来电打断后，通过 `onAudioVolumeIndication` 回调上报的用户音量错误。
- 在接收端默认订阅视频小流、加入频道时不自动订阅任何视频流的前提下，加入频道后调用 `muteRemoteVideoStream(uid,false)` 恢复接收视频流，但接收到的视频流为视频大流，不符合预期。
- 调用 [`startAudioMixing`](/api-ref/rtc/android/API/toc_audio_mixing#api_irtcengine_startaudiomixing)[1/2] 后，立即调用 [`pauseAudioMixing`](/api-ref/rtc/android/API/toc_audio_mixing#api_irtcengine_pauseaudiomixing) 暂停播放音乐文件不生效。
- 音视频互动过程中偶现崩溃。

#### 摄像头广角和超广角

   为了让用户捕捉到更宽阔的视野和更完整的画面内容，该版本新增了对广角和超广角摄像头的支持。你可以先调用 [`queryCameraFocalLengthCapability`](/api-ref/rtc/android/API/toc_video_device#api_irtcengine_querycamerafocallengthcapability) 查询设备支持的焦距能力，然后调用 [`setCameraCapturerConfiguration`](/api-ref/rtc/android/API/toc_video_device#api_irtcengine_setcameracapturerconfiguration) 并将 `cameraFocalLengthType` 设置为支持的焦距类型，包括广角、超广角等。

#### 摄像头多路采集

   该版本针对 Android 摄像头采集新增以下功能：

   1. 支持第三个和第四个摄像头视频流的采集和发布。
      - 在 [`VideoSourceType`](/api-ref/rtc/android/API/enum_videosourcetype) 中新增 `VIDEO_SOURCE_CAMERA_THIRD`(11) 和 `VIDEO_SOURCE_CAMERA_FOURTH`(12) 枚举，分别用于指定视频源为第三个和第四个摄像头。此项改动允许你在调用 [`startCameraCapture`](/api-ref/rtc/android/API/toc_camera_capture#api_irtcengine_startcameracapture) 开启摄像头采集时，指定最多 4 路摄像头采集的视频流。
      - 在 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 中新增 `publishThirdCameraTrack` 和 `publishFourthCameraTrack` 成员。调用 [`joinChannel`](/api-ref/rtc/android/API/toc_channel#api_irtcengine_joinchannel2)[2/2] 加入频道时，将这两个成员参数设置为 `true` 即可在频道内发布第三个和第四个摄像头采集的视频流。
   2. 支持通过摄像头 ID 指定摄像头。
      - 在 [`CameraCapturerConfiguration`](/api-ref/rtc/android/API/class_cameracapturerconfiguration) 中新增 `cameraId` 成员。对于多摄像头的设备，`cameraDirection` 无法识别或访问全部可用摄像头。这种情况下，你可以通过 Android 原生系统 API 获取摄像头 ID，再调用 [`startCameraCapture`](/api-ref/rtc/android/API/toc_camera_capture#api_irtcengine_startcameracapture) 并传入 `cameraId` 指定所需的摄像头。
      - 新增 [`switchCamera`](/api-ref/rtc/android/API/toc_video_device#api_irtcengine_switchcamera2)[2/2]，支持通过 `cameraId` 切换摄像头，允许 App 在运行期间基于可用摄像头的实际情况动态调整摄像头使用。

#### 数据流加密

   该版本在 [`EncryptionConfig`](/api-ref/rtc/android/API/class_encryptionconfig) 中新增 `datastreamEncryptionEnabled` 成员用于启用数据流加密。你可以在调用 [`enableEncryption`](/api-ref/rtc/android/API/toc_network#api_irtcengine_enableencryption) 开启加密时来进行设置。如果在数据流加密或解密的过程中遇到问题导致失败，你可以通过新增的 `ENCRYPTION_ERROR_DATASTREAM_DECRYPTION_FAILURE` 和 `ENCRYPTION_ERROR_DATASTREAM_ENCRYPTION_FAILURE` 枚举得知。

#### 本地视频渲染

   该版本在 [`VideoCanvas`](/api-ref/rtc/android/API/class_videocanvas) 中新增如下成员，以支持更多本地渲染功能。

   - `surfaceTexture`：设置一个 Android 原生的 `SurfaceTexture` 对象作为提供视频图像的容器，然后使用 SDK 外部的方法自行实现 OpenGL 中的纹理绘制。
   - `enableAlphaMask`：可以通过该成员设置接收端是否开启 Alpha 遮罩渲染。Alpha 遮罩渲染功能可以创建具有透明效果的图像或提取视频中的人像。

#### 视频小流自适应配置

   该版本新增视频小流的自适应配置功能，当你调用 [`setDualStreamMode`](/api-ref/rtc/android/API/toc_publishnsubscribe#api_irtcengine_setdualstreammode2)[2/2] 在发送端设置双流模式并设置视频小流时，SDK 的默认行为如下所示：

   - 将视频小流的默认编码分辨率设为原始视频编码分辨率的 50%。
   - 视频小流的码率根据视频分辨率和帧率自动匹配，无需指定。

#### 其他

   - 新增 [`enableEncryptionEx`](/api-ref/rtc/android/API/toc_network#api_irtcengineex_enableencryptionex) 方法，用于多频道场景下开启媒体流或数据流加密。
   - 新增 [`setAudioMixingPlaybackSpeed`](/api-ref/rtc/android/API/toc_audio_mixing#api_irtcengine_setaudiomixingplaybackspeed) 方法，用于设置音乐文件的播放速度。
   - 新增 [`getCallIdEx`](/api-ref/rtc/android/API/toc_network#api_irtcengineex_getcallidex) 方法，用于多频道场景下获取通话 ID。

### 改进

#### 本地视频状态回调优化

   该版本新增如下枚举，你可以通过 [`onLocalVideoStateChanged`](/api-ref/rtc/android/API/toc_video_basic#callback_irtcengineeventhandler_onlocalvideostatechanged) 回调了解更多本地视频状态发生改变的原因：

   - `LOCAL_VIDEO_STREAM_REASON_DEVICE_INTERRUPT` (14)：由于摄像头被其他 App 占用或 App 切后台等原因导致的视频采集中断。
   - `LOCAL_VIDEO_STREAM_REASON_DEVICE_FATAL_ERROR` (15)：视频采集设备出错，可能由于摄像头设备故障导致。

#### 摄像头采集改进

   优化了摄像头采集的视频处理机制，减少噪点、提高亮度、改善色彩，使采集到的图形更加清晰、明亮和真实。

#### 虚拟背景算法优化

   为了提高纯色背景下开启虚拟背景时人像分割的精确度和稳定性，该版本优化了绿幕分割算法：

   - 支持识别任意纯色背景，不再局限于绿幕。
   - 对背景颜色的识别更加准确，并且在分割人像时露出的背景更少。
   - 分割后的人像边缘（尤其是手指边缘）更加稳定，显著减少边缘的画面闪动现象。

#### 降低耳返的 CPU 消耗

   该版本新增 `EAR_MONITORING_FILTER_REUSE_POST_PROCESSING_FILTER`(1 << 15) 枚举。针对复杂的音效处理场景，你可以指定该选项，复用发送端音效处理后的 Audio filter，从而降低 CPU 的消耗。需要注意的是该选项会导致耳返延迟增加，适用于对耳返延迟不敏感的使用场景。

#### 其他改进

   该版本还进行了如下改进：

   - 提升了本地合图功能的性能和稳定性，并降低了该功能对 CPU 的占用率。
   - 优化了媒体播放器对 WebM 格式视频的处理能力，支持渲染 Alpha 通道。
   - 新增 `ROOM_ACOUSTICS_CHORUS`（合唱音效），可使人声在合唱场景下更具空间立体感。
   - 在 [`RemoteAudioStats`](/api-ref/rtc/android/API/class_remoteaudiostats) 中新增 `e2eDelay`，用于报告从发送端采集音频起，到接收端开始播放音频时的延时。

### 问题修复

该版本修复了以下问题：

- 使用媒体播放器播放包含 SEI 数据的媒体流时，SEI 数据的输出与视频渲染不同步。
- 加入频道后调用 [`disableAudio`](/api-ref/rtc/android/API/toc_audio_basic#api_irtcengine_disableaudio) 关闭音频模块，音频播放没有立即停止。
- 主播使用部分型号设备在扬声器下进行音视频互动，之后切换 App 进程到后台再切回前台，偶现本地音频采集失败，远端用户听不到主播的声音。
- 在 Android 8.0 系统的设备上，启用屏幕共享功能时 App 偶现崩溃。
- 使用摄像头采集本地视频场景下，在 App 切后台时已调用 [`disableVideo`](/api-ref/rtc/android/API/toc_video_basic#api_irtcengine_disablevideo) 或 [`stopPreview`](/api-ref/rtc/android/API/toc_video_basic#api_irtcengine_stoppreview)[1/2] 关闭视频采集，但将 App 再切回前台时，摄像头采集被打开，不符合预期。
- 当发送端用户的网络环境恶化（例如弱网）时，接收端偶现视频流畅度降低、卡顿增加。

### 新增特性

#### 接收端自定义合图布局

为支持接收端自定义多路合图流的布局，该版本新增了 [`onTranscodedStreamLayoutInfo`](/api-ref/rtc/android/API/toc_video_rendering#callback_irtcengineeventhandler_ontranscodedstreamlayoutinfo) 回调。当接收端收到合图服务器发送的频道内合图视频流时，该回调会被触发，上报合图视频流的布局信息、以及合图流中每一路子视频流的布局信息。接收端可以在调用 [`setupRemoteVideo`](/api-ref/rtc/android/API/toc_video_rendering#api_irtcengine_setupremotevideo) 方法时，为合图视频流中的子视频流（通过 `subviewUid` 区分）设置单独的 `view` 进行渲染，从而达到自定义视频布局的效果。

当合图视频流中的子视频流布局发生变化时，该回调也会被触发，实时上报最新的布局信息。

通过该特性，接收端可以灵活调整本地的视图布局。当在多人视频场景下应用时，接收端只需接收并解码一路合图视频流，可以有效降低接收端解码多路视频时的 CPU 占用率和网络带宽。

:::info[信息]
关于该特性在多主播场景下的最佳实践，详见[多主播场景下的视频体验优化](/zh-CN/realtime-media/rtc/best-practice/custom-layout.android.android)。
:::

#### 多视图本地预览

该版本支持在本地预览同时预览多个画面、且画面中显示的视频分别处于视频链路上的不同观测位置。使用方式举例如下：

1. 调用 [`setupLocalVideo`](/api-ref/rtc/android/API/toc_video_rendering#api_irtcengine_setuplocalvideo) 设置第一个视图：在 [`VideoCanvas`](/api-ref/rtc/android/API/class_videocanvas) 中设置 `position` 参数为 `VIDEO_MODULE_POSITION_POST_CAPTURER_ORIGIN`（该枚举为该版本新增），对应本地采集视频之后、前处理之前的位置，此处观测到的视频不具备前处理的效果。
2. 调用 [`setupLocalVideo`](/api-ref/rtc/android/API/toc_video_rendering#api_irtcengine_setuplocalvideo) 设置第二个视图：在 [`VideoCanvas`](/api-ref/rtc/android/API/class_videocanvas) 中设置 `position` 参数为 `VIDEO_MODULE_POSITION_POST_CAPTURER`，此处观测到的视频具备视频前处理的效果。
3. 观察本地预览效果：视图一为真人原始视频；视图二为经过视频前处理的虚拟人像（包括美颜、虚拟背景、水印本地预览）效果。

#### 查询设备评分等级

该版本新增 [`queryDeviceScore`](/api-ref/rtc/android/API/toc_network#api_irtcengine_querydevicescore) 方法，用于查询设备的评分等级，以保证用户设置的参数不会超出其设备能力。例如，在高清或超高清视频场景下，可以先调用该方法查询设备的等级评分，如果返回的评分较低（比如低于 60），则需要适当调低视频分辨率，以避免影响视频体验。不同业务场景要求的最低设备评分等级不同，具体评分推荐请[联系技术支持](https://agora-ticket.agora.io/)。

#### 本地播放及发布至远端的音轨控制

该版本新增 [`selectMultiAudioTrack`](/api-ref/rtc/android/API/toc_audio_mixing#api_imediaplayer_selectmultiaudiotrack) 方法，支持分别设置本地播放和发送至远端的音轨。在 K 歌等场景下，主播可以根据需求选择在本地播放一路音轨（如原声），然后发送另一路音轨至远端（如伴奏）以提升听众体验。 使用该功能前，需要通过 [`openWithMediaSource`](/api-ref/rtc/android/API/toc_mediaplayer_open#api_imediaplayer_openwithmediasource) 打开媒体文件，并通过 [`MediaPlayerSource`](/api-ref/rtc/android/API/class_mediasource) 中新增的 `enableMultiAudioTrack` 成员来开启音轨控制。

#### 音频播放设备测试

该版本新增 [`startPlaybackDeviceTest`](/api-ref/rtc/android/API/toc_audio_device#api_iaudiodevicemanager_startplaybackdevicetest) 方法，用于在加入频道前测试音频播放设备能否正常工作。你可以通过 `testAudioFilePath` 参数指定需要播放的音频文件，测试者如果能听到声音，说明播放设备能正常工作。测试完毕后，你需要调用新增的 [`stopPlaybackDeviceTest`](/api-ref/rtc/android/API/toc_audio_device#api_iaudiodevicemanager_stopplaybackdevicetest) 方法停止测试。

## v4.2.3

该版本于 2023 年 10 月 12 日发布。

### 升级必看

#### 兼容性变更

该版本优化了 SDK 采集和自定义视频采集场景下 Texture Buffer 的管理方式，有效消除丢帧和崩溃隐患。自该版本起，TextureBuffer 类型的纹理格式不再包括 OES 格式，仅为 RGB 格式。你需要在处理视频数据时增加对 I420、RGB 纹理格式的适配。

### 新增特性

#### 本地截图上传更新

   为方便接入声网云市场提供的第三方视频审核服务，该版本有以下改动：

   - [`ContentInspectModule`](/api-ref/rtc/android/API/class_contentinspectmodule) 中的 `type` 新增 `CONTENT_INSPECT_TYPE_IMAGE_MODERATION` 枚举值，代表使用声网云市场视频审核插件对视频截图并上传。
   - [`ContentInspectConfig`](/api-ref/rtc/android/API/class_contentinspectconfig) 中新增的 `serverConfig` 可选参数用于云市场视频审核相关服务端配置，配置后可同时接入多个云市场审核插件并实现灵活控制插件开关等功能，详情请[联系技术支持](https://agora-ticket.agora.io/)。

   此外，该版本还新增了 [`enableContentInspectEx`](/api-ref/rtc/android/API/toc_snapshot#api_irtcengineex_enablecontentinspectex) 方法，支持同时对多条视频流截图并上传。

#### 进阶功能查询

   该版本新增了 [`isFeatureAvailableOnDevice`](/api-ref/rtc/android/API/toc_network#api_irtcengine_isfeatureavailableondevice) 方法，用于查询设备能力是否满足虚拟背景、美颜等进阶功能的使用要求。

   在使用进阶功能前，你可以根据查询结果判断当前设备是否支持这些功能，从而避免在低端设备上开启进阶功能导致性能下降或功能不可用的问题。你可以根据该方法的返回值，决定是否显示或启用相应的功能按钮，或者在设备能力不足时，为用户提示相应信息。

   此外，自该版本起，调用 `enableVirtualBackground` 和 `setBeautyEffectOptions` 时，SDK 会自动对当前设备能力进行检查，并在设备能力不足时，通过返回错误码 `-4: ERR_NOT_SUPPORTED` 表示该设备不支持开启该功能。

### 改进

#### 优化虚拟背景内存占用

   该版本升级了虚拟背景算法，降低了虚拟背景功能的内存占用。相比之前的版本，在低端机上使用虚拟背景功能时 App 运行占用的内存降低了约 4% 到 10%（具体数值取决于设备型号和平台）。

#### 屏幕共享场景优化

   该版本优化了屏幕共享场景下的视频编码配置。当用户自定义视频的 `width` 和 `height` 属性时，SDK 会在保持视频与屏幕的宽高比一致的前提下，对实际的编码分辨率进行向下取整，确保最终编码分辨率不超过用户自定义的编码分辨率，从而提升了对屏幕共享流的计费准确性。

#### 其他改进

该版本还进行了如下改进：

- 当调用 `setPlaybackSpeed` 设置音频文件的播放速度时，传入非法参数后会返回错误码 `-2`，表示方法中设置了无效的参数，需要重新设置参数。
- 优化了 Token 解析时的逻辑，避免传入非法 Token 后 App 发生崩溃。

### 问题修复

该版本修复了以下问题：

- 在采用 H.265 编码模式时，如果 Web 端加入互动，会导致 Native 端出现冗余的 [`onUserEnableLocalVideo`](/api-ref/rtc/android/API/toc_video_basic#callback_irtcengineeventhandler_onuserenablelocalvideo) 回调：当主播调用 `enableLocalVideo(true)`时，接收端在收到 [`onUserEnableLocalVideo`](/api-ref/rtc/android/API/toc_video_basic#callback_irtcengineeventhandler_onuserenablelocalvideo) (`enabled` 为 `true`) 回调之前，会先收到一个 [`onUserEnableLocalVideo`](/api-ref/rtc/android/API/toc_video_basic#callback_irtcengineeventhandler_onuserenablelocalvideo) (`enabled` 为 `false`) 回调。
- 本地系统时间不正确时，偶现加入频道失败。
- 调用 [`playEffect`](/api-ref/rtc/android/API/toc_audio_effect_file#api_irtcengine_playeffect3)[2/2] 使用相同的 `soundId` 播放两个不同的音效文件，偶现第一个音效文件播放完毕后会重复播放。

### 新增特性

#### AI 降噪

该版本新增 AI 降噪功能。开启该功能后，SDK 会智能识别和消除背景噪音，无论是在嘈杂的公共场所，还是在需要保持低延迟的实时竞技场景，都能够确保声音传输的清晰度，为用户提供更高质量的音频体验。你可以通过该版本新增的 [`setAINSMode`](/api-ref/rtc/android/API/toc_audio_effect#api_irtcengine_setainsmode) 方法开启 AI 降噪，并根据实际场景，将降噪模式设置为均衡模式、强降噪模式或低延时模式。

#### 增强虚拟背景

为了增加实时视频通话的趣味性、保护用户隐私，该版本增强了虚拟背景功能。你可以在调用 `enableVirtualBackground` 方法时，将自定义背景设置为更多类型：

- 将背景处理为 Alpha 信息，不作替换，仅分割人像和背景，可结合本地合图功能实现人像画中画效果。
- 将背景替换为多种格式的本地视频。

#### 视频场景化设置

该版本新增 [`setVideoScenario`](/api-ref/rtc/android/API/toc_video_basic#api_irtcengine_setvideoscenario) 方法用于设置视频业务场景，SDK 会根据不同场景自动启用最佳实践策略，调整关键性能指标，进而优化视频质量，提升用户体验。无论是正式的商务会议还是轻松的在线聚会，该功能都能确保视频质量满足需求。目前，该特性主要为实时视频会议场景提供了以下针对性的优化：

- 针对会议场景对小流码率要求较高的情况，自动启用多项抗弱网技术，提升小流的抗弱网能力，确保多路流订阅时接收端的流畅性。
- 实时监测接收端大小流的订阅人数，根据订阅人数动态调节大流配置、动态开启和关闭小流，以节省上行带宽和消耗。

#### 本地录制远端音视频 (Beta)

该版本新增本地录制远端音视频功能。本地用户可以录制远端用户的音频视频流，便于将来回放、分析或分享，适用于在线教育、企业培训、在线会议等多类场景。为更准确报告录制状态，该版本在 [`onRecorderStateChanged`](/api-ref/rtc/android/API/toc_recording#callback_imediarecorderobserver_onrecorderstatechanged) 和 [`onRecorderInfoUpdated`](/api-ref/rtc/android/API/toc_recording#callback_imediarecorderobserver_onrecorderinfoupdated) 中新增 `channelId` 和 `uid` 参数，用于表示录制的音视频流的具体信息，并新增 [`createMediaRecorder`](/api-ref/rtc/android/API/toc_recording#api_irtcengine_createmediarecorder) 方法，用于创建本地或远端的录制对象。

你可以通过如下方法体验本地录制远端音视频功能：

- [`createMediaRecorder`](/api-ref/rtc/android/API/toc_recording#api_irtcengine_createmediarecorder)：创建录制对象。如需同时录制本地和远端的音视频，可以多次调用该方法创建多个录制对象。
- [`setMediaRecorderObserver`](/api-ref/rtc/android/API/toc_recording#api_imediarecorder_setmediarecorderobserver)：设置录制回调对象。
- [`startRecording`](/api-ref/rtc/android/API/toc_recording#api_imediarecorder_startrecording)：开始录制。
- [`stopRecording`](/api-ref/rtc/android/API/toc_recording#api_imediarecorder_stoprecording)：停止录制。
- [`destroyMediaRecorder`](/api-ref/rtc/android/API/toc_recording#api_irtcengine_destroymediarecorder)：销毁录制对象。

#### 本地合图

该版本新增 [`setScreenCaptureScenario`](/api-ref/rtc/android/API/toc_screencapture#api_irtcengine_setscreencapturescenario) 方法，用于设置屏幕共享的场景类型，SDK 会根据场景类型自动调整共享画面的的流畅度和清晰度。

#### 提升音视频同步能力

针对自定义视频和音频采集场景，该版本新增 [`getCurrentMonotonicTimeInMs`](/api-ref/rtc/android/API/toc_network#api_irtcengine_getcurrentmonotonictimeinms) 方法用于获取当前的 Monotonic Time，将该值传入视频帧和音频帧的时间戳，可以精确控制音视频时序，确保音视频同步。

该版本新增 [`startCameraCapture`](/api-ref/rtc/android/API/toc_camera_capture#api_irtcengine_startcameracapture) 方法，通过多次调用并指定 `sourceType` 参数可以同时开启多路摄像头采集的视频流，用于本地合图或多频道发布。适用于如远程医疗、远程教育等连接多个摄像头的场景。

#### 优化版权音乐

针对在线 K 歌房场景，改版本新增 [`getCaches`](/api-ref/rtc/android/API/toc_drm#api_imusiccontentcenter_getcaches) 和 [`removeCache`](/api-ref/rtc/android/API/toc_drm#api_imusiccontentcenter_removecache) 方法，用于获取、删除音乐资源缓存，并新增状态码和错误码，可方便用户排查问题。

#### 优化跨频道连麦

该版本新增 [`startOrUpdateChannelMediaRelay`](/api-ref/rtc/android/API/toc_channel_media_relay#api_irtcengine_startorupdatechannelmediarelay) 和 [`startOrUpdateChannelMediaRelayEx`](/api-ref/rtc/android/API/toc_channel_media_relay#api_irtcengineex_startorupdatechannelmediarelayex) 方法，通过一个方法实现开始跨频道转发和更新转发的目标频道，提升了接口易用性；同时，优化内部交互次数，有效降低调用了延迟。在降低开发难度的同时，为开发者提供更顺畅的使用体验。

#### 多路音频自采集

为更好地满足音频自采集的场景需求，该版本新增了 [`createCustomAudioTrack`](/api-ref/rtc/android/API/toc_audio_custom_capturenrendering#api_imediaengine_createcustomaudiotrack) 和 [`destroyCustomAudioTrack`](/api-ref/rtc/android/API/toc_audio_custom_capturenrendering#api_imediaengine_destroycustomaudiotrack) 方法用于创建和销毁自定义音频轨道，并提供了两种音频轨道类型供用户选择，进一步提升了自采集音频处理的灵活性和易用性：

- 可混音的音频轨道：支持将多路外部音频源混合发布到同一频道中，适用于多路音频源的自采集场景。
- 非混音的音频轨道：仅支持将一路外部音频源发布到单个频道中，适用于实时低延迟的自采集场景。

### 升级必看

自该版本起，SDK 对视频编码的算法进行了优化，将默认的视频编码分辨率从 640 × 360 提升为 960 × 540，以适应设备性能和网络带宽的提升，在各种音视频互动场景下，为用户提供全链路的高清体验。

如果你想自定义视频编码分辨率，可调用 [`setVideoEncoderConfiguration`](/api-ref/rtc/android/API/toc_video_basic#api_irtcengine_setvideoencoderconfiguration) 方法，重新设置视频编码参数配置中的视频编码分辨率。

:::warning[注意]
由于默认分辨率的提升，会影响集合分辨率从而导致费用变更。详见[计费策略](/zh-CN/realtime-media/rtc/billing/billing-strategy)。

### 新增特性

#### 快速出图出声

该版本新增 [`enableInstantMediaRendering`](/api-ref/rtc/android/API/toc_video_rendering#api_irtcengine_enableinstantmediarendering) 方法，用于开启音视频帧的加速渲染模式，可加快用户加入频道后的首帧出图与出声速度。

#### 视频渲染数据打点

该版本新增 [`startMediaRenderingTracing`](/api-ref/rtc/android/API/toc_video_rendering#api_irtcengine_startmediarenderingtracing) 和 [`startMediaRenderingTracingEx`](/api-ref/rtc/android/API/toc_video_rendering#api_irtcengineex_startmediarenderingtracingex) 方法，SDK 以调用该方法的时刻作为起点，开始跟踪频道内视频帧的渲染状态，并通过 [`onVideoRenderingTracingResult`](/api-ref/rtc/android/API/toc_video_rendering#callback_irtcengineeventhandler_onvideorenderingtracingresult) 回调报告相关事件的信息。

声网推荐你将该方法和 App 中的 UI 设置（按钮、滑动条等）结合使用。例如：在终端用户点击“加入频道”按钮的时刻调用该方法进行打点，然后通过 [`onVideoRenderingTracingResult`](/api-ref/rtc/android/API/toc_video_rendering#callback_irtcengineeventhandler_onvideorenderingtracingresult) 回调获取视频帧渲染过程中的指标，从而方便开发者针对指标进行专项优化，以提高出图效率。

### 改进

#### 视频观测器

自该版本起，SDK 对 [`onRenderVideoFrame`](/api-ref/rtc/android/API/toc_video_raw#callback_ivideoframeobserver_onrendervideoframe) 回调进行了优化，在不同的视频处理模式下返回值的意义不同：

- 当视频处理模式为 `PROCESS_MODE_READ_ONLY` 时，返回值无实际含义。
- 当视频处理模式为 `PROCESS_MODE_READ_WRITE` 时，返回 `true` 代表设置 SDK 接收视频帧；返回 `false` 代表设置 SDK 丢弃视频帧。

#### 超分辨率

该版本提升了超分辨率的性能表现。为提升超分辨率易用性，该版本删除了 `enableRemoteSuperResolution`，超分辨率纳入画质增强线上策略的一部分，无需单独设置即可体验。

### 问题修复

该版本修复了以下问题：

- 使用媒体播放器播放采样率超过 48 kHz 的音频时，播放失败。
- 在红米 9A 上进行 CDN 推流，将推流的视频分辨率设置为 3840 × 2160 必现崩溃。
- 合唱模式下，OPPO R11 设备外放加入频道后，对端听到明显杂声和回音。
- 本地音乐文件结束播放时，未能触发 [`onAudioMixingFinished`](/api-ref/rtc/android/API/toc_audio_mixing#callback_irtcengineeventhandler_onaudiomixingfinished) 回调。
- 接收端通过视频观测器接收的第一帧视频帧偶现丢包。
- 在多频道场景下开启屏幕共享，偶现远端看到的本地屏幕共享画面为黑屏。
- 开启虚拟背景时切换至后置摄像头会导致背景倒置。
- 当频道内有多路视频流时，调用部分视频增强插件相关 API 偶现失败。
- 客户端主动退出频道时未向服务端发起请求，导致服务端判定为退出频道超时。

#### 蓝牙权限

:::info[信息]
如需开启音强选流功能，请[联系技术支持](https://ticket.shengwang.cn/)。

该版本新增音强选流功能，该功能开启后，声网服务器会根据音量大小对音频流进行筛选，选出 N 路音量最大的音频流并传输至接收端。N 默认为 3 路，如需自定义设置 N，请[联系技术支持](https://ticket.shengwang.cn/)。

该版本通过设置 [`RtcEngineEx`](/api-ref/rtc/android/API/rtc_interface_class#class_irtcengineex) 和 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 实现一个 [`RtcEngine`](/api-ref/rtc/android/API/rtc_interface_class#class_irtcengine) 实例同时采集多组音视频流并发布到远端：

同时，该版本支持通过 [`createCustomVideoTrack`](/api-ref/rtc/android/API/toc_video_custom_capturenrendering#api_irtcengine_createcustomvideotrack) 方法实现自定义视频采集。你可以参考如下步骤，体验同时发布多路自定义采集视频流：

1. 创建自采集视频轨道：调用 [`createCustomVideoTrack`](/api-ref/rtc/android/API/toc_video_custom_capturenrendering#api_irtcengine_createcustomvideotrack) 方法创建一个自定义视频轨道，并获得视频轨道 ID。

2. 设置频道中待发布的自采集视频轨道：在每个频道的 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 中，将 `customVideoTrackId` 参数设置为你想要发布的视频轨道 ID，并将 `publishCustomVideoTrack` 设置为 `true`。

3. 推送外部视频源：调用 `pushExternalVideoFrameEx`，并将 `videoTrackId` 指定为步骤 2 中指定的视频轨道 ID，即可实现在多个频道中发布对应的自定义视频源。

结合多频道能力，你还可以体验如下功能：

- 将多组音视频流通过不同的用户 ID (`uid`) 发布到远端。
- 将多路音频流混音后通过一个用户 ID (`uid`) 发布到远端。
- 将多组视频频流通过不同的用户 ID (`uid`) 发布到远端。
- 将多路视频流合图后通过一个用户 ID (`uid`) 发布到远端。

#### 全高清和超高清分辨率

为提升视频互动体验，SDK 对视频采集、编码、解码、渲染全流程做出了优化，自该版本起支持全高清 (FHD) 和超高清 (UHD) 视频分辨率。你可以在调用 [`setVideoEncoderConfiguration`](/api-ref/rtc/android/API/toc_video_basic#api_irtcengine_setvideoencoderconfiguration) 方法时，将 `dimensions` 参数设置为 1920 × 1080 或更高的分辨率。如果你的设备不支持高分辨率，SDK 支持自动回退到适合的分辨率。

:::info[信息]
- 超高清分辨率（4K，60 fps）目前为 Beta 功能，且对设备性能和网络带宽有一定要求，如需体验该功能，请[联系技术支持](https://ticket.shengwang.cn/)。
- 高分辨率通常需要更高的性能消耗，为避免设备性能不足导致体验下降，声网建议你在性能较好的设备上开启全高清和超高清视频分辨率。
- 高分辨率可能会影响集合分辨率从而导致费用变更。详见[计费策略](/zh-CN/realtime-media/rtc/billing/billing-strategy)。
:::

#### 内置媒体播放器

为减少 SDK 包体积、集成时间，以及简化 API 的调用步骤，该版本支持内置媒体播放器。调用 [`createMediaPlayer`](/api-ref/rtc/android/API/toc_mediaplayer_initialize#api_irtcengine_createmediaplayer) 创建媒体播放器后，你可以通过 [`IMediaPlayer`](/api-ref/rtc/android/API/rtc_interface_class#class_imediaplayer) 类的一系列方法体验内置媒体播放器的各类功能：

- 自动播放本地、在线、自定义的媒体资源。
- 预先加载待播放的媒体资源。
- 根据网络情况切换媒体资源的播放线路。
- 将媒体播放器的音视频流推送到任意频道、分享给远端用户。
- 实时缓存媒体资源文件，该功能开启后，播放器会预先缓存当前正在播放的媒体文件的部分数据到本地，可提高播放流畅度，帮助节省网络流量。

#### 实时合唱

该版本为实时合唱赋予了如下能力：

- 支持两人及两人以上合唱。
- 每位歌手相互独立。一位歌手出现问题或退出合唱，其他歌手还可以继续合唱。

该版本新增 `AUDIO_SCENARIO_CHORUS` 枚举来设置极低延时。使用该枚举后，在网络条件良好的情况下，用户可以体验到极低延时的实时合唱。

#### 增强的频道管理

为满足各类业务场景对频道管理的需求，该版本在 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 结构体中新增了如下功能：

- 设置或切换多种音视频源的发布
- 设置或切换频道场景、用户角色
- 设置或切换订阅视频的大小流类型
- 控制音频发布时延

在调用 `joinChannel` 或 [`joinChannelEx`](/api-ref/rtc/android/API/toc_channel#api_irtcengineex_joinchannelex) 时设置 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions)，明确媒体流发布和订阅行为，例如，是否发布摄像头采集或者屏幕共享的视频流，是否要主动订阅远端用户的音视频流。加入频道后，调用 [`updateChannelMediaOptions`](/api-ref/rtc/android/API/toc_channel#api_irtcengine_updatechannelmediaoptions) 随时更新 [`ChannelMediaOptions`](/api-ref/rtc/android/API/class_channelmediaoptions) 中的设置，例如，切换发布的音视频源。

#### 屏幕共享

该版本优化了开启屏幕共享的逻辑，你可以根据实际场景选择不同的方式开启屏幕共享：

- 在加入频道前调用 [`startScreenCapture`](/api-ref/rtc/android/API/toc_screencapture#api_irtcengine_startscreencapture)，然后调用 [`joinChannel`](/api-ref/rtc/android/API/toc_channel#api_irtcengine_joinchannel2)[2/2] 加入频道并设置 `publishScreenCaptureVideo` 为 `true`，即可开始屏幕共享。
- 在加入频道后调用 [`startScreenCapture`](/api-ref/rtc/android/API/toc_screencapture#api_irtcengine_startscreencapture)，然后调用 [`updateChannelMediaOptions`](/api-ref/rtc/android/API/toc_channel#api_irtcengine_updatechannelmediaoptions) 设置 `publishScreenCaptureVideo` 为 `true`，即可开始屏幕共享。

#### 设置音视频流订阅黑/白名单

该版本新增音视频流订阅黑/白名单功能，支持灵活订阅频道内发流用户的音视频流。你可以通过以下 API 来将指定用户的用户 ID 加入到相应的音视频黑白名单中，从而实现订阅/不订阅指定用户的音频或视频流。在多频道场景下，你可以通 [`RtcEngineEx`](/api-ref/rtc/android/API/rtc_interface_class#class_irtcengineex) 类下的同名方法来实现该功能。

- `setSubscribeAudioBlacklist`：设置音频订阅黑名单。
- `setSubscribeAudioWhitelist`：设置音频订阅白名单。
- `setSubscribeVideoBlacklist`：设置视频订阅黑名单。
- `setSubscribeVideoWhitelist`：设置视频订阅白名单。

如果某个用户同时在音频或视频订阅的黑、白名单中，只有黑名单会生效。

#### 设置音频场景

为方便用户灵活修改音频场景，该版本新增 [`setAudioScenario`](/api-ref/rtc/android/API/toc_audio_basic#api_irtcengine_setaudioscenario) 方法，支持你根据业务需求设置音频场景。例如，如果你在频道内想将音频场景从自动场景 (`AUDIO_SCENARIO_DEFAULT`) 切换为高音质场景 (`AUDIO_SCENARIO_GAME_STREAMING`)，你可以调用该方法。

#### 设置本地代理

该版本新增 [`setLocalAccessPoint`](/api-ref/rtc/android/API/toc_network#api_irtcengine_setlocalaccesspoint) 方法，用于在成功部署声网混合云、私有化平台后，指定 Local Access Point 来设置本地代理。你可以联系 sales@shengwang.cn 了解和部署声网混合云或声网私有化平台。

#### 垫片推流

该版本新增垫片推流功能，支持你在发流时使用本地 png 格式的图片来替代当前发布的视频流画面进行推流。你可以通过 [`enableVideoImageSource`](/api-ref/rtc/android/API/toc_image_source#api_irtcengine_enablevideoimagesource) 来开启该功能，并通过 `options` 参数自定义垫片图片；在你关闭垫片功能之后，远端用户看到的依旧是当前你发布的视频流画面。

### 改进

#### 快速切换频道

该版本通过 `leaveChannel` 和 `joinChannel` 切换频道即可实现和 v3.7.0 中 `switchChannel` 一样的切换速度，无需额外调用 `switchChannel` 方法。

#### 推送外部视频帧

该版本新增支持推送 I422 格式的外部视频帧，你可以通过 [`pushExternalVideoFrame`](/api-ref/rtc/android/API/toc_video_custom_capturenrendering#api_irtcengine_pushvideoframe2)[1/2] 方法将 I422 格式的外部视频帧推送至 SDK。

#### 本地人声音调

该版本在 `onAudioVolumeIndication` 的 [`AudioVolumeInfo`](/api-ref/rtc/android/API/class_audiovolumeinfo) 中新增 `voicePitch` 参数。你可以通过 `voicePitch` 获取本地用户的人声音调，从而实现唱歌评分等业务功能。

#### 设备权限管理

该版本新增 [`onPermissionError`](/api-ref/rtc/android/API/toc_network#callback_irtcengineeventhandler_onpermissionerror) 方法，当获取音频采集设备或摄像头权限开启失败时自动上报，用户可根据该回调的提示开启相应的设备权限。

#### 本地视频预览

该版本优化了 `startPreview` 方法的调用逻辑。如果你需要开启本地视频预览，你可以直接通过 `startPreview` 方法来开启视频预览，无调用时序要求。

#### 订阅视频流

你可以通过 `setRemoteDefaultVideoStreamType` 方法，根据你想要订阅的视频流分辨率和码率来灵活设置默认订阅视频流类型。
