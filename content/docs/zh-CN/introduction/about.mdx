声网提供构建实时互动应用所需的 API、SDK 和云服务。你可以用它实现音视频通话、互动直播、实时协作，也可以把用户和语音智能体接入同一个实时会话。

这些能力运行在声网自建的实时传输网络 SD-RTN™ 上，负责实时音视频和数据流的传输、路由、同步与会话管理。

## 接入前需要理解的核心概念

声网项目用于管理应用接入所需的 App ID、鉴权配置、服务开通状态和用量数据。客户端使用项目参数加入会话；服务端保存密钥，生成 Token，并调用需要服务端权限的 API。

开始接入前，需要先区分项目、App ID、App 证书、Token、客户端和服务端各自承担的职责。

### 账号、项目和控制台

**账号**用于登录声网控制台。你可以在同一个账号下创建多个**项目**，分别对应不同应用、环境或业务线。每个项目都有自己的 App ID、鉴权配置、服务开通状态和用量数据。

**声网控制台**用于创建项目、开通服务、查看用量和计费，并获取 App ID 或临时 Token。

如需完成控制台配置，参考[控制台指南](/zh-CN/introduction/quickstart)。

### 项目凭证和鉴权

| 参数 | 含义 | 用途 |
| --- | --- | --- |
| **App ID** | 声网为项目分配的唯一标识 | 客户端 SDK 和服务端请求用它识别项目；访问权限通常由 Token 或对应服务的鉴权机制控制。 |
| **App 证书** | 用于生成 Token 的项目密钥 | 只应保存在你的服务端，不能写入客户端应用或公开仓库。 |
| **Token** | 带有权限和有效期的鉴权字符串 | 提供给需要鉴权的 SDK 或 API。Token 的字段和作用范围取决于具体产品和操作。 |

RTC SDK 通常使用 App ID、频道名、用户 ID 和 Token 加入频道。生产环境中，Token 应由你的业务服务端生成；控制台临时 Token 适合测试和排障。

RESTful API 的鉴权方式由具体服务决定。例如，调用对话式 AI 引擎 RESTful API 需要遵循[HTTP 基本认证](/zh-CN/ai/build/http-basic-auth)。各服务的 Token 范围、签名方式和请求 Header 以对应 API 参考为准。

### 客户端和服务端职责

| 应用部分 | 常见职责 |
| --- | --- |
| **客户端** | 展示界面，请求麦克风或摄像头权限，使用对应 SDK 加入会话，采集、播放或接收媒体和事件。 |
| **服务端** | 保存密钥，生成客户端所需的鉴权信息，调用服务端 API 管理会话、任务或服务端资源。 |

RTC 客户端 SDK 负责把用户接入实时音视频会话。在对话式 AI 场景中，服务端还会使用 Agents SDK（用于在服务端管理智能体会话的 SDK）或 RESTful API 创建、停止和管理智能体会话。

## 实时会话与智能体如何协同

RTC 中的**频道**是一组参与者交换实时媒体的逻辑空间。用户加入同一个频道后，可以根据角色和业务逻辑发布或订阅音视频。

- **发布**：发送本地采集的音频或视频。
- **订阅**：接收其他用户发布的音频或视频。
- **用户 ID**：频道内用户的身份标识，同一频道中应保持唯一。有些 SDK 或 API 字段会写作 `uid` 或 `UID`。
- **用户角色**：在直播场景中，主播通常可以发布和订阅，观众通常只订阅。

在对话式 AI 场景中，用户侧客户端通常先加入 RTC 频道。你的服务端再使用 Agents SDK 或 RESTful API 创建智能体，让智能体加入同一个频道，与用户进行实时语音互动。

在这个流程中：

1. 客户端负责采集用户音频并播放智能体回复。
2. 服务端负责准备项目凭证、控制智能体生命周期，并配置 STT（语音转文字）、LLM（大语言模型）、TTS（文字转语音）等模型能力。
3. 声网提供 RTC 实时传输能力和对话式 AI 引擎运行能力。

如需了解更完整的 RTC 概念，参考 [RTC 关键概念](/zh-CN/realtime-media/rtc/reference/key-concept)。
