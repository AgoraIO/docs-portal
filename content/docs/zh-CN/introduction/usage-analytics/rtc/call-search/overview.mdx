## 通话调查简介

通话调查具有以下优势：

- 针对大规模通话场景，提高从通话级别问题定位至用户级别问题的调查效率。
- 分开呈现接收端与发送端的关键质量指标与事件，方便定位异常问题。
- 集成自动诊断引擎，提供直观的诊断结论，帮助降低调查成本。与自动诊断引擎相关的功能目前均处于 Beta 阶段。

### 功能概述

新版通话调查服务提供以下功能：

- 定位具体通话，详见[使用通话检索](#使用通话检索)。
- 了解频道整体质量情况，详见[查看通话全景](#查看通话全景)。
- 查询用户级别的指标和事件详情，详见[查看通话详情](#查看通话详情)。
- 查询用户级别的诊断信息，详见[查看通话诊断（Beta）](#查看通话诊断beta)。

## 使用通话检索

在通话检索页面，你可以通过频道名称、通话时间、通话卡顿率、通话人数等多个条件组合检索目标通话，查看通话基本信息。

参考如下步骤使用通话检索：

1. 登录[控制台](https://console.shengwang.cn/)，在左侧菜单栏中点击**水晶球** > **通话调查**。
2. 在页面左上角选择要查询的项目，即可查看该项目最近①发生的所有通话。
3. 通过以下任一方式检索通话：

   - 基本检索：在页面上方选择时间范围、频道名称或通话 ID、通话状态。

   - 高级搜索：点击页面右上角的**高级**，根据需要设置单个或多个筛选条件，然后点击**查询**按钮。

![通话检索页面示意图](https://web-cdn.agora.io/docs-files/1650250621594)

:::info[信息]
① 可查看的时间范围取决于[套餐包](/zh-CN/introduction/usage-analytics/overview/billing#管理套餐包)中通话调查功能的数据存储时间。
:::

## 查看通话全景

通话全景页面提供通话级别的异常情况统计、卡顿用户分布、时序趋势追踪和多维质量分析，帮助你快速了解大规模通话的整体情况，定位到具体问题或用户，从而进行用户级别的调查。

参考如下步骤进入通话全景页面：

1. 订阅专业版或旗舰版的水晶球套餐包，详见[订阅套餐包](/zh-CN/introduction/usage-analytics/overview/billing#订阅套餐包)。其余套餐包暂不支持查看通话全景。
2. [使用通话检索](#使用通话检索)找到要查看的通话，点击**操作**下面的**查看通话详情**。
   - 如果[累计通话人数（ACU）](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#acu累计通话人数)大于或等于 50 人，会自动进入通话全景页面。
   - 如果累计通话人数小于 50 人，会自动进入通话详情页面。你需要在页面上方点击**通话全景**页签，切换到通话全景页面。

通话全景页面由以下部分组成。

### 结论总览

结论总览展示在当前通话中发现的可能严重影响用户体验的问题，具体包括以下版块：

![通话全景结论总览示意图](https://web-cdn.agora.io/docs-files/1650253017752)

|  | 描述 | 注意事项 |
| --- | --- | --- |
| 诊断洞察 | 与音频卡顿、视频卡顿有关的重要结论。 | 该版块在符合条件时展示，注意事项见下方。 |
| 通话体验（Beta） | 通话中出现的严重体验问题。详见[诊断项](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#诊断项)。 | 点击某个问题可以跳转到对应的[通话诊断（Beta）](#查看通话诊断beta)页面，同时查看最多 10 个用户的诊断结论。 |
| 主播诊断（Beta） | 通话中主播用户遇到的问题。详见[诊断项](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#诊断项)。 | 点击某个问题可以跳转到对应的[通话诊断（Beta）](#查看通话诊断beta)页面，同时查看最多 10 个用户的诊断结论。 |
| 异常主播（Beta） | 通话中发流遇到异常的主播用户，展示用户 ID、上行时长、异常类型的信息。 | 如果主播诊断没有异常结果，该版块不展示。点击某条异常可以跳转到对应的[通话诊断（Beta）](#查看通话诊断beta)页面，查看该主播用户的诊断结论。 |

诊断洞察注意事项：

- 如果当前通话的[累计通话人数](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#acu累计通话人数)小于 20 人或者没有卡顿有关的结论，该版块不展示。
- 该版块的统计粒度为分钟，如果某一分钟内的在线人数不超过 20 人，则不纳入统计。
- 点击该版块右上角的箭头图标可以滑动至[数据统计](#数据统计)区域。

### 数据统计

数据统计使用多种图表展示通话级别的质量情况，便于监控与分析大规模通话。具体包括以下版块：

![通话全景数据统计示意图一](https://web-cdn.agora.io/docs-files/1650251547851)

![通话全景数据统计示意图二](https://web-cdn.agora.io/docs-files/1650251732639)

|                              | 描述                                                         | 注意事项                                                     |
| ---------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| 时间筛选器                   | 选择要查看的时间区间。                                       | 改变时间区间后，以下版块的数据都会更新。                    |
| TOP 视频卡顿用户/视频卡顿情况 | 根据累计通话人数展示 TOP 视频卡顿用户或视频卡顿情况，规则见下方。 | / |
| TOP 音频卡顿用户/音频卡顿情况 | 根据累计通话人数展示 TOP 音频卡顿用户或音频卡顿情况，规则见下方。 | / |
| 时间序列趋势追踪             | 展示音频卡顿用户、视频卡顿用户、在线用户数、[音频卡顿率](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#音频卡顿率)和[视频卡顿率](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#视频卡顿率)随时间变化的趋势。 | 该版块展示条件和统计规则见下方。 |
| 多维分布                     | 音频卡顿率和视频卡顿率在地域、设备、网络、SDK 版本、系统维度的分布情况。 | 如果当前通话的累计通话人数不超过 20 人，该版块不展示。   |

数据统计版块说明：

- TOP 视频卡顿用户/视频卡顿情况：
  - 如果当前通话的[累计通话人数](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#acu累计通话人数)不超过 20，则显示为 **TOP视频卡顿用户**，按卡顿率的倒序列出所有用户。
  - 如果当前通话的累计通话人数大于 20，则显示为**视频卡顿情况**，按卡顿率分桶显示用户分布。
- TOP 音频卡顿用户/音频卡顿情况：
  - 如果当前通话的累计通话人数不超过 20，则显示为 **TOP 音频卡顿用户**，按卡顿率的倒序列出所有用户。
  - 如果当前通话的累计通话人数大于 20，则显示为**音频卡顿情况**，按卡顿率分桶显示用户分布。
- 时间序列趋势追踪：
  - 音频卡顿用户指音频卡顿率大于 3% 的用户人数。
  - 视频卡顿用户指视频卡顿率大于 5% 的用户人数。
  - 如果当前通话的累计通话人数不超过 20 人，该版块不展示。
  - 该版块所有指标的统计粒度均为分钟。
  - 时序图左侧展示的最大在线人数仅作参考。准确的[最大同时在线人数](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#pcu最大同时在线人数)可以在页面顶部查看。

## 查看通话详情

通话详情页面可以帮助你定位到用户级别的质量问题和异常事件。

通话详情页面包含以下子页面：

- 通话详情主页：点击**通话详情**页签进入的页面。该页面支持查看所选通话中每个用户的基本信息，以及同时查看 20 个用户的关键事件和音视频质量指标。
- 端到端详情页面：单独查看一对发送端和接收端的所有关键质量指标和事件。
- 发送端详情页面：单独查看一个发送端的所有关键质量指标和事件。

每个页面的具体介绍详见[查看通话详情](/zh-CN/introduction/usage-analytics/rtc/call-search/call-detail)。常见通话质量问题的排查详见[常见问题排查指南](/zh-CN/introduction/usage-analytics/rtc/call-search/troubleshooting)。

## 查看通话诊断（Beta）

通话诊断页面内嵌声网自动诊断引擎，可以对用户体验进行诊断，帮助你发现异常，并且将体验异常与根因异常进行归因匹配，给出完整的推测结论。目前支持的诊断项包含通话体验问题和主播问题，详见[诊断项](/zh-CN/introduction/usage-analytics/rtc/call-search/concept#诊断项)。

参考如下步骤查看通话诊断页面：

1. [使用通话检索](#使用通话检索)找到要查看的通话，点击**操作**下面的**查看通话详情**。
2. 在页面上方点击通话诊断（Beta）页签。
3. 根据需要添加筛选条件：
   - 诊断对象：输入用户 ID 逐一添加，或者使用高级搜索批量添加。最多可添加 10 个用户作为诊断对象。
   - 时间：拖拽滑块或者从下拉菜单中选择。
   - 异常：在下拉列表中选择异常类型，包括发送端异常、接收端异常、网络异常、采集异常、行为异常、体验异常等。
4. 点击要查看的用户，可以看到具体的诊断结论：
   - 如果显示一个用户 ID，代表是该用户的诊断结论。
   - 如果显示两个用户 ID，代表是一对发送端和接收端用户的诊断结论。
5. （可选）点击**查看详情**：
   - 如果是单个用户的诊断结论并且该用户为发送端用户，会跳转到[发送端详情页面](/zh-CN/introduction/usage-analytics/rtc/call-search/call-detail#发送端详情页面)。
   - 如果是单个用户的诊断结论并且该用户为接收端用户，会跳转到[通话详情主页](/zh-CN/introduction/usage-analytics/rtc/call-search/call-detail)并为该用户打开**查看详情**的开关。
   - 如果是一对发送端和接收端用户的诊断结论，会跳转到[端到端详情页面](/zh-CN/introduction/usage-analytics/rtc/call-search/call-detail#端到端详情页面)。

![通话诊断页面入口示意图](https://web-cdn.agora.io/docs-files/1650252884406)

## 反馈意见

与自动诊断引擎相关的功能目前均处于 Beta 阶段。你可以通过以下方式对诊断功能给予反馈：

1. 鼠标悬浮在以下任一区域展示的诊断结论上：
  - 通话诊断页面。
  - 通话全景页面的通话体验（Beta）、主播诊断（Beta） 或异常主播（Beta）版块。
2. 鼠标移动至高亮文字**准不准**。
3. 点击**诊断准确**或**诊断不准**。
4. （可选）在文本框中填写详细描述。
5. 点击**提交**。
