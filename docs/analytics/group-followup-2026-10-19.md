## 去掉中文 URL 前缀仍有配套依赖

本次核对的是当前 staging 和应用源 `e113a4246`，没有修改已验证的路由或发布配置。[PR #1211](https://github.com/AgoraIO/docs-portal/pull/1211) 只准备无前缀的旧站跳转目标，没有实现无前缀应用路由。

| 依赖 | 已确认的现状 | 去前缀时的验收要求 |
| --- | --- | --- |
| 采集启用 | `src/lib/analytics/measurement.client.ts` 用 `/zh-CN/` 判断中文范围 | 改用与路由一致的中文范围判定；无前缀正文、搜索及反馈仍能收到事件，英文和错误页不误收 |
| 搜索地址 | `src/lib/search/cn-search-page.ts` 校验中文前缀；`cn-search-strategy.ts` 的排名分类也依赖前缀 | 同步调整索引 URL、地址校验和分类，重建配套索引，实际点击到达正文和锚点 |
| 搜索参数 | 当前 `/search?q=Token&platform=web` 返回 301，Location 为 `/zh-CN/search`，参数丢失；带前缀入口的尾斜线跳转会保留参数 | 新站直接服务 `/search`；跨域迁移另按 host 处理，保留关键词和筛选条件，避免同路径自循环 |
| 历史链接与引用 | 已有搜索结果、AI 引用、收藏和分享可能包含前缀 | 保留带前缀旧地址到新地址的兼容，覆盖查询与锚点；核对 canonical、sitemap 和 AI 引用 |
| 报告连续性 | 本次流量查询已合并两种地址；P0 正文/反馈报告仍使用采集时的 canonical path | 明确文档身份和历史地址别名，按发布区间验收，避免同篇文档拆成两份 |

因此，仅替换重定向产物并重新部署，不能完成整站去前缀。流量查询的地址归类通过，也不代表应用路由迁移已验收。
