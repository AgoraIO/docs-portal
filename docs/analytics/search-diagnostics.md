# 中文搜索漏报修复与无结果诊断

本次范围：修复弹窗展示/点击漏报；两个入口记录可定位的空结果和受控错误；提供服务端请求追踪、恢复操作与诊断查询。保留逻辑搜索、首屏可见、翻页和重试的现有口径，不调整召回、排序或索引内容。

## 事件与归因

- 弹窗不再通过数组对象身份关联快照。每次请求返回 `{ items, snapshot }`，两者一起被接受或丢弃；旧请求晚返回、关闭弹窗、输入法组合与筛选变化均不能让快照串到另一批结果。
- `docs_search_results_presented` 包括成功且真正可见的空结果。`result_count` 为当前入口所见条目数；`total_hits` 为引擎匹配章节数；`server_group_count` 为 API 返回、浏览器公开 URL 过滤前的分组数。三个单位不能互换。
- `result_outcome`：`results` 有可见条目；`no_hits` 引擎命中为零；`no_visible_results` 引擎有匹配但界面为空；`empty_unknown` 缺少引擎计数。后两者不能自动断言内容缺失或前端故障，需用请求复现。
- 关键词继续使用 `query_redacted`，敏感输入统一为 `[redacted]`；保留产品、平台、类别、入口、搜索/请求/视图 ID。点击携带所见快照的请求 ID 和索引版本。
- `docs_search_failed` 使用 `network/network_error`、`http/http_error`、`parse/invalid_response`；未知异常保留 `request/search_unavailable`。HTTP 状态单列，原始异常、响应正文和服务凭据均不上报。已取消和过期响应不产生用户可见失败事件。
- `docs_search_recovery_selected` 记录 `retry`、`clear_filters`、`open_full_search`，使用操作前的搜索上下文。改词/筛选后的新搜索仍由 `parent_search_id` 关联；恢复操作本身不是成功或解决问题。

## 服务端追踪与索引版本

API 对每个带非空查询的有效请求输出一条 JSON 结构化日志 `docs_search_request_completed`，包含请求/搜索 ID、脱敏查询、筛选条件、页码、HTTP 状态、耗时、引擎命中数和返回分组数。缺少请求 ID 时由服务端生成并通过 `X-Docs-Request-Id` 返回；外部传入标识仍须通过 UUID 校验。错误的结果计数为 `null`，不伪造成零。

该记录写入服务进程 stdout，不依赖前端埋点，也不直接发送到 PostHog。部署环境的日志采集系统需保留这些 JSON 行，才能按请求 ID 检索；如需在 PostHog 联表，应由已有日志管道另行接入，不能把浏览器事件当作独立服务端证据。日志记录不额外访问分析服务，不增加外部采集请求对搜索的等待。

`DOCS_SEARCH_INDEX_REVISION` 是可选的服务端运行时配置，仅在已确认当前读索引的版本时填写完整 40 位提交 SHA；索引提升/回滚时同步更新。未配置或无效时返回/记录 `null`。不以应用提交替代索引版本，也不声称该字段是实时查询引擎内部元数据。需要发布责任人核对配置与当前索引的一致性。

## 面板与排查

`report-selects.json` 新增三份可导入既有搜索面板的查询：

1. `search_empty_details`：按展示时间，列出所选窗口内每次逻辑搜索首次首屏展示为空的上下文和请求 ID。它是诊断清单，不替代现有按提交时间构建的正式 `docs_search_facts` 指标。15 条历史空结果应先从现有事件排查，新增字段不会回填历史事实。
2. `search_failure_details`：网络、HTTP、解析错误明细，按请求 ID 去重。
3. `search_measurement_gaps`：提交至少一分钟后仍未见展示/失败的搜索线索。关闭弹窗、改词或离开也会造成缺口，不能逐条直接告警为漏报。按入口和应用版本观察持续异常，待基线建立后再设置阈值。

查询沿用环境、流量类型、入口、应用版本、产品与平台筛选。历史事件没有的新字段保留未知。查询文件的新增不等于远端 PostHog 面板已更新；导入后须在真实项目验证 HogQL 以及时间/过滤变量。当前任务不自动配置通知或周期任务。

排查顺序：先区分失败和空结果，再对照 `total_hits`、`server_group_count` 与 `result_count`，最后用请求 ID 找服务端日志，并按记录的关键词/条件复现。清除筛选后有结果，是筛选影响的线索；仍无结果时继续查索引覆盖、内容与召回规则，不能由零计数直接得出原因。

## 验收

- 回归测试先在原实现观察展示/零结果事件缺失，再验证正常结果点击、空结果、连续查询旧响应晚返回、错误重试、清除筛选、服务端日志脱敏及采集边界字段保留。
- 运行聚焦测试、全量测试、类型检查和 lint；保留已有失败及基线对照，不能把有失败的套件描述为通过。
- 上线后分别在弹窗和完整页执行有结果、无结果、HTTP 失败、改词和清除筛选，核对 PostHog 同一 `search_id` 的提交/展示/点击及日志 `request_id`。远端面板导入、索引版本配置和生产采集核验属于部署验收。
