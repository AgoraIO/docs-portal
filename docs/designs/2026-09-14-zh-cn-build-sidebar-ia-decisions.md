# 中文产品 Build 导航 IA 决策记录

本文记录对 `2026-09-14-zh-cn-build-sidebar-ia-options.md` 的逐产品讨论结论。除非另有说明，导航层级不超过两层；目录仅承载 Build 任务，不纳入产品介绍、快速开始、计费、下载或 API 参考。

## 实施边界

本次是完整的 IA 迁移，而非只调整侧栏：页面文件和 `meta.json` 必须移动到与本记录中各分组对应的物理目录。目录路径、`meta.json` 和侧栏层级必须一一对应；仅目录调整时不能保留旧位置的内容副本。

Fumadocs 根据 `meta.json` 中的 `pages` 列表生成侧栏。每个引用必须继续解析到一个页面或子目录，否则页面会从侧栏消失或导致构建检查失败。水晶球隐藏项继续使用 `!` 前缀。

本地服务端录制的 `build/legacy` 是唯一例外：其目录、页面文件、`meta.json`、页面顺序和折叠行为均不移动、不修改。

## 链接与兼容性

- 为每个已移动的中文页面，在 `src/lib/zh-cn-product-ia-redirects.ts` 中添加“旧相对路径 → 新规范 URL”的映射；旧 Build 路径必须返回 301，并保留查询参数和锚点。
- 全仓扫描 Markdown、MDX、JSON 和 TypeScript 中指向旧路径的站内链接。相对链接随文件移动改写；绝对的 `/zh-CN/...` 链接改为新规范 URL；导航、卡片、测试夹具和重定向目标也纳入扫描范围。
- 不为旧位置保留重复内容文件。旧 URL 仅通过既有的产品 IA 重定向机制访问新位置，避免重复索引和两套规范路径。
- 移动后重新审计每页的相对资源与文档链接；对无法确定的跨页链接保留原始证据并单独列出，不能静默删除。

## 验证要求

- 逐页对照本记录检查五个 Build 侧栏的标题、分组和顺序。
- 对每个迁移页面确认旧文件不存在、新文件存在且内容保持；确认 `content/docs/zh-CN/realtime-media/local-server-recording/build/legacy/` 的页面和 `meta.json` 完全未修改。
- 确认水晶球的“指标 ID 表”和“分析信令数据”仍隐藏。
- 对每个旧 Build URL 断言 301 指向对应新 URL；对每个新 URL 断言可直接加载。将这些断言加入现有的中文产品 IA 回归测试。
- 扫描并验证迁移范围内没有指向已删除物理路径的站内链接；审查 `src/lib/zh-cn-product-ia-redirects.ts` 中全部新增重定向的目标是否存在。
- 运行 `bun run types:check` 和 `bun run test`。
