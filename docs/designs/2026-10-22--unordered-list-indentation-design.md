## 目标

修复中文迁移文档中由转换错误引入的列表层级，保持同级项目符号及文字起点对齐，并保留真实嵌套、正文、数值、顺序与链接。

分支：`codex/cn-newdoc-html-api-migration`。本次诊断基于本地提交 `9fa19b226`；本地落后已缓存的远端分支 9 个提交。已检查这 9 个提交中相关迁移函数及配额页面的差异：本问题相关逻辑和两份配额页面没有变化。实现前应再次检查分支状态，安全同步最新分支，并重新运行复现。

不执行合并、发布，也不改写正常嵌套或英文内容。

## 已验证的根因链

1. 旧源 `shengwang-doc-source/shared/cloud-recording/pcw.mdx:35` 中，SD、HD、FHD 在 `<Td>` 内均缩进 6 个空格；`stream-number-limit.mdx` 内同级列表统一缩进 4 个空格。这些空格用于旧 JSX 容器的源码排版。
2. `scripts/migrate-legacy-docs.mjs` 的 `normalizeSlotDefinitionContent` 未移除整个块的公共缩进，就调用字符串 `.trim()`。这只清除了第一项前面的空格，后续项目仍保留原缩进。
3. `content/docs/zh-CN/realtime-media/cloud-recording/reference/quota.mdx:19` 因此成为：

   ```md
   - SD: 100
         - HD: 50
         - FHD: 30
   ```

4. 本地页面 DOM 实际为 `ul > li(SD) > ul > li(HD/FHD)`。`remarkTableSlots` 将已解析的列表节点复制进表格，不改变层级。
5. 浏览器计算出的内外层 `ul` 左内边距均为 16px；文字起点为 SD=492px、HD=508px、FHD=508px。这是错误嵌套被正常排版后的结果。

结论：已确认的截图问题来自迁移转换，不需要用 CSS 覆盖嵌套缩进。

- 651 是待核实候选数，不能当成已确认错误数。形态相似的列表可能具有合法嵌套，必须对照源内容。

## 方案比较

| 方案 | 内容 | 收益与代价 |
| --- | --- | --- |
| A：只修已知配额页 | 修改两份配额文档的列表缩进 | 改动小，但其他同类页面及后续迁移仍会出错 |
| B：公共转换修复 + 有证据的正文回填（推荐） | 修复 Slot 内容公共缩进处理，对照旧源修复已迁移槽位 | 解决已知根因并防止重现；需要映射和核实历史内容 |
| C：运行时统一去除表格嵌套缩进 | 通过 CSS 或渲染器让嵌套看起来同级 | 会掩盖错误 DOM，并破坏真实子列表，不满足语义保留要求 |

## 推荐方案 B 的实现边界

### 公共转换

在处理旧表格单元格时，先移除整块共同的源码缩进，再进行 HTML 列表转换、块间空行处理和首尾清理。复用现有 `trimCommonIndent` 或同等的块级逻辑，保留项目之间的相对缩进。

需要验证标签换行、首行直接接在标签后、HTML 列表、已有顶格 Markdown、列表引导段落、嵌套列表以及含代码块的单元格。公共缩进无法安全推断时，保留并报告，不逐行 `trimStart()`。

### 已迁移正文回填

使用迁移来源元数据、path-map 和旧共享内容确定源单元格。仅当旧源能证明同级关系、且目标项目文字和顺序可匹配时，更新对应 Slot 内缩进。

保留目标文档后续已编辑的名称、链接、数据、元信息和正文；不重新生成整篇文档。仅凭 Slot 名称或“首项顶格”的形态不能决定拉平。存在歧义、来源缺失、匹配不唯一或与目标后续编辑冲突时，记录具体位置与原因。

以同一源内容为基础的指南和 API Reference 副本均纳入检查。真实嵌套由源内容和渲染回归共同约束。

### 待修改文件

- `scripts/migrate-legacy-docs.test.ts`：实际转换入口的回归测试。
- `content/docs/zh-CN/**`：经旧源核实的槽位；最终文件清单由审计产生。
- 如需批量回填工具，仅处理上述可证明的映射并输出差异清单，默认检查模式，重复执行不再产生变化。

生产 CSS 和运行时 Slot 解析器目前没有需要修改的证据。
