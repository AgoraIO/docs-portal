# 中文文档全量链接检查方案

状态：方案已获批准并已实现；实际命令及边界见 [使用说明](./cn-doc-link-validation.md)。

基准分支：`codex/cn-newdoc-html-api-migration`，提交 `536a6f22621afe0e0657f2f0ad655ee5f42dfd6f`。
工作分支：`codex/cn-doc-links-validation`。

## 验收目标

对该提交的 `content/docs/zh-CN/**` 建立完整链接清单，验证用户最终看到的链接是否到达对应内容。覆盖 Markdown/MDX、共享内容展开、平台/版本变体、页面生成组件、中文 OpenAPI 页面、图片与下载资源。对每一条链接记录来源、检查证据与结论。

“全量”同时要求页面覆盖和链接覆盖，不能从首页递归爬取后把未发现的孤立页面算作通过。隐藏导航但仍可访问的页面需要检查。已退役或不发布的内容单列；发布页面指向这些内容仍然是问题。

外部服务的可达性是一次运行时的观测结果，需记录检查时间。登录、反爬、限流、超时或无法判断的页面必须标为待核查，不能作为有效链接计入通过率。

## 已有能力和缺口

- `scripts/audit-doc-links.mjs`：检查 Markdown/引用式链接和 HTML `href`、内部路径与部分锚点，支持外链请求。模块接口接受 `sourcePaths`；CLI 没有全中文范围参数，不能把不存在的 `--locale=zh-CN` 参数当作已支持。
- 此脚本以正则抽取链接；代码示例中的伪链接、复杂 MDX 表达式、自动链接、组件生成链接需要进一步核对。`src`/`srcset` 没有完整纳入；部分本地资源直接跳过检查。
- 其锚点从源码推导，无法代替最终 HTML 与交互状态检查；API 宏、模板链接也有单独跳过的分支。
- 外链检查默认不启用；启用后部分 401/403/429 归入 skipped。因此退出码 0 不等于每条链接已验证。
- `api-center:links` 基于迁移 ownership 清单，不能代表全部中文文档；`api-center:links:check` 还检查已生成报告是否过期。
- `scripts/search/verify-cn-public-urls.mjs` 校验搜索记录对应的线上 HTML，但搜索记录不涵盖全部页面，也不涵盖正文中的每条链接。
- 中文站使用无 `/zh-CN` 前缀的公开路径，源码与构建清单仍可能保留此前缀。必须区分源文件、构建路径、用户实际访问 URL。

## 方案选择

| 方式 | 能力 | 限制 |
| --- | --- | --- |
| 只运行现有源码审计 | 快速定位路径和部分锚点问题 | 无法证明资源、生成链接、页面部署及交互状态完整可达 |
| 只爬预览站 | 检查实际返回内容 | 漏掉孤立页面、未激活的平台/折叠内容，来源定位困难 |
| 源码清单 + 构建验证 + HTTP/浏览器验证（推荐） | 同时核对覆盖率、最终目标和部署行为 | 首次需要完整中文构建及网络检查，成本较高 |

## 第一层：链接清单和静态检查

1. 枚举全部中文 MD/MDX 与适用于中文的 OpenAPI 输入；保持完整目标索引，不能为了筛选来源而只索引一个目录。
2. 使用 Markdown/MDX AST 收集链接、引用、自动链接、HTML/JSX `href`、资源 `src`/`srcset`、卡片和指令属性；排除不会渲染为可点击内容的代码和注释。保留文件、行列、原始链接和所属平台/版本。
3. 复用项目现有 include、API 宏和路由规范化逻辑。动态属性无法静态求值时登记 unresolved，交给渲染阶段补齐，不静默丢弃。
4. 依据发布路由清单解析相对路径、路由组 `(current)`、平台后缀、版本、编码、查询参数与跳转规则。保持实际浏览器解析语义，不能通过过度纠正链接掩盖错误。
5. 检查本地资源是否有对应发布文件。远程图片、视频封面、下载包归入网络验证。
6. 区分 HTTP(S)、同页片段、mailto/tel 等协议。后者不宣称 HTTP 可达；已知非 HTTP 行为明确列为不适用，未知或不支持的协议标为待核查。

## 第二层：实际构建内容验证

执行完整中文构建：

```bash
VITE_DOCS_REGION=cn bun run build
```

不可使用限定部分 prerender 路径的构建冒充全量结果。读取生成的 `public/__static/docs-routes.json` 与 `dist/client`，核对每个应发布页面是否生成正文；OpenAPI 页面从实际注册和发布清单进入范围，不要求它们存在 MDX 文件。

从页面正文、相关卡片和页面导航提取最终 `a[href]`、图片和资源地址，与源码清单合并并保留所有来源关系。生成组件没有直接的源码行时，记录组件及源页面。

目标锚点以最终 HTML 的 `id`/兼容 `name` 为依据。平台、代码标签页、版本折叠区可能只渲染当前状态：枚举有内容差异的状态，加载对应内容，核对深链接能否激活正确状态、展开目标并定位。仅在其他未激活状态里发现同名 ID 不算当前链接通过。

源码清单与渲染清单不匹配时输出差异；任何解析失败、页面构建失败或未处理的动态内容都使完整性状态变为 INCOMPLETE。

## 第三层：HTTP 与浏览器验证

- 对该提交对应的预览部署指定 `origin`，访问所有中文公开路由及去重后的内部目标。保留每次跳转及最终 URL，检查循环、过多跳转、错误首页和登录页跳转。
- 不以 HTTP 200 单独判定有效。核对正文标记、页面身份和预期构建内容，识别 SPA 壳、软 404、过期部署；可复用搜索 URL 校验器的构建 HTML 摘要思路，适配合法跳转。
- 旧站绝对链接保持原始 URL 进行检查，另行报告是否应该迁移到新站；不能悄悄替换域名再声称原链接已通过。
- 外链按实际网络 URL 去重，保留查询参数；片段单独校验。使用有限并发、每域限流、超时、重试和重定向上限。HEAD 失败或内容需要核验时使用 GET，并控制响应体大小。
- 404/410 为明确断链；5xx、DNS/TLS/超时、401/403/429 等保留具体原因并复核，暂未确认的结果归为待核查。禁止用无说明的域名白名单制造全绿。
- 外部 HTML 的片段尝试从实际 DOM 验证；JS 动态页面、认证页面和需要交互的目标使用浏览器复核。仍无法确定时保留未确认状态。
- 对本地互动内容枚举状态，对无法通过静态/HTTP 确定的链接执行浏览器复核；不能把抽样浏览器检查描述为每条链接均已验证。

## 报告和通过标准

输出机器可读 JSON 和便于处理的 Markdown/CSV，默认放到 `.agent/artifacts/cn-links/`。

每条记录至少包含：源码文件与行列、源页面 URL、平台/版本、原始 href、规范化目标、来源类型、跳转链、最终 URL、HTTP 状态、锚点检查结果、结论、失败原因、检查时间。

汇总同时展示文档数、发布路由数、应检查/实际检查页面数、链接出现次数、唯一网络目标数、有效/断链/待核查/不适用数量；断链按目标归并，同时列出全部引用位置。

- PASS：页面与链接清单完成核对，所有适用目标均已验证有效，断链和待核查均为 0。
- FAIL：存在已确认断链或错误目标。
- INCOMPLETE：覆盖缺失、解析/构建失败、网络或动态内容仍待核查。即使断链数为 0，也不能宣称全部可达。
- 不适用项目必须有明确类型和原因，不能用于容纳未验证的 HTTP(S) 链接。

已新增三个执行入口：`docs:links:cn` 做静态清单检查，`docs:links:cn:built` 做构建内容检查，`docs:links:cn:full --origin <该提交的预览站>` 汇总全量网络/浏览器验证。完整验收模式只在 PASS 时退出 0；断链与不完整使用不同非零退出码。

建议 PR 执行确定性的静态和构建检查；发布前对对应预览部署执行完整网络验证。后续需要周期检查时再配置任务。

## 实现验证

针对漏检和误判建立小型 fixture：复杂 Markdown/MDX、引用链接、代码中的伪链接、include/宏展开、孤立页面、图片缺失、路由组、平台与版本、中文/重复标题 ID、编码片段、OpenAPI 页面、200 软 404、重定向循环、HEAD 不支持、限流与超时。

网络行为使用本地 HTTP fixture 验证，避免单元测试依赖公网。大仓库实测报告单独保存。实现完成后运行相关测试、`bun run test`、`bun run types:check`，并记录完整中文构建和预览部署的证据。

本轮先检查并报告问题；修复正文链接可在报告基础上另行实施，不能用删链接或跳过检查改变通过标准。
