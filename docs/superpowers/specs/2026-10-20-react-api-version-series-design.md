# React API 双版本系列随页面切换

## 已确认的交互

React SDK 的概览、组件、Hooks 和类型页面显示 React SDK 版本列表。点击 Web SDK API 或进入其下任意类、接口、枚举页面后，同一位置的版本下拉改为底层 Web SDK 系列；返回 React SDK 页面后自动切回。

每个系列只有 current 使用本站内容，历史版本继续使用旧站归档外链并在新标签页打开。切换系列由当前页面路径决定，不持久化一个可能与 URL 不一致的系列选择。刷新、直接打开深层链接、浏览器前进后退和移动端遵循同一规则。

## 基线与保留内容

从已包含 PR #1244、#1245 的目标分支基线 `7ed48130f4` 开始；工作分支为 `codex/react-api-version-series`。沿用 #1245 完成的 React/Web SDK 目录，保持当前页面 URL、侧栏层级、默认展开及全部 API 正文不变。

默认 React SDK 页面为 `rtc/react-sdk/**`；其中 `rtc/react-sdk/web-sdk` 及其后代页面属于 Web SDK 系列。路径匹配按完整片段边界，不能用任意子串匹配，且忽略查询参数和 hash。

## 接入方式与边界

推荐在现有 React 根 `meta.json` 的 navScope 维护默认版本列表，并增加路径匹配的版本列表覆盖，例如 `versionOverrides`。每个覆盖以相对范围路径匹配，对应自己的完整版本数组。

解析器根据当前路径选取默认或最具体的覆盖列表，供当前版本识别和 header.versionSwitcher 使用；导航 scope 与 sidebarRoot 仍为 React 根，不能因为版本列表切到 Web 而丢失 React 的四个入口或 Web 子目录。

两套 current 都显式指向各自本站概览，使用根范围路径以保持侧栏；历史项使用各自清单中的完整 href。两个系列可分别使用 `current` ID，但在任一实际展示的列表内 ID 必须唯一，不将两个系列合成一个数组。

考虑过两种替代：给 Web SDK 新增独立 navScope（会改变侧栏上下文与返回路径），或增加手动系列切换控件（额外操作且容易与当前页面不一致）。本轮不采用。

## 版本数据

依据已保存的历史归档清单中 React 的 9 个选项：React wrapper 的本站 current 标签为 v2.5.0，历史 v2.4.0、v2.3.0、v2.2.0、v2.1.0、v2.0.0、v2.0.0-beta.0；底层 Web SDK 的本站 current 为 v4.22.0，历史 v4.21.0、v4.20.0、v4.19.3。

React 历史目标保留旧 `/rtc/react/react-sdk/overview` 路径，底层 Web SDK 历史目标保留旧 `/rtc/react/overview`，不使用新站路径拼接。当前 Web 正文标题已明确为 v4.22.0；不因版本标签更改 API 正文。实施时对 9 个归档入口检查可达性及同版本证据，有失效或版本不符则记录并调查，不猜测替换版本。

## 回归与生成器

原先保护“React 暂不接入”的清单测试需更新为保护两个系列互相隔离：原 43 平台的 219 项不变，React 新增 6 项、Web 新增 3 项。默认上下文及覆盖匹配测试覆盖刷新/深链、路径边界、优先级、查询参数/hash 与回退；真实页面 payload 测试保护侧栏和 current 标签/历史列表正确。

现有 DropdownMenu 组件不改造，复用它的外链、安全属性、移动端与选中态。检查导航生成器会保留整个手工维护的 navScope，包括版本覆盖，避免后续生成时丢失双系列配置。

实施前先写失败测试，再最小修改 schema、解析器和 React 根元数据。实施后运行完整测试、类型检查、lint，并在 zh-CN 预览核对 React → Web SDK 概览 → Web 接口 → React 的连续切换、刷新、浏览器后退以及移动端。

## 本轮不做

不修改其他产品的版本清单，不改变通用 RTC Web 的版本列表，不迁移历史正文，不改 API 页面 URL，不自动推送、创建 PR 或合并。
