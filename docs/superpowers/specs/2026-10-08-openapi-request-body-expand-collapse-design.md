# OpenAPI 请求 Body Schema 全部展开/折叠设计

## 背景

OpenAPI 参考页的请求 Body 会以递归字段树展示 Schema。当前字段树支持逐个字段展开或折叠，并默认展开必填字段、折叠可选字段。当请求体较深或字段较多时，用户需要连续点击多个字段才能查看完整结构。

本次改动只面向请求 Body 的 Schema 树。响应状态码面板、查询/路径/Header 参数，以及其他请求 Body 实例不受该按钮控制。

## 用户交互

在“请求 Body”标题和第一个 Schema 字段之间增加一个右对齐的小型控制按钮，与请求媒体类型区域保持同一右边界。界面结构如下：

```text
请求 Body                                      application/json
                                      [全部展开]
name  string  必填
      智能体唯一标识，相同标识不可重复创建。
```

按钮文案根据当前树状态切换：

- 只要仍有可展开字段未展开，显示“全部展开”；
- 所有可展开字段均已展开后，显示“全部折叠”。

点击“全部展开”会展开当前请求 Body Schema 树中所有拥有子节点的字段。点击“全部折叠”会折叠这些字段。没有子节点的叶字段不参与状态判断。

初次渲染继续沿用现有默认状态：必填字段和根容器按现有规则展开，可选字段按现有规则折叠。按钮只改变用户主动操作后的展开状态。

## 组件与状态

`OpenApiSchema` 继续负责判断当前 Schema 是否为请求 Body，并把 Schema view 传给 `OpenApiSchemaTree`。统一控制状态放在 `OpenApiSchemaTree` 内部，与现有 `expandedIds` 状态共享同一套节点 ID。

新增一个从树节点递归收集可展开节点 ID 的纯函数。统一展开将这些 ID 写入 `expandedIds`；统一折叠将其移除。按钮是否显示“全部展开”由可展开节点集合和 `expandedIds` 的包含关系计算得出。

现有的手动字段切换、URL/path 定位、原生查找触发展开、Schema identity 重置和复制字段链接逻辑保持不变。统一操作只作用于当前 `OpenApiSchemaTree` 实例，因此不同请求 Body 之间不会共享状态。

按钮需要使用项目现有的可访问按钮模式，提供明确的可见文案和 `type="button"`，不触发表单提交。文案通过现有 OpenAPI 翻译/标签传入，至少覆盖中英文页面。

## 失败与边界行为

- Schema 没有可展开字段时不显示统一控制按钮。
- Schema 数据变化或请求 Body 切换导致树 identity 重置时，恢复现有默认展开状态，并重新计算按钮文案。
- 用户通过 URL 定位或浏览器原生查找触发某个隐藏字段展开时，统一按钮状态随 `expandedIds` 更新。
- 统一折叠不移除节点，也不影响隐藏搜索路径和锚点定位能力。

## 测试

为 `OpenApiSchemaTree` 增加覆盖以下行为的组件测试：

1. 有可展开字段时显示“全部展开”，没有可展开字段时不显示按钮。
2. 点击“全部展开”后所有可展开节点的 `aria-expanded` 为 `true`，按钮文案切换为“全部折叠”。
3. 点击“全部折叠”后所有可展开节点的 `aria-expanded` 为 `false`，按钮文案切换回“全部展开”。
4. 统一操作不改变叶字段内容，并保留现有手动展开与 Schema 重置行为。
5. 请求 Body 树的统一按钮不影响响应面板或其他 Schema 树实例。

同时运行相关 OpenAPI 组件测试、类型检查和 lint。基线测试中与本改动无关的现有失败需要单独记录，不能归因于本次变更。
