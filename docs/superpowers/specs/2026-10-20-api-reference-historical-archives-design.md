# API Reference 历史版本归档外链接入

## 需求与范围

中文版 API Reference 的最新版本继续使用仓库中的内容；历史版本统一使用旧站归档外链，不提供同一数字版本的本站与归档双入口。

用户于 2026-10-20 明确：本轮不处理 RTC React SDK wrapper 与其底层 Web SDK 两个版本系列。保持 `rtc/react-sdk/**` 的内容和元数据不变。

数据依据为主工作区中的 `docs/migration/api-reference-historical-archive-inventory-20261020.md`，旧站固定基线为 `e91218031d7dd02ff84a66fc1b5f422a1cd28a64`。实施分支基线为 `58245f6cfd7566a8eca1c1653f0885f1b39e03bf`。

排除 React 的 9 个历史选项后，本轮接入 9 个产品配置组下的 43 个平台，共 219 个历史选项、214 个去重 URL。不同版本标签即使对应相同 URL 也保留。

## 接入方式

采用现有平台 `meta.json` 的 `navScope.versions` 与 `href` 字段配置外链。数据继续由内容元数据维护，不新增运行时清单解析或历史正文迁移。

考虑过另设全局历史版本注册表、增加独立“历史版本”页面；两者都会引入第二处配置或额外访问步骤，本轮不采用。

- 每个平台保留一个指向本站的 `current` 项，默认选中该项。
- 沿用已有 current 的站内路径与内容；缺少版本菜单的平台补充 current 配置，版本标签依据清单核对，不凭标签更改正文。
- 历史项配置清单中的 SDK 显示版本与完整 archive URL，不能用新站路径拼接。
- RTC Android v4.6.0 的版本项改为清单中的归档链接，不保留对应的本站菜单项。
- 本地录制的两个 Legacy 项不是有明确归档映射的数字版本。将它们移出版本菜单，不把 v4.4.150 归档冒充为 Legacy；本轮不删除 Legacy 文件、不新增重定向、不调整已有正文侧栏。
- 不删除已有历史正文目录，不改变其直接访问 URL。本轮改变的是版本菜单入口，既有 URL 的停用或重定向不在本轮范围。
- 修正新基线已有的 macOS/C++ v4.6.2 外链：按清单对应 `0.0.519`，不沿用现有 `0.0.492`。
- 无历史配置、被注释的平台不补造历史选项。英文站不改动。

## 导航行为

沿用现有版本下拉组件；外域链接使用原生 `<a>`，新标签页打开，并带安全的 `rel` 属性。本站 current 保持现有站内导航。

桌面与移动端使用同一套链接判断与行为；历史外链不成为当前站内版本，也不改变新站选中状态。长列表必须可滚动，所有选项可通过键盘访问。

不新增 React 专属版本选择逻辑。公共组件改动不得影响 React 现有页面。

## 数据特殊情况

- RTM v2.1.3 使用旧 `/rtm2/web/` 路径。
- Fastboard 使用旧 `/fastboard/` 路径，不因新站白板层级而改写。
- RTC HarmonyOS 使用清单中的小写路径。
- ConvoAI `0.0454`、小程序 `v0.0.166`、RTC RN 的 v6.x 标签按清单保留，不猜测修复。
- 归档 URL 是源码推导的候选地址，尚不能宣称已验证可达或版本一致。上线前核验异常编号、入口存在性及内容版本；网络失败需区分超时、权限与页面不存在，不自动改成另一版本链接。

## 验证与验收

1. 对照清单逐项校验 219 个版本标签及其 URL，确认 214 个去重 URL 和 43 个平台；排除 React 的 9 项。
2. 在本轮平台中，只有 current 使用本站链接；所有数字历史版本使用归档链接，无重复版本项。
3. 验证已有 current 路径与内容未被替换；React 元数据及内容无差异。
4. 补充解析器和版本下拉测试，覆盖外域链接、新标签页、移动端、选中状态、没有独立版本目录的平台及已有本站历史目录的情况。
5. 核对版本菜单与现有导航生成脚本的关系，避免后续生成覆盖新增项。
6. 运行完整 `bun run test` 与 `bun run types:check`，并对代表性平台做浏览器验证；线上链接核验结果与本地导航测试分开记录。

## 工作顺序

确认本设计后编写实施计划；先建立清单完整性与导航行为测试，再补齐元数据及外链渲染，最后执行完整验证并报告线上归档核验中的未决项。

本设计尚不代表归档链接已接入。
