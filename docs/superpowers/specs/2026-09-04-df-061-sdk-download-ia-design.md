# DF-061 中文 SDK 下载页信息架构设计

## 背景

DF-061 针对中文 SDK 下载页 `/zh-CN/reference/sdks` 的信息层级和扫描效率问题。当前页面将 15 个产品连续放在两列卡片网格中：桌面端页面高度约 3959px，移动端约 6961px；语音、视频和实时消息等产品的平台选项超出卡片可视宽度；不同产品的版本、下载、包管理器、包名、MD5 和发布日期组合也不一致。

本次改动只针对中文 SDK 下载页，不改变 SDK 数据、下载地址、版本事实或 API 参考页面本身。

## 目标

- 使用户可以按与 `/zh-CN/api-reference/api` 一致的能力分类浏览 SDK。
- 降低 15 个产品连续平铺造成的滚动和扫描负担。
- 统一产品条目的信息层级和操作入口。
- 让桌面端和移动端的平台选择交互一致，并消除平台横向滚动。
- 保留页面现有链接参数、锚点、安装命令复制和 SDK 下载能力。

## 非目标

- 不修改 SDK 下载数据中的版本、包名、MD5、发布日期或链接。
- 不修改 `/zh-CN/api-reference/api` 的 sidebar 分组或 API 参考页面。
- 不改变英文 SDK 页面。
- 不新增搜索、排序或与本反馈无关的下载能力。
- 不通过懒加载移除折叠内容；所有产品内容仍需在服务端生成的 DOM 中可访问。

## 能力分组

页面复用 `src/lib/api-reference-navigation.ts` 中的 `API_REFERENCE_CAPABILITY_GROUPS`，使用该常量的标题、顺序和产品 ID。SDK 页面只渲染至少包含一个 SDK 产品的能力组，空能力组隐藏。

SDK 产品与 API 参考能力组的映射如下：

| 能力组 | SDK 产品 |
| --- | --- |
| 对话式 AI 引擎 | 对话式 AI 引擎 SDK |
| 实时互动基础能力 | 语音 SDK、视频 SDK、实时消息 SDK、即时通讯 SDK |
| 实时媒体处理 | 无，隐藏 |
| 会议协作 | 智能云会议引擎 SDK |
| 监控与分析 | 无，隐藏 |
| 扩展能力与生态 | 互动白板 SDK、Fastboard SDK、媒体播放器组件、RTC 服务端 SDK、本地服务端录制 SDK |
| 社交娱乐 | 无，隐藏 |
| 教育 | 灵动课堂 SDK、云课堂 SDK、灵动监考 SDK |
| 智能硬件 | 物联网 aPaaS SDK |
| 平台管理 | 无，隐藏 |

其中，物联网 aPaaS、媒体播放器、Fastboard、云课堂和灵动监考在 API 参考能力组中没有一一对应的独立产品 ID，按已确认的最近能力归类处理。

## 页面结构

页面结构从“产品卡片网格”调整为：

1. 页面标题、更新时间和简介。
2. 产品筛选器、平台筛选器和匹配数量。
3. 按 API 参考能力组顺序排列的能力组标题。
4. 每个能力组中的产品 Accordion。
5. 产品详情内容，包括平台、版本、安装命令、下载、包管理器和版本详情。

产品筛选和平台筛选继续支持现有 `product`、`platform` URL 参数；筛选后只显示匹配产品所在的能力组，能力组为空时隐藏。

## Accordion 行为

- 产品条目使用原生 `details` 和 `summary` 语义。
- 每个能力组中的第一个产品默认展开，其余产品默认折叠。
- 多个产品可以同时展开。
- 折叠只改变视觉展示，不移除内容；页面内搜索、Copy Page、Markdown 输出和无 JavaScript 场景仍能访问内容。
- 产品标题行展示产品名称、简短说明、平台数量或语言提示、当前最新版本等摘要信息。
- 产品锚点继续使用现有 `sdk-download-product-{productId}` 规则。

## 平台和版本选择

所有产品、所有屏幕尺寸统一使用原生平台下拉选择器，不再使用平台 Tab 或平台横向滚动。

- 平台下拉选项使用 SDK 数据中的真实平台名称。
- 当 URL 带有有效 `platform` 参数时，产品默认选择该平台；如果该产品不支持该平台，则回退到该产品的第一个平台。
- 切换平台时，版本选择回到当前平台的第一个可用版本。
- 多版本变体使用版本选择器，标签统一表达“版本 / 语言 / 架构”信息，例如完整版、轻量版、Java x86-64 或 C++ arm64。
- 页面继续只暴露最新版本及当前版本变体，不恢复历史版本列表。

## 产品详情和操作层级

每个展开的产品使用一致的字段顺序：

1. 平台。
2. 安装工具和当前版本。
3. 安装命令及复制按钮（适用时）。
4. 主操作“下载 SDK”（适用时）。
5. 次操作“包管理器”（适用时）。
6. “版本详情”区域中的发布日期、包名和 MD5（存在时）。

安装命令保留横向查看能力和可访问名称，但平台选择本身不再横向滚动。没有可推导安装命令的产品继续直接显示下载入口。

## 数据和组件边界

- `API_REFERENCE_CAPABILITY_GROUPS` 是能力组顺序和标题的唯一来源。
- `sdk-downloads-data.ts` 与 `sdk-downloads-data.zh-cn.ts` 继续作为 SDK 下载事实数据来源。
- SDK 产品 ID 到能力组 ID 的映射集中在 SDK 下载组件附近，避免散落在 JSX 条件中。
- 产品分组、筛选和可见能力组计算保持为可测试的纯逻辑。
- 现有下载链接、包管理器链接、安装命令推导和版本元数据组件尽量复用。

## 无障碍与响应式要求

- 使用原生 `select`、`details` 和 `summary`，保持键盘操作和无 JavaScript 回退。
- 下拉选择器有可关联的可见或屏幕阅读器标签。
- 产品折叠状态使用原生语义表达，不依赖 hover。
- 桌面端和移动端使用相同的产品顺序、字段顺序和交互模型。
- 在 1440px 桌面视口和 390px 移动视口下不得出现页面级横向溢出。
- 安装命令可以在自身容器内横向查看，并保留当前的溢出提示和键盘可访问性。
- 下载、包管理器和复制命令等主要操作保持清晰可发现且具备足够触控区域。

## 错误和边界行为

- 无有效筛选结果时，显示现有的空结果提示和清除筛选操作。
- 无版本数据的产品只显示产品说明，不渲染空的版本操作区。
- 无下载地址或包管理器地址时，不渲染对应操作，不创建伪链接。
- URL 中的未知产品或平台参数继续按现有逻辑忽略并回退到全部结果或默认平台。
- 能力组映射中没有 SDK 产品的组不渲染，不显示空标题。

## 测试和验证

新增或调整组件测试，至少覆盖：

- 能力组顺序与标题来自 API 参考能力组结构。
- SDK 产品映射到正确能力组。
- 空能力组隐藏。
- 每个能力组首个产品默认展开，其余产品折叠。
- 产品和平台筛选只影响可见产品及能力组。
- 所有产品使用平台下拉选择器，不渲染平台 Tab。
- 平台切换和版本/语言/架构选择保持现有数据与链接行为。
- 安装命令复制、下载和包管理器链接继续可用。
- 版本详情保留发布日期、包名和 MD5（存在时）。

验证命令和浏览器检查：

- 运行 SDK 组件相关 Vitest 测试。
- 运行变更文件的 Biome 检查。
- 在 1440px × 900px 和 390px × 844px 下预览 `/zh-CN/reference/sdks`。
- 检查能力组、折叠状态、平台下拉、下载入口、版本详情和筛选 URL。
- 检查页面级横向溢出、安装命令容器的局部滚动、键盘操作和控制台错误。
