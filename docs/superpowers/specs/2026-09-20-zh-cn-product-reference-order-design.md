# 中文产品文档参考区排序设计

## 背景

不同产品的 `reference/meta.json` 内容不完全相同，但目前下载资源、API、错误码、迁移和概念说明的相对位置缺少一致性。用户希望统一这些内容在产品文档“参考”区中的排序，同时保留每个产品已有的页面名称、链接和特殊内容。

## 目标

- 为中文产品文档的参考区建立一致的排序优先级。
- 将下载资源放在 API 页面之前。
- 只调整参考区内条目的顺序，不调整条目结构。
- 让配额、限制、错误码、迁移指南和概念/核心说明集中出现在参考区前部。
- 将未归入上述类别的产品特有内容放在这些类别之后。
- 保留每个页面现有的标题、链接、分组结构和产品特有内容。

## 非目标

- 不统一或重命名页面标题，例如不强制把页面命名为“下载资源”或“API 参考”。
- 不新增、删除、拆分或重组现有条目。
- 不改变参考区之外的导航结构。
- 不处理无法明确归入本次五类的其他页面内容，只调整它们在参考区中的最终位置。
- 不修改页面正文、页面文件位置或页面 URL。

## 排序规则

对每个产品的 `reference/meta.json`，按以下五个类别重新排列页面条目：

1. 下载资源
2. API 页面
3. 配额、限制与错误码
4. 迁移指南
5. 概念 / 核心说明

完成上述五类后，放置所有未归类的条目。

分类只决定位置，不决定显示名称或条目结构。条目仍使用产品现有的字符串、链接对象或 `group` 对象。

### API 页面

所有客户端 API、服务端 API 以及其他明确属于 API 的页面都归入 API 位置。客户端 API 排在服务端 API 前面；同类 API 条目之间保持原有相对顺序。API 条目的现有结构不做调整。

### 类别内部顺序

同一类别内的多个页面保持原有相对顺序。例如多个下载页面、多个错误码页面或多个迁移页面，不额外按名称排序。

### 分组条目

如果现有条目是 `group`，只调整这个 `group` 条目在 `pages` 中的位置，不拆分或改写其内部页面。分组的类别由其语义决定，例如：

- “错误码”组归入第三类。
- “迁移升级”组归入第四类。
- “概念事件”组归入第五类。
- “平台支持”组未归类，放到五类内容之后。

如果某个分组同时包含多个类别的页面，保留整体结构，并根据该组的主要语义放置。

## 示例

原有结构：

```json
{
  "pages": [
    "[服务端 API](/api/server)",
    "downloads",
    "platform-support",
    "response-code",
    "migration-guide",
    "concepts"
  ]
}
```

调整后：

```json
{
  "pages": [
    "downloads",
    "[服务端 API](/api/server)",
    "response-code",
    "migration-guide",
    "concepts",
    "platform-support"
  ]
}
```

页面实际名称不因排序规则改变。

## 实现策略

- 逐个审阅中文产品参考区的 `meta.json`，只调整可以明确识别的条目顺序。
- 对已有 `group`、链接页面和隐藏页面保持原有 JSON 结构。
- 不修改页面路径、站内链接或重定向规则。
- 增加或扩展 IA 测试，验证代表性产品的排序和现有条目结构未被改变。

## 验收标准

- 每个被纳入本次调整的产品参考区都符合五类优先、其他内容置后的顺序。
- 现有 API、链接和分组条目结构保持不变。
- 客户端 API 与服务端 API 的现有相对顺序不被意外改变。
- 分组条目没有被拆分，组内页面顺序保持不变。
- 页面标题、路径、链接和产品特有内容保持不变。
- 相关 IA 测试通过。
