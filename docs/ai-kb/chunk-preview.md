# 本地 KB 质量检查与切块预览

用于真实 corpus 的离线检查，不创建百炼资源、不生成向量、不调用模型。输入仍是原有完整文档 corpus；预览是独立派生产物，不替换同步输入，也不改变当前问答检索方式。

## 使用

在本开发工作树执行：

```sh
bun run kb:preview:cn \
  --corpus dist/ai-kb/cn-real-demo-v1/corpus.json \
  --out dist/ai-kb/cn-real-demo-v1/preview.json
```

可选 `--target-chars 3000`，允许 32–20000。单位为 JavaScript UTF-16 字符长度，不是模型 token；它是软目标。语料摘要不一致、缺参数、输出覆盖输入时拒绝执行；解析或空正文错误会保存诊断报告并非零退出。warning 不阻断预览。`ready` 只表示没有检测到本地结构错误，不能作为上传、生产或云端检索验收。

## 规则与数据

策略名 `mdx-block-v1`。以 MDX + GFM AST 的顶层块为边界，先按标题分段，再按字符目标合并或分组。代码围栏、列表、表格、整个 JSX 组件均不可从中间切断。超长块保留全部文本并产生 `oversized-block` 警告，不截断、不静默丢弃。组件内的标题不单独拆分。解析失败时保留整篇作为诊断块，报告 `parse-error`，禁止认为预览通过。

每个 chunk 包含：

| 字段 | 含义 |
| --- | --- |
| `id` | 策略、sourceId、文档 hash、目标长度、起止位置的 SHA-256 |
| `sourceId` / `documentHash` | 来源文档与内容/Metadata 版本 |
| `start` / `end` | 原文 UTF-16 起止偏移，end 不包含在片段内 |
| `content` | 原文连续子串，不重写、不重复添加标题 |
| `citationUrl` | 已验证章节链接，或来源文档页 |
| `headingPath` | 匹配章节的标题路径；无法匹配时为文档标题 |
| `metadata` | 完整继承原文档 Metadata，平台变体保持分离 |

标题中明确的 `[#anchor]` 必须与 corpus 的 section URL 完全匹配，才能用作章节引用；不从标题猜 slug。未知或缺少锚点时报告 `unmapped-heading` 并退回文档页，不能沿用上一节锚点。可信度来自上游发布产物校验；本命令不会重新请求网站验证链接。

按来源顺序拼接 chunks 的正文应等于原文；Metadata 不因切块改变。只改构建 revision 不改 chunk ID；文档正文或 Metadata 改变会使该文档的 chunk ID 全部变化，其他文档保持稳定。同步仍以文档为粒度，尚未实现 chunk 级远端更新。

## 后续边界

- 结构检查不等于语义质量评测；仍需人工核对示例、平台内容和回答是否适用。
- Markdown 内相对链接、跨块 link reference/脚注依赖尚未解析为独立展示包，当前片段只供预览，不应直接作为独立文档上传或展示。
- 如需缩小超长结构块，应单独设计语义拆分方式，不能破坏代码、列表或组件；暂时保留原文是有意的保守选择。
- 百炼是否支持采用这些切块、如何写 Metadata 和过滤、token 限制与实际召回，待真实接口验证。既有文档级上传适配器继续保留，不能把预览 JSON 直接传给它。
- 本次 sample 不覆盖全站；之前记录的 20 个全量来源覆盖缺口仍待处理。
